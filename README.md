# Рабочее место УОР · 0.6.0

Локальное рабочее место для получения исходников, общих справочников, целей, управленческих экранов и недельной сводки. Принятая общая версия хранится в Git; личные файлы, черновики и сеансы остаются на компьютере пользователя. Собственный центральный сервер не нужен.

Основной путь: **получить файл → проверить строки и происхождение → сопоставить с базой знаний и целью → проверить расчёт → сохранить отчёт → договориться о следующих действиях**. Получить исходник можно до настройки каталога, методики и обогащения.

## Первый запуск

Обычному пользователю предназначен подготовленный дистрибутив **Linux x64** и ярлык **«РМ УОР»**. ИТ один раз проверяет системную совместимость, устанавливает СберБраузер **152.0.7977.120**, указывает его путь и создаёт ярлык. В комплект входят закреплённые Node.js **22.16.0**, npm **10.9.2** и зависимости из lock-файла. Ежедневный запуск не выполняет установку зависимостей.

1. Распакуйте подготовленный комплект в согласованную физическую папку.
2. Откройте ярлык «РМ УОР» или `START_RM_UOR.sh`. Оставьте окно запуска открытым.
3. В разделе **Настройки → Рабочее место** проверьте состояние среды.
4. Откройте **Данные** и получите первый файл с компьютера, введите таблицу вручную либо настройте свой сценарий ОКО/Confluence.
5. Подключите выбранный общий пакет в **Обновления и копии**, когда он нужен для вашей работы.

Кодовый ZIP — отдельный комплект для разработчика/ИТ; он требует подготовки зависимостей. Для существующей установки сначала сделайте штатную личную копию. Не удаляйте `.runtime` и не копируйте чужую рабочую базу вместо общего пакета.

## Разделы продукта

| Раздел | Что можно сделать |
| --- | --- |
| Обзор | Увидеть результат и проблемы в выбранной области, открыть собственные дашборды |
| Данные | Сохранить исходник, повторить получение, скачать неизменённый файл, найти строки, проверить происхождение и подготовить обработку |
| База знаний | Посмотреть и подготовить общие команды, подразделения, связи, методики и выбранные реальные материалы |
| Цели | Создать и изменить определение цели в своём черновике, проверить порог и основания, подготовить согласованную публикацию |
| Работы и решения | Зафиксировать действия, этапы, решения и их доказательства отдельно от расчётного достижения цели |
| Отчёты | Настроить разделы, сохранить неизменяемую версию, выгрузить XLSX/PPTX/PDF; подготовить и проверить недельную сводку |
| Панель УОР | Проверить свой пакет общих изменений; внешнее согласование и принятие отделены от локальной подготовки |
| Настройки | Выбрать тему/плотность, проверить рабочее место и перейти к настройке нужного сценария |
| Обновления и копии | Проверить кодовый канал, общие данные и пакет настройки; открыть личные копии и восстановление |

Сворачиваемое меню, избранное, недавние разделы и стартовая страница сохраняются в личных предпочтениях. Внешний вид доступен из верхней панели. Смена владельца очищает приватные представления; неизвестный результат сохранения сверяется по прежней операции.

## Разделение данных и полномочий

Читатель получает собственные исходники и просматривает доступные общие сведения. Редактор готовит изменения в своём черновике. Проверенный внешний Git/Bitbucket и принятый реестр определяют право общей публикации. Локальный переключатель «Читатель / Редактор» сохраняет личность, но не выдаёт банковский допуск и не разрешает внешнюю AI-отправку или применение main.

Сырой файл, преобразованный набор, принятый факт, рассчитанный результат и подтверждение УОР — разные сущности. Нет данных, нет событий и исключение показателя не становятся нулём или успехом. Недельный текст и завершение действия не подтверждают цель автоматически.

Выпуск содержит разрешённые владельцем XLSX/PPTX от30октября2026 и извлечённые справочники:58команд,5метрик и290ожидаемых позиций. Их происхождение и ограничения видны в интерфейсе и manifest. Материалы за25октября содержат только заявления источника; отсутствующие исходные факты не восстановлены по догадке.
