# Рабочее место УОР ДИТ Operations

УОР — управление обеспечения развития.

Локальное веб-приложение для директора ДИТ, ИТ-лидеров кластеров и кураторов УОР: цели технологической повестки, факты, прогресс, подтверждение выполнения, комментарии, знания и управленческая отчётность.

**Текущее состояние:** первый этап локального приложения реализован, обзор упрощён, добавлены редактируемые направления. Доступны обзор по ИТ-лидерам, подробная матрица, карточки с фактами и источниками, редактирование куратором, комментарии, ручные факты, проверка выполнения, журнал операций и обмен общими данными через Git. Реальный вход в корпоративные дашборды пока заменён явно обозначенной заглушкой. Свежая проверка: 130 тестов в 20 файлах и успешная сборка. Автоматическая визуальная проверка текущего прохода недоступна; подробности — в журнале доказательств.

## Запуск

Нужны Node.js 22.20+ ветки 22.x либо Node.js 24+, npm, Git и браузер. Текущий локальный запуск проверяется на Windows с Node.js 24.19; macOS и СберОС требуют отдельной проверки. Python для этого этапа не нужен.

Из разрешённой папки проекта:

```text
npm ci
npm run dev
```

Откроется [локальное рабочее место](http://127.0.0.1:5173). Консоль остаётся открытой; остановка — Ctrl+C. Перед рабочим использованием настройте `config/site.local.json` и кураторов по [гайду запуска](docs/guides/setup-and-run.md).

Чистая копия показывает вымышленные демонстрационные данные. Рабочую карту можно импортировать через каталог целей в режиме куратора либо командой:

```text
npm run import:map -- "путь/к/карте.html"
```

Команда сохраняет карту локально; для применения нужен перезапуск. Данные из дашбордов эта команда не получает.

## Основные правила

Каждый компьютер работает самостоятельно. Общая информация приходит из Git, личные обращения к источникам выполняются с правами пользователя. Кураторы могут публиковать проверенные снимки для тех, у кого нет доступа к исходному источнику; происхождение, автор, период и актуальность всегда видны.

Кураторские изменения накапливаются в `release/current`. Руководитель УОР выпускает их слиянием в `main`. Обычные пользователи читают `main`.

Сборка под отдельную ОС и иконка приложения сейчас не требуются. После подготовки окружения по инструкции пользователь запускает приложение командой `npm run dev` из разрешённой директории.

Приложение показывает неизвестное значение, если подходящих фактов нет. Положительный расчёт и подтверждение УОР различаются. Устаревшие данные помечаются; новое подтверждение текущего выполнения по ним отклоняется.

## Граница первого этапа

Главная показывает компактную сводку, один основной график сравнения ИТ-лидеров и три первых действия. Длинная матрица, направления, каталог, источники и история открываются отдельно. Фамилии и полные русские названия доступны без расшифровки технических кодов; подробности раскрываются по запросу.

Направления — редактируемый справочник: архитектура, производственный процесс, управление технологическим долгом, данные, МЕТЛА, тарифные модели ИТ и SberInfra. Исходные категории карты сохраняются. Предварительное отнесение цели к направлению требует проверки куратора; цели без привязки остаются явно видимыми. Общие показатели считают уникальные назначения и не суммируют повторные попадания в направления.

Через UI куратор редактирует существующие цели и назначения, источники и объекты базы знаний, вводит факты и комментарии. В базе знаний хранится отдельная связь продукта с его лидером. Полный состав новых целей задаётся импортом карты; расширенные мастера настройки будут дополняться по следующим этапам.

Обновление получает общие данные перед выбранными источниками и расчётом. Локальный источник проверяет наличие уже загруженных данных; он не перечитывает исходный Excel автоматически. Источник с заглушкой возвращает понятный результат без новых фактов.

Генерация презентаций и еженедельных отчётов, запись браузерных сценариев, реальный Qlik/Confluence и сертификатный вход относятся к следующим этапам.

## Проверка разработки

```text
npm test
npm run build
```

`build` проверяет TypeScript и собирает интерфейс. Это не отдельный установщик и не проверка корпоративных интеграций. Состав выполненных проверок фиксируется в [документе проверки](docs/first-stage-validation.md).

## Данные в тестовом репозитории

Тестовый GitHub-репозиторий публичный. Здесь размещаются код, документация и обезличенные демонстрационные наборы. Рабочая карта целей и исходные корпоративные файлы импортируются из разрешённой локальной папки. Их публикация в корпоративный репозиторий настраивается при переносе. Настройки доступа, коды кураторов в открытом виде и браузерные профили не являются содержимым каталога общих данных.
