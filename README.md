# Рабочее место УОР

Версия **0.5.0**, кандидат для локальной проверки. Рабочий путь: **запись отчёта → выгрузка → справочник → дообогащение → скачивание результата**.

Ветка кандидата редизайна — `codex/uor-redesign-reference`, база `ac299a5` из `codex/uor-workbench-rebuild`. Штатный запуск открывает пять рабочих разделов: «Обзор», «Цели», «Работы и решения», «Данные», «Панель УОР». Проверки и условия внедрения опубликованы в [описании кандидата](docs/releases/redesign-candidate.md), [журнале завершения](docs/validation/redesign-completion.md) и [карте сохранённых функций](docs/validation/redesign-reuse-map.md). Реальная банковская приёмка ещё требует доступа к целевой среде.

## Начать работу

Нужны Node.js **22.16.0**, npm **10.9.2**, Git и установленный браузер. Для записи используйте установленный СберБраузер; Google Chrome и Microsoft Edge подходят для локального аналога. Python приложение не использует.

Получите код в короткую разрешённую папку, например `C:/RM_UOR`, установите зависимости:

```text
npm ci
```

Для нового места создайте `config/site.local.json`, подставив существующую разрешённую папку:

```json
{
  "allowedWorkspaceRoots": ["C:/RM_UOR"],
  "port": 4174,
  "clientPort": 5173,
  "autoOpen": true,
  "roleMode": "local-preview",
  "repositoryUrl": "",
  "publishedBranch": "main"
}
```

Затем выполните:

```text
npm run dev
```

Оставьте окно запуска открытым. Локальный адрес обычно `http://127.0.0.1:5173`; остановка — Ctrl+C. Новое место пустое: личный инструмент ОКО доступен в «Данные → Личные выгрузки ОКО» без организационного каталога.

По указанию владельца временно используется переключатель **Читатель / Редактор**. Он сохраняет одну личность и разрешает локальную подготовку. Реестр допуска и внешние права на Git/ОКО настраиваются отдельно. Временный режим не разрешает отправку общего пакета или применение внешнего main.

Читатель может создавать и повторять собственные личные сценарии ОКО и загружать собственный справочник. Общие источники и пакеты сохраняют отдельные права. При несохранённой форме смена роли или переход требуют решения пользователя; отказ сохраняет ввод.

Существующую установку сначала сохраните штатной копией. Не удаляйте `.runtime` и не запускайте подготовку пустого места поверх рабочих данных. Старый неопознанный формат останавливает запуск с диагностикой; приложение не объявляет его автоматически перенесённым.

Справочник добавляет человеческие названия продуктов, кластеров, ДИТ и руководителей по точным ключам. Исправление выполняется повторной загрузкой справочника или сменой сопоставления столбцов. Исходный файл сохраняется побайтно; обогащённый CSV — отдельный результат. Личная проверка не создаёт официальные факты или подтверждение цели.

Общий пакет проходит собственный черновик, проверку и внешний PR. Слияние выполняется в Bitbucket вне приложения. Проверенный main применяется отдельно; согласованные основания сохраняются. Нативный банковский провайдер Bitbucket в стандартной композиции пока недоступен, внешний цикл проверен на синтетических провайдерах.

## Данные и проверки

Приватные данные находятся в `.runtime`. Активная версия рабочего набора выбирается проверенным указателем; копирование отдельных файлов SQLite вместо штатного архива не является переносом. Копия не переносит cookies, браузерные профили, сертификаты, роли или доступы.

```text
npm test -- --fileParallelism --maxWorkers=2
npm run test:workbench:e2e
npm run build
```

Фактические результаты и известные предупреждения приведены в [журнале проверки](docs/VALIDATION.md). Нынешние Linux/Chrome проверки и исторические испытания Chrome/Edge на Windows не подтверждают банковские SSO, ГОСТ, smartcard, сертификаты, прокси, СберБраузер, другие ОС и работу со всеми реальными отчётами. Массовое внедрение и слияние разработки в main требуют отдельного решения владельца.
