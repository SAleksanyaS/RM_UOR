# Рабочее место УОР ДИТ Operations

**Цели ДИТ, факты, исполнение и управленческие решения — в одном рабочем месте.**

УОР — управление обеспечения развития. Версия **0.4.1** · 25 октября 2026 года.

Директор видит общую картину и результаты ИТ-лидеров. Куратор настраивает цели, принимает данные, проверяет результат и готовит общий выпуск. Приложение запускается на компьютере пользователя; общие определения и выбранные проверенные данные распространяются через Git.

> **Начните с [простого руководства пользователя](docs/USER_GUIDE.md).** Там — установка с нуля, вход, маршруты директора и куратора, полный цикл работы и помощь при ошибках.

## Запуск

Целевая связка — **Node.js 22.16.0 и npm 10.9.2**. Также нужны Git и браузер. Установленный **Python 3.13.5 можно оставить**: приложение его не использует. Получите проект в разрешённую папку и выполните из его корня:

```text
npm ci
npm run setup:workspace -- --mode empty
npm run dev
```

Для существующей установки: остановите приложение, выполните `git pull`, `npm ci` и `npm run dev`. База, настройки и пароли сохраняются; повторно выполнять `setup:workspace` не требуется. [Подробности и проверка версий](docs/guides/runtime-versions.md).

Браузер откроет локальный адрес, обычно `http://127.0.0.1:5173`. Оставьте окно запуска открытым; остановка — **Ctrl+C**. Локальная служба принимает соединения только с этого компьютера.

`empty` создаёт новую установку без прежних целей, фактов и журнала. Для знакомства на новой установке можно **вместо него** выбрать `--mode demo` с синтетическими примерами. Подготовка не затирает существующее рабочее место. Повторный обычный запуск сохраняет базу и черновики.

Для работы внутри организации добавьте при подготовке `--repository "<URL внутреннего репозитория>" --publication internal`. Затем настройте локальные учётные записи по [пошаговой инструкции](docs/USER_GUIDE.md).

## Кто что делает

| Кто | Маршрут |
| --- | --- |
| **Директор / ИТ-лидер** | «Обзор ДИТ» → лидер или цель → факты, сроки и отклонения → «Повестка директора» → «Еженедельный отчёт» |
| **Куратор УОР** | «Настройка целей» → данные → предпросмотр → проверка снимка и подтверждение результата → «Публикация» |
| **Руководитель УОР** | Проверяет готовящийся выпуск `release/current` и включает его в `main` через Git UI |
| **Сопровождающий / администратор** | Готовит среду, учётные записи, источники, внутренний Git, резервирование и перенос |

В приложении две роли: **читатель** и **куратор**. Просмотр доступен без кураторского пароля. Куратор входит через профиль справа сверху, выбирая свою учётную запись. Права на Git и корпоративные источники оформляются отдельно; отдельной роли администратора в интерфейсе нет.

## Основной рабочий цикл

**Цель → данные → предпросмотр → проверка → публикация → отчёт.**

| Шаг | Что получается |
| --- | --- |
| Настроить цель | Паспорт, методика, показатели, официальный и внутренний пороги, участники и источник |
| Загрузить или получить данные | Личный снимок с периодом, происхождением и проверкой полноты |
| Посмотреть расчёт и принять факты | Проверенные пользователем значения становятся основанием расчёта; пример из мастера фактов не создаёт |
| Проверить снимок и подтвердить достижение | Две отдельные отметки: корректность данных и подтверждение положительного результата УОР |
| Подготовить публикацию | Выбранные черновики и артефакты отправляются в `release/current`; руководитель выпускает их в `main` |
| Подготовить отчёт | Недельная управленческая сводка или отчётный снимок выбранных целей, лидеров и периода |

**Нет данных — результат неизвестен.** Завершённый план не заменяет измерение. Положительный расчёт ждёт подтверждения УОР; изменение фактов, правил или состава участников требует новой проверки.

## Возможности

- **Обзор и аналитика:** общий результат ДИТ, ИТ-лидеры, направления, матрица, карточки целей, история и полнота данных. Разнородные показатели не усредняются.
- **Цели и факты:** мастер настройки методики и состава участников, ручные факты, Excel/CSV и специальный импорт модели зрелости; явное сопоставление, предпросмотр и принятие данных.
- **Получение данных:** HTTP, Confluence, Qlik Engine и записанные действия Chromium-браузера. Доступы и браузерный профиль остаются локальными; ошибки источника не подменяются успешной загрузкой.
- **Исполнение:** планы, вехи, владельцы, сроки, зависимости, проверки удержания и очередь куратора. Измеренные результаты, заявленные работы и прогнозы показаны отдельно.
- **Отчётность:** текстовый еженедельный отчёт для директора, неизменяемые отчётные снимки, сравнение периодов, HTML и PPTX, загружаемые шаблоны с поддержанными привязками и профиль модели зрелости.
- **Совместная работа и обслуживание:** выбор состава выпуска, разрешение конфликтов по полям, библиотека доказательств, перенос рабочего набора с файлами, восстановление, хранение и обновление программы.

## Где находятся данные

| Общие данные | Личные данные компьютера |
| --- | --- |
| Только намеренно выбранные определения, проверенные снимки, подтверждения и разрешённые файлы | База и черновики, исходные выгрузки, доступы, браузерные профили, резервные копии и диагностика в `.runtime` |
| Куратор отправляет в `release/current`; руководитель выпускает в `main` | Не попадают в Git автоматически; пароли и профили не входят в обычный переносимый ZIP |
| Коллеги получают через «Обновить данные → Только данные УОР» | Доступ к источникам каждый компьютер использует собственный |

Публичный репозиторий работает в режиме **`demo-only`** и предназначен для кода и синтетических примеров. Рабочие корпоративные данные публикуются только в специально настроенный разрешённый внутренний репозиторий. **Не удаляйте `.runtime` для устранения ошибки:** там могут быть единственные копии фактов и неотправленных правок.
