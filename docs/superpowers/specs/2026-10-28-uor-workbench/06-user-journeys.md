# Черновик пользовательских сценариев рабочего места УОР

Дата: 27 октября 2026 года. Статус: предложение для обсуждения клиентского пути; экраны и порядок действий ещё не утверждены.

Сейчас согласуются основные сценарии и платформенные контракты. Редкие краевые случаи расчётов отложены в backlog уточнений перед реализацией соответствующего метода. Нерешённые вопросы остаются открытыми; исполнитель не заменяет их догадками.

## Подтверждённые условия

Первый этап включает цели, данные, аналитику и панель УОР. Формирование пользовательских отчётов и презентаций относится к следующему этапу; платформенные контракты предусматривают точку подключения этой отчётности.

Для цели выбирается один рабочий способ: настроен отчёт ОКО/Qlik Sense — автоматическое получение отчёта; ОКО для цели не настроен и есть файл — Excel/CSV; нет дашборда и файлов, а цель статусная — ручной ввод статуса. Это альтернативные способы.

Источник данных настраивается на уровне цели. Для ОКО фиксированная ссылка в настройке цели ведёт к её источнику с нужным набором всех продуктовых строк. Отдельные ссылки или источники получения данных для каждого продукта не требуются.

Состояния ручной статусной цели: «Не начата», «В работе», «Выполнена». Ручное состояние сохраняется без подстановки числового балла и учитывается отдельно от состояний работ. При выборе «Выполнена» у такой цели куратор обязательно кратко описывает полученный результат; ссылку или файл добавляет при необходимости. Эти сведения входят в накопленный пакет куратора и не создают отдельного PR.

Каждый сотрудник по возможности получает свежие оперативные факты на свой ноутбук по настроенному способу. Оперативный расчёт использует общую принятую методику; источник и актуальность видны. Git/main распространяет общие настройки, комментарии, согласованные итоги и данные для резервного получения. Согласованный срез и его подтверждение показываются отдельно от текущего оперативного результата.

Исходные данные отчёта или файла, обогащённые данные и визуализация просматриваются раздельно. Продуктовая выгрузка обогащается связями справочников УОР для среза кластера и его продуктов с раздельным указанием лидеров по уровням. Результат прослеживается до исходных строк и источника. Если не сопоставлены связи, необходимые выбранному расчёту или срезу, соответствующие строки видны как неполнота и задача сопоставления, без подстановки нуля.

Основной маршрут: кластер с одним лидером кластера → продукты с одним лидером продукта у каждого → при необходимости команды со своими лидерами. Лидер кластера, лидер продукта и лидер команды — три разных предметных поля. По D-120–D-122 закрытый служебный реестр задаёт `viewer`, `curator`, `chief`; главный УОР использует обычную панель куратора. Политика подробно описана в [15-access-policy.md](15-access-policy.md).

Для необязательной детализации продукт может быть связан с несколькими командами. Отсутствие такой детализации само по себе не делает основные данные кластера и продуктов неполными. Куратор сам настраивает общие сопоставления и включает их в свой накопленный пакет для публикации через Git.

Настройка источника, соответствия колонок и связей справочников отделена от обработки конкретной выгрузки: получения исходных данных, обогащения и построения визуализации. Наличие идентификаторов и наименований продуктов в реальной выгрузке проверяется при технической настройке конкретного источника; формат не предполагается заранее.

Приоритет получения: прямой источник → последний успешный локальный набор → согласованные данные последнего опубликованного пакета Git. При недоступном ОКО/Qlik сохраняются последние успешно полученные локальные данные с исходными датами и предупреждением; Git используется, если локального набора нет. Сбой ОКО не переключает цель на Excel/CSV или ручной ввод. Отклонённая загрузка или импорт не считаются успешным кэшем.

Пакет Git содержит значения, исходное происхождение, период или дату факта и дату актуальности. Для каждого пути получения видны происхождение и даты, проверяются давность и полнота. Дата скачивания или публикации не подменяет дату актуальности. Автоматическое получение не отменяет согласованные исправления и не удаляет подтверждения. Принятая ручная корректировка ошибочного факта — отдельный процесс, а не параллельный источник.

Общие предметные данные доступны всем. Читатель просматривает факты и настраивает представление; право редактировать факты ему не предоставлено. Кураторы равны в обычной панели: проверяют факты, вручную ведут полный список работ и вех с исполнителями, датами и статусами. Закрытый служебный репозиторий читают только УОР, а реестр компьютеров/ролей изменяет только главный УОР вне обычной панели. Куратор назначает одного конкретного ответственного от кластера на несколько команд либо отдельных ответственных команд. Назначение не меняет права редактирования и авторство действий. Соисполнители работ и наследование назначений ещё не согласованы.

Каждый куратор накапливает изменения, комментарии и согласованные итоги в собственном рабочем пакете и отправляет отдельный накопленный PR за цикл публикации. Обновление факта, сохранение работы или отметка риска сами по себе не создают PR. Готовый пакет отправляется по важному событию либо один-два раза в неделю. Владелец рассматривает каждый пакет независимо: принимает в Bitbucket либо возвращает на доработку. До отправки рабочие черновики остаются локальными. Принятый пакет становится общим после обновления из main.

Кураторы ведут свои зоны по договорённости. По умолчанию выбран рабочий фильтр «Моя зона ответственности»; его можно изменить для просмотра других зон. Общие данные всех зон видимы, права кураторов одинаковы; технического запрета редактирования чужой зоны нет. Пересечения правок рассматриваются как редкое исключение.

Неполнота данных показывается явно. Отсутствующий применимый обязательный показатель блокирует подтверждение выполнения цели до получения данных, даже если исключён из предварительного балла. N/A с причиной и периодом — отдельный случай неприменимости; пропуск сам по себе не становится N/A. Политика необязательных показателей и настройки исключения ещё уточняются.

Изменение основного куратора выполняют вручную и включают в рабочий пакет; после его принятия уведомления направляются по текущему назначению. Прежнее авторство и история сохраняются, права кураторов остаются равными.

Куратор вручную отмечает риск до просрочки, причину, прогнозную дату завершения и требуемую помощь. Плановый срок сохраняется отдельно от прогноза.

Состояния работы: «Запланирована», «В работе», «Приостановлена», «Выполнена», «Отменена». При приостановке или отмене куратор обязательно указывает причину. Риск и блокировка отображаются отдельно от состояния работы. Выполненную работу куратор может вернуть в «В работе» с обязательной причиной; прежнее завершение сохраняется в истории, изменение включается в рабочий пакет.

Одна работа хранится одной записью и может быть связана с несколькими целями. Её состояние обновляется один раз и отображается во всех связанных целях; достижение каждой цели определяется собственной методикой. При завершении куратор обязательно кратко описывает полученный результат; при необходимости добавляет ссылку или файл подтверждения.

Куратор задаёт зависимости работ, в том числе между командами: видны блокирующая работа, её ответственный и цели под угрозой. Приложение показывает всю затронутую цепочку работ и целей; после проверки ситуации куратор вручную обновляет прогнозные даты связанных работ, сохраняя плановые сроки отдельно.

Отдельный запрос решения связан с работой. Куратор ведёт четыре поля: что нужно решить, кто должен решить, до какой даты и какое решение принято.

В работающем приложении уведомления о рисках и блокировках адресованы основному куратору и ответственному за работу, о запросах решений — указанному адресату. Остальные могут подписаться на нужные цели; доступ к данным не меняется.

Новое событие показывается один раз. Повторные напоминания об открытых рисках, блокировках и просроченных решениях показываются только по рабочим дням общего календаря УОР, раз в день. Календарь и частоту настраивает куратор. Повторное напоминание отличается от дубля события. После перерыва показывается актуальное напоминание без накопленных повторов.

Время ежедневных напоминаний по умолчанию — 09:00 по Москве; куратор может его изменить. Если в рабочий день приложение запущено позже настроенного времени, при запуске показывается актуальное напоминание без накопленных повторов.

Для общих сроков, границ дня и напоминаний используется часовой пояс Москвы — Europe/Moscow. На разных ноутбуках они интерпретируются одинаково.

Срок, заданный датой, действует до конца указанного дня включительно по Москве; просрочка начинается с 00:00 следующего дня. Выходной не переносит срок. При необходимости куратор включает изменение даты в рабочий пакет.

## Предлагаемые пути

### UJ00 Пользователь запускает рабочее место

1. Локальный Node получает hostname через `os.hostname()` и проверяет принятую версию закрытого служебного реестра.
2. Активная запись `curator`/`chief` открывает обычную панель УОР; остальные получают viewer. Hostname не удостоверяет человека, реальные сетевые права проверяет Bitbucket.
3. В немодальном мини-окне появляется «С возвращением, <имя>»; его можно закрыть, через 5 секунд оно исчезает. Без имени показано «С возвращением».
4. При временной недоступности ранее проверенный собственный профиль допускает локальные черновики по D-098; без профиля доступен просмотр. Явный отзыв допуска показан отдельно и не уничтожает черновики.

**Приёмка и восстановление:** реестр не виден читателю и не попадает в обычный архив; после переноса на новый ноутбук роль проверяется заново. Перед каждым push и его повтором повторно проверяются hostname и активная роль; локальный отказ означает ноль сетевых записей. Подробные состояния — документ 15, D-120–D-122.

### UJ01 Читатель переходит от отклонения к действию

**Цель пользователя:** понять проблему и следующий шаг.

**Начальный контекст:** читатель открыл цель в срезе кластера и его продуктов; общая методика и согласованный срез приняты из Git, факты получены на ноутбуке прямым или резервным путём.

1. Открывает цель, работу или запрос решения из уведомления либо выбирает кластер, продукт и цель самостоятельно.
2. Смотрит визуализацию обогащённых данных с отдельно подписанными лидером кластера и лидером продукта; сопоставляет факт, требование и расчёт по общей методике. Видит источник, прямое получение, локальный кэш или Git, дату, полноту и давность.
3. Отдельно открывает исходные строки отчёта или файла и прослеживает построение среза кластера и продуктов по связям справочников УОР. При необходимости детализирует продукт до команд и видит их лидеров.
4. Отдельно смотрит согласованный срез из Git, его дату и подтверждение; замечает отличие от оперативного результата, если оно есть.
5. Читает комментарий УОР, открывает связанные работы, находит действие, срок, ответственного, риск и требуемую помощь; при наличии открывает запрос решения.
6. По зависимостям находит блокирующую работу, её ответственного и цели под угрозой.

**Видимый результат:** понятны использованные данные, их актуальность, согласованный результат и необходимое действие в срезе кластера и его продуктов. Лидеры кластера и продукта различимы; команды и их лидеры открываются при необходимости.

**Ошибка и восстановление:** при недоступном ОКО/Qlik показываются последние успешные локальные данные с датой и предупреждением; если их нет — согласованные данные последнего опубликованного пакета Git. Файл не подставляется вместо недоступного отчёта. Отклонённая загрузка не заменяет успешный набор. Ошибка Git сохраняет принятую методику и согласованный срез; отсутствие резервных данных видно как неполнота. Доступен повтор соответствующей операции.

**Качественная приёмка:** читатель объясняет, из каких исходных строк и связей справочников получен результат; отличает оперативный расчёт от согласованного среза и понимает следующий шаг. Фильтр не подменяет общую методику. После перерыва получает актуальное напоминание вместо накопленных повторов.

### UJ02 Куратор проверяет факты и накапливает рабочий пакет

**Цель пользователя:** проверить актуальные данные и подготовить согласованный результат за нужную дату или период.

**Начальный контекст:** выбраны цель, область и общая принятая методика; доступны локальные оперативные факты.

1. Использует настройку источника выбранной цели: проверяет автоматический отчёт ОКО/Qlik Sense по её фиксированной ссылке, загружает Excel/CSV для файловой цели или выбирает «Не начата», «В работе» или «Выполнена» для ручной статусной цели. Отчёт и файл просматривает отдельно в исходном виде; сверяет источник, период, состав и актуальность.
2. При настройке файловой цели один раз сопоставляет исходные колонки значения и даты/периода; колонки команды/кластера — если они нужны выбранному срезу и есть в файле. При обработке использует сохранённую настройку и перед сохранением видит распознанные данные, пропуски и ошибки; предпросмотр не применяет значения. Может сохранить корректные строки; непринятые видны отдельным списком с причинами, набор явно помечен неполным. Исправленные ранее непринятые строки дополняют данные того же периода без удаления уже принятых строк.
3. Проверяет обогащение продуктовой выгрузки по общим связям справочников УОР: кластер и его лидер, продукты и лидер продукта у каждого. При выбранной детализации проверяет команды и их лидеров. Несопоставление необходимых расчёту или срезу связей видит как неполноту и задачу; отсутствие необязательной командной детализации не делает основной набор неполным.
4. Просматривает расчёт или ручное состояние, пропуски и применимость. При «Выполнена» у ручной статусной цели обязательно кратко описывает полученный результат; ссылку или файл добавляет при необходимости. Исправление ошибочного факта сопровождает причиной с сохранением исходного значения.
5. Сохраняет выбранные проверенные результаты, комментарии и подготовленный срез в собственном рабочем пакете. Включает согласованные значения с происхождением и датами для резервного получения коллегами. При выполнении требований добавляет основание подтверждения этого среза.
6. По готовности своего пакета проверяет сводку влияния. Перед каждым push, включая повтор, приложение заново получает hostname и проверяет активную роль в закрытом реестре, затем реальные права Bitbucket. При разрешении отправляет отдельный PR за цикл: по важному событию либо один-два раза в неделю; при локальном отказе сетевых записей нет, пакет сохранён.

**Видимый результат:** раздельно видны исходные строки, обогащённые данные и результат расчёта; частичный импорт явно неполон. Пакет накапливается отдельно, прежний согласованный срез сохраняется до принятия нового пакета.

**Ошибка и восстановление:** для отказа источника предусмотрен резервный путь UJ01. Отсутствие данных по применимому обязательному показателю блокирует подтверждение даже при его исключении из предварительного балла; просрочка необходимых данных также объясняет запрет. Повторный импорт не стирает принятую ручную корректировку. Исключение недостающего значения не оформляется молча как N/A. Ошибочные строки не стирают прежние факты. Неизвестные команды автоматически не создаются.

При повторном Excel/CSV с другим значением того же показателя, команды и периода предпросмотр показывает «было / станет». Куратор выбирает исправления и применяет одним действием; прежние значения сохраняются в истории.

**Качественная приёмка:** импорт и обновление факта не создают отдельного PR. Сохранённое сопоставление используется повторно, данные до сохранения не меняются. Куратор понимает происхождение результата и ограничения; высокий предварительный балл не снимает запрет подтверждения при отсутствии данных применимого обязательного показателя. Подтверждение среза не переносится автоматически на новый оперативный расчёт.

### UJ03 Куратор ведёт работы и вехи

**Цель пользователя:** отразить план и фактическое продвижение.

**Начальный контекст:** открыта цель в выбранной области; куратор располагает сведениями о работах.

1. Добавляет работы и вехи, связывает одну работу с несколькими целями без копирования; выбирает одного ответственного от кластера на несколько команд либо отдельных ответственных команд, указывает даты и текущие статусы.
2. Обновляет состояние работы; при приостановке или отмене обязательно указывает причину. Отдельно отмечает риск до просрочки, его причину, прогнозную дату и требуемую помощь. При завершении обязательно кратко описывает полученный результат; ссылку или файл подтверждения добавляет при необходимости.
3. Связывает работы разных команд; по всей затронутой цепочке проверяет блокирующую работу, её ответственного и цели под угрозой. После проверки вручную меняет прогнозные даты связанных работ, сохраняя плановые сроки.
4. При необходимости создаёт связанный с работой запрос: что нужно решить, кто должен решить и до какой даты. Принятое решение записывает, когда оно появится.
5. Сохраняет изменения в своём рабочем пакете для отправки отдельным PR за цикл публикации: по важному событию либо один-два раза в неделю.

**Видимый результат:** плановый срок и прогноз различимы; видны риск и помощь. Изменения накапливаются локально и отделены от принятого общего плана.

**Ошибка и восстановление:** незавершённый ввод сохраняется при сбое; редкое пересечение правок разрешается в предпросмотре по UJ04. При возврате выполненной работы в «В работе» видны причина и прежнее завершение; изменение включается в рабочий пакет.

При отмене блокирующей работы предупреждение показывает сохраняющуюся зависимость. Куратор указывает заменяющую работу либо снимает зависимость с причиной; решение включается в рабочий пакет.

**Качественная приёмка:** сохранение работы или риска не создаёт отдельного PR. На этом рабочем месте одна запись отражается во всех связанных целях. При приостановке или отмене видна причина; риск и блокировка не заменяют состояние. Читатель различает план и достижение каждой цели по её методике; ответственность понятна для затронутых команд.

### UJ04 Куратор дорабатывает предложение по замечаниям

**Цель пользователя:** исправить предложение, сохранив связь с обсуждением.

**Начальный контекст:** рабочий пакет уже отправлен в PR; приложение получило его замечания.

1. Открывает замечание и соответствующее изменение.
2. Дорабатывает содержимое этого пакета, повторяет затронутые проверки и просматривает обновлённое влияние.
3. После свежей проверки hostname и роли перед каждой попыткой push отправляет доработку в существующий PR и переходит к обсуждению по ссылке. Сетевая недоступность не разрешает отправку по offline-кэшу; локальный пакет сохраняется.

**Видимый результат:** видны новая редакция, авторство и оставшиеся замечания.

**Ошибка и восстановление:** при изменении main предпросмотр совмещает непересекающиеся правки. Если одно поле изменено по-разному, куратор видит «было / main / моё» и явно выбирает значение; затем повторяет проверки и обновляет сводку. При неясном результате отправки приложение сначала сверяет состояние, сохраняя черновик и избегая дубликата PR.

**Качественная приёмка:** понятны замечание, исправление и состояние предложения. При открытом приложении периодический опрос приносит уведомления без дублей одного события.

### UJ05 Главный УОР принимает пакет в Bitbucket

**Цель пользователя:** выпустить пакет общих настроек, комментариев и согласованных итогов.

**Начальный контекст:** приложение показывает отдельные PR накопленных пакетов кураторов, авторов, сводки влияния и ссылки; `chief` внутри обычной панели равен другим кураторам. Главное обслуживание закрытого реестра выполняется отдельно; реальное право merge задаётся Bitbucket.

1. Выбирает PR пакета конкретного куратора, переходит в Bitbucket и проверяет актуальные изменения, машинные файлы, обсуждение и результаты проверок.
2. Независимо рассматривает выбранный пакет: возвращает на доработку с замечаниями либо выполняет merge в Bitbucket.
3. Приложение при следующей проверке обнаруживает результат; пользователи принимают общие настройки, комментарии, согласованный срез и данные для резервного получения из main по кнопке.

**Видимый результат:** новая согласованная версия различима с прежней; локальные настройки сохраняются. Факты по возможности поступают напрямую; согласованные данные Git доступны для резервного получения с исходными датами.

**Ошибка и восстановление:** устаревшее предложение перепроверяется; недоступность Bitbucket сохраняет последнее известное состояние без ложного сообщения об успехе.

**Качественная приёмка:** в приложении нет действия merge. Пакетная публикация меняет согласованный срез и общие условия; оперативное обновление факта не требует отдельного PR.
