# Проверочные примеры и подготовка реальной приёмки

Дата: 28 октября 2026 года. Статус: подготовленные примеры для будущих спецификаций. Продуктовые тесты здесь не запускались; наличие примера не означает прохождение приёмки.

## 1. Что фактически есть в репозитории

Проверена локальная версия RM_UOR с HEAD `3d8704e4a6ff2195af4f2c0602ed11bff5d38f4b`.

- [catalog/catalog.json](../../../../catalog/catalog.json) содержит пустые списки целей, лидеров, назначений, источников и комментариев. Это не рабочая банковская карта для миграционного эталона.
- [tests/fixtures/maturity-demo.json](../../../../tests/fixtures/maturity-demo.json) явно помечен синтетическим набором. Для `demo-maturity` записан ожидаемый результат 50%, выполнены требования у 1 из 2 команд, покрытие 100%, одно исключение, `official: not_met`.
- [measurement.test.ts](../../../../src/features/evaluation/measurement.test.ts) содержит старые unit-примеры: бинарный метод с целью 1 принимает 1, не принимает 0, а значение 2 считает неизвестным. Это не пример цели с нулевым планом и не новый ручной статус.

Исторические сведения о карте и демонстрационные данные нельзя выдавать за актуальные банковские эталоны. Старое `no_events` не приравнивается автоматически к новой процедуре N/A с областью, причиной и периодом. Числовой ручной ввод не превращается из-за своего способа ввода в цель с состояниями «Не начата / В работе / Выполнена».

## 2. Примеры нового поведения из принятых решений

Ниже синтетические примеры, основанные на требованиях пользователя. Названия A-01–A-03 — идентификаторы примеров, не настоящие цели банка. После утверждения схем они должны стать машинными наборами с тем же смыслом.

### A-01. Независимые требования областей

Вход: одна числовая цель, условие «не меньше»; область ДИТ имеет факт 92 и цель 90, область кластера — факт 88 и цель 95. Нужные данные получены. Основание: D-021–D-022.

Ожидание: условие ДИТ выполнено, условие кластера не выполнено. Результат ДИТ не подменяет результат кластера; не вводится скрытое правило «все дочерние области должны выполнить». Этот пример проверяет результат условия, а не неуточнённое округление балла.

### A-02. Нулевой план счётчика

Вход: неотрицательный счётчик, цель 0. Основание: D-085.

| Факт | Ожидание |
| --- | --- |
| 0 | Условие выполнено, нормированное выполнение 100%; исходный факт 0 виден. |
| 1 | Условие нарушено, нормированное выполнение 0%; исходный факт 1 виден. |
| Отсутствует | «Нет данных»; факт 0 и успешный результат не подставляются. |

Этот пример не задаёт правило для отрицательных значений, положительного плана снижения или любого другого типа показателя.

### A-03. Возврат ручной цели

Исходное состояние: ручная цель опубликована как «Выполнена», описание результата и прежняя запись завершения сохранены. Основание: D-075–D-076, D-118.

1. Куратор предлагает «В работе» без причины — проверка показывает ошибку, включение такого возврата в готовый пакет и отправка запрещены. Незавершённый ввод сохраняется локально, общая версия остаётся прежней.
2. Куратор вводит причину — появляется локальное изменение с понятным «было / станет».
3. До merge общая принятая версия остаётся прежней; предложение не выдаётся за согласованный результат.
4. После принятия PR новое общее состояние — «В работе», прежнее завершение и причина возврата доступны в истории.
5. Числовой прогресс для ручного статуса не выдумывается; другие работы и независимые области не меняются только из-за этого возврата.

Точные поля и команды будут закреплены в контракте модуля. Этот текст не является уже реализованным HTTP-тестом.

### A-04. Пятничная динамика без изменения

Синтетический ряд одного показателя в одной области по D-119:

| Пятница | Наблюдаемый факт |
| --- | --- |
| 02.10.2026 | 80% |
| 09.10.2026 | 85% |
| 16.10.2026 | 85% |
| 23.10.2026 | 92% |

На каждой указанной дате есть отдельное наблюдение. Ожидание: участок 9–16 октября горизонтальный; значения не суммируются и не усредняются. Публикация ряда в обычном PR не подтверждает выполнение цели. Случай без нового наблюдения определён D-124 и рассмотрен отдельно в A-05; новое измерение из старого факта не создаётся.

Это ожидаемое поведение для будущей приёмки, не результат запуска промышленного графика.

### A-05. Пятница без обновления

Синтетический случай D-124: последнее успешное наблюдение — 92% от 22.10.2026. В пятницу 23.10.2026 свежих данных нет.

Ожидание: недельный график показывает 92%, исходную дату 22.10.2026 и предупреждение «Данные не обновлялись». В хранилище не появляется новое измерение за 23 октября; пропуск исходных наблюдений сохраняется. Дата факта и давность не меняются, новое подтверждение выполнения не возникает. Построение графика само не создаёт PR или согласованный срез.

Если прежнего значения нет, показано «Нет данных»; значение 0 не подставляется. Это ожидаемые результаты будущей приёмки, не выполненные продуктовые тесты.

## 3. Что нужно для банковского эталона

Для выбранной реальной цели подготовить: ID и название из переносимой карты; область и применимый состав; текущую методику с целевыми значениями; обезличенный исходный набор; сопоставления; ожидаемые факт, выполнение, полноту и возможность подтверждения; дату/период и известные источники. Кураторы проверяют именно эти ожидания.

Если источник, прежняя методика или историческое основание отсутствуют, это отмечается как пробел. Исходный смысл не восстанавливается из названия цели или демонстрационного теста. Пустой каталог публичного репозитория не отменяет выбранный пользователем перенос существующей карты из реального рабочего источника.

Сначала фиксируются вход и ожидаемый результат, затем проверяются расчёт, карточка, история и публикация одного и того же состояния. Работа на синтетике подтверждает соответствующие правила и границы теста; реальное получение ОКО, корпоративные права и миграция проверяются отдельно.
