# Роли и локальные учётные записи

25.10.2026. Прямое поручение: скрыть источники/корректировку и управление от обычного пользователя, оставить куратору; добавить6 персональных кураторов. Сохраняется прежнее разрешение реализовывать без промежуточных согласований и публиковать код в RM_UOR.

Выбран единый список возможностей для reader/curator, используемый меню и сервером. Отдельные роли директора/ИТ-лидера сейчас не ограничивают чтение: исходное назначение — общий обзор ДИТ и фамилии лидеров. Обычный пользователь видит опубликованные цели, факты, историю, планы, знания, доказательства, отчёты и может обновлять данные под своей учёткой/версию программы. Он не настраивает источники/профили, не импортирует/правит/подтверждает/публикует, не управляет копиями. Происхождение данных и ссылка на источник остаются видны в карточке цели.

Прятать только кнопки недостаточно: сервер по умолчанию запрещает действия изменения кроме явно разрешённых читателю. Прямой вызов скрытого API получает403. Конфигурация источников/сопоставлений, приватные операции и локальные правки не передаются в читательское состояние. Вход/выход пересоздаёт состояние страниц и закрывает диалоги.

Вход куратора: выбор имени из публичной проекции локального реестра{id,name} и пароль. Совместимость прежнего входа по персональному коду сохраняется. На сервере хранятся только salt+scrypt hash. Исходные пароли не попадают в код/демо/документы/Git. Новые записи сохраняются в исключённый .runtime/local-config/curators.json с сохранением существующего профиля и стабильныхID. Перенос реестра на другие станции выполняется защищённым локальным provisioning, а внутри банка может быть заменён штатной идентификацией. Локальный пароль роли не создаёт права записи Git.

Варианты: только скрыть меню не защищает API; полноценный новый SSO без банковской среды не даёт проверяемого результата. Общая политика поверх существующих локальных сессий выполняет поручение сейчас и оставляет точку адаптации идентификации.

Проверка: читательские/кураторские маршруты, запрет прямых обходов, переключение роли, выбранный аккаунт+неверный пароль, реестр без plaintext и сохранениеID, сборка и локальный показ. Отдельный реестр оставшегося разделяет исходные требования, локальное развитие и банковскую приёмку.
