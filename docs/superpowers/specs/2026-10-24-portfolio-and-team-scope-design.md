# Обзор всех целей ДИТ и выбор состава

Уточнение заказчика после демонстрации 24.10.2026. Предыдущий обзор автоматически выделял одну цель с фактами; заказчик хочет видеть весь портфель, общий статус и оставшуюся работу, а затем выбрать любую цель. В редакторе нужны галочки включения команд и объектов и добавление новых записей в базу знаний.

Заказчик ранее поручил принимать разумные решения самостоятельно, продолжать реализацию и ускорять независимые работы параллельно. Дополнительный цикл согласования макетов не требуется. Ниже решения исполнителя в пределах этого поручения.

## Подход

Рассмотрены: расширение длинной матрицы на главной; сохранение одного автоматически выбранного показателя; портфельная сводка с явным переключением «Все цели / выбранная цель». Выбран третий подход: сохраняет компактность и показывает именно общий состав. Матрица остаётся отдельной страницей.

Главная имеет три визуальные зоны: статус портфеля с распределением целей; сравнение ИТ-лидеров; компактный реестр полных названий целей с переходом в карточку. Реестр фильтруется по статусу. Выбор цели доступен и для целей без данных; тогда отсутствие фактов явно показано. Три ближайших действия можно раскрыть отдельно, не заполняя ими весь первый экран.

Одна цель — одна единица портфельного распределения. Статус цели берётся из её официальной общей оценки; результат отдельного ИТ-лидера не заменяет глобальный расчёт доли. Статусы назначений по лидерам показываются отдельно. Никакого усреднения фактических процентов разных целей. «Осталось» = все применимые цели минус подтверждённые. Полнота данных и актуальность — отдельные признаки; при недостатке данных нельзя объявить ДИТ успешным. Веса не меняют итог без отдельно утверждённой формулы.

Изумрудный означает подтверждение; коралловый красный — отклонение; янтарный — проверку; серо-синий — неизвестность. Брендовый бирюзовый служит акцентом интерфейса и графиком факта, а не доказательством подтверждения. Цвет сопровождается текстом/иконкой/числом. Основания: [WCAG use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html), [Tableau dashboards](https://help.tableau.com/current/pro/desktop/en-gb/dashboards_best_practices.htm). Используются установленные токены SDDS; новые библиотеки не нужны.

## Состав назначения

Две разные сущности не смешиваются: «Команды в расчёте» связаны с устойчивыми `participantIds`; «Продукты и объекты карты» сохраняют существующие текстовые группы `teams`. Наследованные группы не превращаются в расчётные команды по догадке. Команды выбираются среди справочника своего ИТ-лидера и уже включённых записей. Неизвестный ожидаемый состав остаётся неизвестным до явного выбора; пустой выбранный состав не считается выполнением.

Новый пункт создаётся по имени и типу: команда, продукт, ИТ-услуга или иной объект. Он появляется в списке с галочкой включения. Сервер назначает устойчивый id, сохраняет запись базы знаний и назначение атомарно как черновики куратора. Создание не теряется при ошибке публикации. Равнозначная существующая запись используется повторно, неоднозначность объясняется. Исключение из цели не удаляет справочную запись и прошлые факты.

Сохранение сравнивает исходное назначение с текущим: устаревшая форма получает понятный отказ без перезаписи новой правки. Изменённый состав оценки не наследует прежнее подтверждение; регресс действует по существующим правилам. Общие записи публикуются существующим Git-процессом; корпоративный контент остаётся локальным в публичном режиме.

## Граница

Этап не добавляет универсальные методики, прогнозы, корпоративный сбор или отчёты. Новые цели и данные будут поступать позже; интерфейс и расчёт не привязаны к количеству или техническому коду целей. Фактический браузерный осмотр выполняется при доступном CUA; отсутствие инструмента не заменяется заявлением о визуальной приёмке.
