# Чистая корпоративная исходная версия и недельная сводка

Пользователь разрешил реализацию без промежуточных остановок. Дополнительно прямо уточнил: прежнюю Git-историю сохранить отдельно, main сделать одной чистой целевой версией; история приложения начинается в банке. Секреты остаются локальными, для редактирования нужен отдельный файл.

## Решения

1. Выпуск0.4.0: сохранить прежнюю полную историю в отдельной архивной ветке и приватном Git bundle. После всех проверок создать новый корневой commit актуального дерева; main и release/current атомарно перевести на него с проверкой прежних удалённых refs. Никакие правки коллег не терять. Старые планы/акты доступны в архиве, текущая документация имеет одну входную точку.
2. Чистая установка не переносит `.runtime`, зависимости, .git, локальные настройки, факты и журналы. Экспорт поставки формируется из фиксированной разрешённой файловой выборки, без рекурсивного копирования пользовательских папок. Режим empty создаёт пустой каталог, demo — синтетический. Существующее рабочее место не перезаписывается. Реальные учётные записи сохранены здесь; перенос локального хеш-реестра — отдельное явно включаемое приватное дополнение. Публичный пример содержит только заполнители.
3. Недельная сводка — самостоятельный feature slice, текстовая информация, которая не меняет измеренные факты и подтверждения. Один куратор пишет собственный отчёт за неделю: главная сводка, выполненные задачи, внимание, планы следующей недели. Черновик защищён revision/CAS. Общая версия распространяется тем же release/current→main→обновить данные. Читатель видит только опубликованный каталог; куратор — общий набор плюс собственный явно помеченный черновик.
4. README даёт три маршрута: пользоваться, установить/перенести, продолжить разработку. Отдельный человеческий Markdown-гайд содержит действие→видимый результат и поиск ошибки. Агентский гайд содержит карту файлов/контракты/инварианты/точки расширения. Текущая мастерспека и карта архитектуры не ссылаются на исторические планы как на действующие инструкции.
5. Проверка архитектуры оценивает реальные границы, не обещает бесконечный масштаб или автоматическую совместимость. Общая инфраструктура отчётов отделена от индивидуальных пресетов; адаптеры получения от парсеров/расчёта; предметные функции от HTTP/UI/хранилища. Изменения — только при конкретной пользе; новые плагины не требуют выдуманного универсального фреймворка.

## Приёмка

- Новый каталог пуст, история и сессии отсутствуют; собственные данные здесь сохранены.
- Публичная поставка не содержит текущих паролей, хеш-реестра, корпоративного набора или старой .git.
- Недельный черновик недоступен читателю; опубликованная сводка доступна после получения общего каталога; параллельная правка отказывается по revision.
- Архивная ветка/bundle восстановимы; main имеет один commit и точное проверенное дерево.
- Руководства показывают фактические команды и названия экранов. Локальный прогон не считается банковской приёмкой.
