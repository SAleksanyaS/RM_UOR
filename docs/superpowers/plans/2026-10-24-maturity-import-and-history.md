# Следующий этап: загрузка Excel и история фактов

Заказчик поручил реализовать следующий полезный шаг, проверить оставшиеся требования и ускорить независимые задачи параллельно. Предыдущий этап опубликован в RM_UOR, основа — 91631d4.

## Результат

Куратор загружает XLSX модели зрелости через UI, задаёт период и при наличии дату обновления источника, видит распознанный состав, ошибки сопоставления и отличия, затем явно сохраняет новый срез. До сохранения текущие факты не меняются. Период не выводится из имени файла/времени загрузки. Оригинальный Excel остаётся локально и не попадает в Git.

Поддерживается предоставленная форма с колонками «Команда», «Метрика», «Значение метрики», «Цель метрики». Иерархические итоговые строки пропускаются. Исключения, отсутствие релизов/PR и пропуски различаются. Команды сопоставляются по устойчивому коду/точному имени/однозначному псевдониму; неоднозначность требует выбора куратора. Показатели связываются с объявленными метриками цели; новое правило не выводится автоматически из загружаемых фактов.

Срезы сохраняются неизменяемыми. Повтор идентичных фактов за тот же период не создаёт дубликат. Изменение фактов одного периода сохраняется как новая редакция с видимой разницей; положительное подтверждение не переносится на другие факты. Отрицательный результат применяется сразу. История показывает реальные периоды, при несовместимом составе/методике не рисует непрерывный сопоставимый тренд. Единственный период — отдельное состояние без выдуманной прошлой недели.

## Разделение работ и контракты

1. Парсер (`src/features/importing/maturity-parser.ts`) и синтетические тесты: `parseMaturityWorkbook(bytes:Buffer):Promise<ParsedMaturityWorkbook>`, проверка формата/объёма, Cached formula values only; формулы и внешние ссылки не исполняются. Данные строк: rowNumber, teamName, teamCode, metricName, value, target, state, reason. Пакет ExcelJS закреплён. Исходная книга заказчика проверяется локально, не включается в тестовые фикстуры.
2. Сервис/API: `POST /api/import/maturity/preview` (curator; name,base64,goalId,sourceId,period,sourceUpdatedAt?,teamMapping?,metricMapping?) возвращает previewId,summary,issues,changes,sample,evaluation и возможность принятия. `POST /api/import/maturity/commit` (curator; previewId) проверяет неизменность базы/профиля, атомарно сохраняет и пересчитывает. Предпросмотр привязан к куратору, имеет срок действия, не заменяет факты. Новый источник file создаётся согласованно с каталогом и может публиковаться как настройка. Сырые файлы только в `.runtime`.
3. UI: мастер файла → распознавание и исправления → предпросмотр → сохранение; понятные русские названия, дата обязательна, ошибка не уничтожает предыдущий срез. Доступ читателю к действию не выдаётся. История фактов доступна из карточки цели, подробности раскрываются.
4. Основной агент: интеграция истории/сравнения, аудит оставшегося плана, адресные проверки, один полный прогон и сборка, независимое review, публикация кода. Визуальная проверка зависит от доступности CUA; не заменяется утверждением по одному build.

## Проверки, которые имеют смысл

- 59 команд/295 строк исходного локального примера распознаются, но контрольные числа не подгоняются под код; публичные тесты используют другую синтетическую книгу.
- Пустые/нечисловые/неизвестные строки не превращаются в ноль или успех; агрегаты не удваивают факты.
- Неизвестная команда/метрика, конфликт дубликатов и пропавший обязательный показатель не принимаются как полное выполнение.
- Читатель и чужой/просроченный preview не могут сохранить данные; ошибка и устаревший preview сохраняют текущий снимок.
- Идентичная повторная загрузка не создаёт новую редакцию; изменённые факты требуют новой валидации, регресс немедленно снимает выполнение.
- История читает данные без отзыва текущего подтверждения; разные источники/составы не склеиваются в один тренд.

Один полный прогон после объединения; повторять только затронутые проверки при новом исправлении. Реальный корпоративный браузер и сертификаты сохраняют отдельный этап. Генератор презентаций и отчётов, recorder, новые цели и сложные методики будут отражены в аудите незавершённого, без ложных отметок «готово».
