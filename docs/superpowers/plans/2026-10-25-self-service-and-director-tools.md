# Самостоятельные цели, импорт и отчётность

**Spec:** ../specs/2026-10-25-self-service-and-director-tools-design.md
**Goal:** Полный UI-путь новой цели, реальные данные через таблицы, первый отчёт и ближайшие действия директора.
**Execution:** Параллельные независимые области по прямому поручению пользователя. Все агенты используют общий checkout и не коммитят/не пушат; интеграцией владеет root.

## Global Constraints

- Пробные значения не сохраняются как рабочие факты.
- Читатели не изменяют данные; действующие роли/CSRF сохраняются.
- Факт, план и подтверждение УОР разделены; нет ложного успеха из пустых/неполных данных.
- Существующие цели без measurement сохраняют legacy-методику.
- Корпоративные данные/сырые файлы/секреты остаются в .runtime и вне публичного Git.
- Устаревшие preview/CAS отклоняются, черновики сохраняются, связанные записи атомарны.
- Код публикуется по уже данному разрешению; содержание через release/current → main.

## Task 1 — сервер создания и методики

Owner agent goal_core. Создать features/goal-setup контракты, схемы, preview/commit, тесты; расширить domain/contracts, evaluation, publication validation/allowlist/history для measurement. Все правила и API — по spec. Не менять App.tsx/server/app.ts; root регистрирует routes. Не писать UI. Тесты собственного модуля; общий прогон выполняет root. Brief: .runtime/implementation/self-service/task-1.md.

## Task 2 — табличная загрузка

Owner agent table_import. Новая папка features/tabular-import, parser/profile/preview/commit/TabularImportWizard и тесты. Нормализованные Observation и факты — через текущие протоколы. Владеет SourceDefinition importProfile расширением только после согласования с agent1; domain/contracts и validate-version редактирует agent1. Не менять App/server/app; root интегрирует. Brief task-2.md.

## Task 3 — отчётность и директор

Owner agent reports_director. Новые features/reporting и features/director, модели/сервисы/routes/UI/CSS и проверки. HTML/PPTX из фиксированного state, реальные журнальные изменения и сроки; возможность реестра решений по существующим справочным объектам без подмены планов. Не менять общие domain/App/server/зависимости без root. Brief task-3.md.

## Task 4 — UI мастера и интеграция

Owner root. GoalSetupWizard/GoalSetupPage, шесть понятных шагов с показателями/назначениями/источником/пробными значениями, ошибки без потери ввода, сохранение → факты/публикация. Интеграция навигации, новых маршрутов/API и импорта. Координация контрактов и зависимости экспорта. Дополнить знания/пользовательские сценарии по результату, не переписывая существующее ядро.

## Task 5 — приёмка, гайды, запуск, публикация

Независимое review по областям, исправить существенные замечания. Один полный набор тестов, финальная сборка, HTTP-сценарий создания/импорта/отчёта на синтетике без изменения корпоративной карты. Попытка реального визуального просмотра; честно записать недоступность, если среда по-прежнему сломана. Гайды и фактические границы ready/remaining, локальный запуск, безопасный push кода в RM_UOR. Не считать недоступную корпоративную интеграцию готовой.

## Task 6 — база знаний

После core в освободившемся потоке: самостоятельный экран справочников и статей/методик, явные связи, мягкий архив/восстановление с проверкой использования и CAS. Отдельные features/knowledge; root подключает вместо старого общего редактора. Исторические даты оргструктуры не подменяются текущими связями. Brief .runtime/implementation/self-service/task-6.md.
