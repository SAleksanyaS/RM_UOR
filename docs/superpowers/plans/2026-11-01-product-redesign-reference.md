# RM_UOR: визуальный эталон и подготовка исправлений

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the coordinated reference slice. Steps use checkbox (`- [x]`) syntax for tracking. Independent agents own only the named research/fixture tasks; do not repeat the whole audit.

**Goal:** Подготовить на действующем приложении согласуемый визуальный эталон «Обзор → цель» и «Данные → готовый личный результат ОКО».

**Architecture:** Существующий production entrypoint и HTTP v1, Workbench read models, SQLite и личный OkoClient остаются источниками данных. Меняется слой представления; конфигурация ОКО переиспользуется как рабочий компонент без вложенного OkoApp. Синтетические сценарии запускаются на отдельном рабочем наборе и явно помечаются в материалах.

**Tech Stack:** React 19, TypeScript, Vite, Fastify, native SQLite, Playwright. Отдельный Node 22.16.0/npm 10.9.2.

**Spec:** `../specs/2026-11-01-product-redesign.txt` — предоставленная владельцем спецификация 1.0.

## Global Constraints

- База: `ac299a5508dba60df7d4f5b8152fb7aaf4655223`, `origin/codex/uor-workbench-rebuild`.
- Реальные пользовательские `.runtime`/userdata и Windows preview не трогаются. Работа в отдельном worktree `codex/uor-redesign-reference`.
- Светлая рабочая область, тёмный desktop sidebar 240–264px, исходный полный логотип `public/brand/rm-uor.png`, один основной акцент.
- Пять направлений, текущие capabilities, временные локальные роли, личный ОКО читателя, внешний merge в Bitbucket сохраняются.
- Backend, командные квитанции, ownership, exact refs и история не переписываются ради макета. Нет подмены успешных API-ответов.
- Сначала эталон на двух экранах и карточке цели. По разделу 16 входной спецификации массовый перенос начинается только после одного визуального согласования.
- Счётчики отражают существующий API. Личный ОКО не создаёт официально принятые факты. Отсутствующие значения не превращаются в нули.
- Один полный suite только после стабилизации итогового редизайна. На этапе эталона — затронутые проверки, сборка и реальные browser scenarios.
- Ни push, ни merge, ни обновление пользовательской установки не входят в этот этап.

## Review Focus

- Длинные русские имена и большие десятичные строки должны оставаться читаемыми; горизонтальная прокрутка допускается внутри таблицы, а не страницы.
- Пустой каталог не должен порождать демонстрационные цели; личная выгрузка остаётся доступна.
- Back/forward, смена области и выбранный согласованный срез должны сохранять контекст; исторические названия не подменяются сегодняшними.
- Неизвестный исход операции и ручной вход остаются видимыми; повторная загрузка не запускается сама.
- На узком экране drawer удерживает фокус и возвращает его инициатору; недоступная Панель УОР не получает полномочий из UI.
