# Реальные сборщики: инструкция внутреннему банковскому агенту

Состояние на 25.10.2026. Код выполняет реальную загрузку; без корпоративной настройки возвращает явную причину отказа и сохраняет последний принятый срез. Банковские адреса, API, версии Qlik/Confluence, SSO и сертификаты не угадывались и здесь не испытывались. Локальные проверки используют только вымышленные факты и 127.0.0.1.

## Поддержанный протокол

`SourceDefinition.collection` хранит общую конфигурацию без секретов:

```json
{
  "adapter": "http",
  "format": "observations-json",
  "authProfileId": "bank-profile",
  "endpoint": "https://source.example.invalid/export.json"
}
```

Способы: `http`, `confluence`, `qlik`, `browser`. Форматы: `observations-json`, `csv`, `xlsx`. Для CSV/XLSX у источника должен быть сохранён `importProfile`: `tabular-v1` (колонки, сопоставления, явные значения по умолчанию) либо `maturity-xlsx-v1` (команды/метрики). У нескольких целей укажите `collection.goalId`. Для модели зрелости явно укажите `parameters.period` (YYYY-MM-DD), при наличии `parameters.sourceUpdatedAt`. Дата загрузки никогда не заменяет дату фактов.

Нормализованный JSON принимает только envelope `schemaVersion:1` и `observations`. Каждый факт содержит все перечисленные поля:

```json
{"schemaVersion":1,"observations":[{"goalId":"g1","leaderId":null,"participantId":"global-dit","participantName":"ДИТ","metricId":"g1","metricName":"Показатель","value":75,"target":80,"unit":"%","state":"numeric","reason":null,"period":"2026-10-01","sourceUpdatedAt":"2026-10-01T00:00:00Z"}]}
```

ID/sourceId/downloadedAt формируются локально. Состояния `numeric`, `missing`, `exception`, `no_events`; для нечислового факта обязательна причина, value=null. Пустая выгрузка, повтор одного измерения, неизвестный участник/лидер/показатель и несоответствие явной методике отклоняются. Полнота оценивания определяется заявленным составом цели, а не присутствием строк в файле. Успех загрузки не подтверждает достижение цели.

## Приватный доступ

Создайте `.runtime/local-config/connectors.json` на компьютере владельца. `.runtime` не включается в Git. Пример с вымышленным адресом:

```json
{
  "profiles": {
    "bank-profile": {
      "allowedOrigins": ["https://source.example.invalid"],
      "bearerEnv": "UOR_SOURCE_TOKEN",
      "caFile": "C:/private/corporate-ca.pem",
      "maxBytes": 10485760,
      "timeoutMs": 30000,
      "retries": 1,
      "browser": {
        "channel": "msedge",
        "profileDirectory": "bank-source",
        "headless": false,
        "loginUrlPattern": "login|sso|authorize"
      }
    }
  }
}
```

Удалите неиспользуемые поля примера. Токен задаётся в окружении процесса приложения; его значение не вводится в сценарий. `headersEnv` — словарь «имя HTTP-заголовка → имя переменной окружения» для Authorization Basic, X-Qlik-User или deployment-specific session header. Например, `{"Authorization":"UOR_AUTHORIZATION"}`; сама переменная содержит полный требуемый заголовок. HTTP/WS поддерживают `certFile`, `keyFile`, `passphraseEnv`. TLS проверяется всегда. HTTP/WS без TLS разрешены только для localhost-стенда.

`allowedOrigins` содержит точные origins без пути и завершающего `/`. В браузере перечислите также фактически необходимые origins SSO/CDN/ресурсов; всё остальное блокируется до обращения. HTTP-переход на другой origin не пересылает токены и возвращает manual_login_required. Для браузерных клиентских сертификатов используйте `browser.clientCertificates` с `origin`, `certFile`, `keyFile`, необязательным `passphraseEnv`. Настройка `caFile` применяется к Node HTTP/WebSocket. Chromium/Edge использует системное/браузерное доверие CA: импортируйте корпоративный CA штатным способом. Проверка TLS не отключается.

Можно задать `browser.executablePath` вместо channel для совместимого Chromium/Сбербраузера. Программа не устанавливает браузер автоматически. Фактическая совместимость конкретной сборки Сбербраузера, политики запуска/расширений, прокси/PAC и smartcard/ГОСТ требуют испытания внутри банка. Профиль создаётся только под `.runtime/browser-profiles/<profileDirectory>`, где имя состоит из латинских букв, цифр, `_` и `-`. Один профиль выполняет одну операцию; ожидающие операции поддерживают отмену. Не используйте одновременно этот профиль в отдельном процессе браузера.

## Особенности источников

**HTTP:** endpoint — реальная ссылка файла. GET, проверка сертификатов, до четырёх перенаправлений внутри origin, контроль длины/размера и абсолютный timeout. Повторы ограничены 0–2 и применяются к временным сетевым ошибкам/429/ошибкам сервера, а не к авторизации/формату.

**Confluence Cloud/Data Center:** задайте `confluence.deployment` и точный `confluence.downloadUrl` вложения. URL получает администратор из штатного Confluence API/ссылки скачивания для этой установки. Код не выдумывает host, REST route, идентификаторы страницы или версии. Прямой файл скачивается по настроенному профилю. Если вложение защищено только интерактивной SSO-сессией, используйте браузерный сценарий; не пытайтесь сохранять HTML страницы входа как XLSX. Автоматический поиск «последнего вложения» не выполняется: владелец задаёт точную версию/URL либо использует браузер.

**Qlik:** `endpoint` — точный ws/wss адрес Engine для вашей установки и сессии; `qlik.appId`, `objectId`, `exportFormat` (`CSV_C`, `CSV_T`, `OOXML`) обязательны. Выполняется JSON-RPC `OpenDoc` → `GetObject` → `ExportData` (`/qHyperCubeDef`, export state `A`), затем реально скачивается `qUrl` с проверкой origin и TLS. Доступ к Engine, сертификат/сессионные заголовки и право экспорта на объект должны быть подтверждены внутри банка. Код не обходит SSO и не выполняет универсальный логин в Qlik. Если Engine запрещён либо экспорт требует интерфейсных выборок, настройте браузерный сценарий. Плоская таблица объекта и гиперкуб должны поддерживать этот метод; специальные объекты требуют отдельной явно реализованной схемы экспорта.

## Браузер, ручной вход и recorder

1. Куратор выбирает источник, способ, формат, имя приватного профиля, прямой адрес/идентификаторы через форму «Получение данных». JSON оставлен в дополнительных настройках администратора.
2. Сохраните конфигурацию источника. Читатель также может открыть свой настроенный профиль кнопкой «Открыть профиль для входа», выполнить обычный вход и нажать «Вход завершён». Пароли/OTP/SSO выполняются человеком в браузере; приложение их не записывает.
3. Для записи куратор задаёт начальную страницу, открывает браузер, выполняет фильтры и скачивание, затем завершает запись в приложении.
4. Recorder наблюдает реальные DOM click/change/select/check и событие скачивания. Запись ограничена главным frame начального origin. Поля паролей, токенов, OTP, формы с password, SSO/login URL исключены. Значения текстовых полей/select не сохраняются: в шагах остаются имена параметров. После записи владелец явно заполняет безопасные значения фильтров в форме и проверяет список действий.
5. Снимки шагов приватны, редактируемые поля/iframe/элементы data-sensitive маскируются. Ссылки открываются только владельцу сессии с `Cache-Control: no-store`. Оригинальные снимки не помещаются в общую конфигурацию. Нельзя гарантировать обнаружение секрета, отрисованного сторонней страницей в произвольном обычном тексте; до записи используйте представление без секретов и проверяйте приватные снимки.
6. Общий сценарий `scenario:{id,startUrl,steps}` хранится внутри collection; также есть локальный `scenarioId` для `.runtime/connector-scenarios`. Поддержаны только goto(url), click(selector), fill/select(selector,parameter), check(selector,checked), wait(selector), download(selector). Селекторы берутся из data-testid/id/name; неоднозначный selector не записывается. При изменении разметки сценарий перепроверяется/перезаписывается. Свободный JavaScript/shell не исполняется.
7. Сценарий воспроизводится тем же Playwright Chromium persistent profile. Перед действиями проверяется origin. Размер браузерной загрузки ограничивается CDP download progress, факт проверяется после получения. Сигнал отмены закрывает контекст, освобождает очередь и удаляет временные загрузки. Каждый шаг ограничен timeout, весь replay — максимум две минуты. Запись/ручной вход автоматически закрывается через 15 минут.

Recorder не записывает внутренние клики cross-origin iframe и не создаёт универсальные semantic selectors для custom web components. Такие сценарии требуют ручной настройки поддержанных селекторов или адаптации с проверкой. Нельзя нажимать «успех» на отсутствии файла: download-шаг и реальное непустое содержимое обязательны.

## Сохранение и расписание

`collectConfiguredSource(context,session,sourceId,signal,onStage)` возвращает `{snapshots,duplicate}` только после реальной выгрузки, проверки и атомарного принятия личных фактов. Снимки имеют стабильный приватный ownerInstallationId, личный статус и зафиксированную историческую основу. Читатель, сменивший роль на куратора на том же компьютере, видит свои полученные факты; чужая установка их не читает. Идентичность проверяется по содержимому измерений в той же локальной установке/источнике/периоде/цели. Сессионный ownerSessionId сохранён для происхождения; прежние снимки без installation ID используют прежнюю сессионную границу. Конфигурация и общий каталог при сборе читателем не меняются. Отказ сохраняет предыдущие факты; файл/диагностика остаются приватно в `.runtime`.

Личное расписание использует ту же функцию. Оно привязано к сессии, источнику и имени профиля, действует только при запущенной программе и живой сессии. Пропуски не воспроизводятся лавиной: следующая дата считается от текущего тика. Изменение профиля/истечение сессии снимает задание. Во время maintenance сбор не стартует. Есть операция/владелец/отмена; автоматической публикации нет. При закрытии приложения фоновые операции отменяются.

## Диагностика

- configuration_required: нет конфигурации, профиля, переменной окружения, сценария или требуемого поля; старый `mode=stub` не имеет успешного fallback.
- manual_required: источник ручной либо файловый без настроенного адаптера.
- manual_login_required: HTTP401, переход на внешний SSO origin, URL входа или закрытая сессия Qlik. Откройте личный профиль/обновите разрешённый токен.
- access_denied: HTTP403 либо попытка читать чужую запись/снимок.
- certificate: проверка TLS/CA/клиентского сертификата не пройдена; доверие не отключать.
- network / timeout: нет сети/адреса/ответа в установленное время. Исправьте среду; не подставляйте старый файл как новую выгрузку.
- format / incomplete: неподдержанный формат/профиль, чужая цель, повторы, неизвестная методика, неполный файл или отсутствие download. Проверьте исходную выгрузку.
- cancelled: операция остановлена владельцем либо закрытием программы.

Техническое сообщение не содержит токенов, исходного HTML, cookies или содержимого ответа. Последняя диагностика хранится отдельно для каждой сессии/источника.

## Проверка внутри банка

Сначала настройте синтетическую цель/участников и отдельный приватный профиль. Подтвердите доверие CA, точные origins, executable/channel, способ SSO и доступность endpoint без ввода секретов в общую конфигурацию. Выполните успешное получение, повтор того же содержимого, смену значения и отказ403, истечение входа, отмену и отключение сети. Сравните исходный файл и принятые факты/период/единицу/порог. Убедитесь, что смена роли на том же компьютере сохраняет личные факты, другая установка не читает их, а чужая сессия не открывает приватный screenshot. Затем настройте реальный корпоративный каталог; публикация банковских оригиналов/фактов в demo-only репозиторий запрещена.

Локально испытаны HTTP/сохранённый CSV/XLSX, точный download Confluence на стенде, настоящий Qlik JSON-RPC mock server с HTTP-файлом, живой установленный Microsoft Edge с Playwright persistent profile и реальным download, recorder click/change/select/download с маскировкой, очередь/отмена/ограничение размера/расписание. Эти испытания доказывают выполнение реализации, но не наличие прав и совместимость конкретного банковского окружения.


## Дополнение после независимого аудита

Браузер запускается с serviceWorkers:block. Все WebSockets отдельно проверяются routeWebSocket; ответные перенаправления Chromium перехватываются до перехода на запрещённый origin. Фактический Edge-стенд подтвердил ноль запросов к неразрешённой второй службе при fetch/WebSocket/redirect. Некорректный HTTP Location возвращает format, не завершает сервер.

Для записи теперь обязательно задаётся collection.authenticatedSelector — устойчивый элемент отчёта, видимый только после входа. До его видимости и при наличии видимых признаков входа не записываются ни действия, ни снимки. Это явная проверяемая граница авторизации, включая SPA входа на `/`. Ручной вход отдельно запускает браузер без установки recorder-инструментов. Общая схема запретит секретные имена параметров и явные credential values до сохранения source-черновика/публикации.

Личный профиль доступа настраивается через форму: разрешённые сайты, браузер/путь/приватная папка, имена переменных окружения, пути CA/клиентских сертификатов/ключей, лимиты. Значения секретов в форме не принимаются; переменные остаются в окружении процесса. Дополнительные клиентские сертификаты и несколько заголовков также доступны в приватном файле. GET/POST /api/connectors/profiles требуют локальную сессию, возвращают только схему env names/paths, сохраняют .runtime/local-config/connectors.json атомарно с CAS revision. Смена файла вне формы требует перечитывания, чужие изменения не затираются.

Перед принятием файла повторно сверяется captureEvaluationBasis целей источника. Смена методики/состава/организационной основы во время загрузки отклоняет результат; файл до принятия очищается и прежние факты сохраняются.
