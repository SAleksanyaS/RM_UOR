# Кандидат завершённого редизайна РМ УОР 0.5.0

Дата: 1 ноября 2026. Ветка: `codex/uor-redesign-reference`. База: `ac299a5508dba60df7d4f5b8152fb7aaf4655223`. Версия приложения остаётся 0.5.0; точная ревизия каждого кодового архива указана в `DISTRIBUTION_MANIFEST.json`. Утверждённый визуальный эталон сохранён отдельным коммитом `32106a9`.

## Что входит

Штатный Workbench получил общий брендированный каркас, таблицы целей и исполнения, предметное сравнение пакета, встроенное личное ОКО, согласованное обслуживание, тему и защиту несохранённых форм. Сохраняются прежние API, расчёт, SQLite, import/enrichment, command receipts, backup/restore и управляемый запуск.

Функциональные изменения: полный граф exact Git candidate перед передачей; продолжение своей proposal-ветки после движения main; сохранённые время и ссылки исторического preview; доверенная принадлежность частных кандидатов; `publication_anchor.id === packageId`; sandbox браузера и cleanup loader; отдельные сохранение/readback и восстановление составного сохранения. Точные имена и единицы исторического результата поступают из сохранённой редакции методики.

Читатель создаёт и повторяет свои личные выгрузки без общих curator полномочий. Локальный переключатель роли остаётся; внешний merge по-прежнему выполняется в Bitbucket. Личные сценарии не создают официальные факты и подтверждения автоматически.

## Проверки

Фактические результаты финальных gates записываются в [журнал завершения](../validation/redesign-completion.md). Исторические результаты прошлого кандидата0.5.0 сохранены в [прежнем акте](workbench-candidate.md) и не выдаются за новый полный прогон.

Owning evidence: [формы и точность оснований](../validation/redesign-completion-forms.md), [публикация](../validation/redesign-completion-publishing.md), [личный ОКО](../validation/redesign-completion-oko.md), [UI и карта функций](../validation/redesign-completion-ui.md), [зависимости и SQLite](../validation/redesign-dependencies.md).

[Полная карта наследия](../validation/redesign-reuse-map.md) отдельно перечисляет перенесённые, адаптированные, частично соответствующие и отложенные возможности, включая матрицу руководителей, отчёты/PPTX и библиотеку.

## Перенос без потери данных

Пакет содержит код, публичные шаблоны и инструкции. Рабочая база, конфигурации, браузерные профили, сертификаты, выгрузки, зависимости и личные файлы в него не входят. Исходную папку владельца и её `.runtime` не заменять содержимым ZIP.

Для знакомства распакуйте код в новую разрешённую папку, проверьте manifest, установите согласованные Node/npm, выполните `npm ci`, `npm run build`, затем следуйте README для первого запуска. Пустая установка не содержит синтетические цели из демонстрации; fixture запускается только специальным скриптом на отдельной пустой базе.

Для существующей Git-копии сначала сохраните собственную резервную копию и исходную ревизию. Применяйте diff/bundle в отдельной ветке или отдельной копии, согласуйте местные изменения и проверяйте обновление по [руководству](../guides/workbench-recovery.md). Не запускайте `git reset --hard` и не удаляйте `.runtime` ради чистого запуска. Новый код и рабочие данные обновляются раздельно.

Пользовательская Windows-папка `RM_UOR-0.5-preview` не обновлялась из текущей среды. Миграция реальных данных и подтверждение новой версии владельцем остаются отдельным действием после проверки поставки.

## Неподтверждённые условия

Linux/Chrome и синтетические источники не подтверждают банковские адреса, SSO, ГОСТ, smartcard, прокси, СберБраузер, Windows и Office. Внешние Bitbucket enforcement/registry binding требуют принятой настройки. Свежий `npm audit` и ограничения WAL рассмотрены отдельно; оставшаяся moderate цепочка не скрыта. Полный перечень — [границы и дальнейшая работа](../remaining-work.md).
