# Границы выпуска 0.6 и следующая проверка

Реализованные маршруты и доказательства перечислены в [акте0.6](validation/product-2026-11-02.md), инструкции — в [руководстве](guides/product-0.6.md). Этот список не выдаёт локальную синтетическую проверку за внедрение в банк.

## Требует целевой среды

1. СберБраузер 152.0.7977.120 на фактическом корпоративном Linux/рабочем ПК: SSO/service workers/ГОСТ/smartcard/CA/proxy, закрытие/возобновление реального окна, реальные выгрузки ОКО и версии вложений Confluence. Переход после входа сохраняет живой контекст и вкладку, но завершает его фоновые задачи; стадия повторного отчёта запрещает новые service workers, Web Workers и Shared Workers. Worker-dependent отчёты и экспорт через новое окно или дополнительную вкладку требуют отдельной проверенной адаптации; последнее останавливается с `REPORT_NEW_WINDOW_UNSUPPORTED`. Поддержана одна выбранная вкладка отчёта и её фреймы; проверить экспорт в ней на целевом ОКО. Выбор авторизованного popup при ручном входе до перехода к отчёту сохраняется. Защитная обработка страницы отчёта ограничена 16 МиБ в памяти и не сохраняет её содержимое. Разрешённые во время ручного SSO фоновые сервисы не покрыты доказанной packet-level изоляцией средствами приложения; корпоративную сетевую политику подтверждает ИТ.
2. Точный разрешённый корпоративный URL/DOM ГигаЧат, ручной вход, согласие на конкретный evidence bundle, потерянный ответ и reconciliation без второго сообщения.
3. Приватный реестр hostname и подтверждённая личность. Local-preview оставляет внешнюю отправку и применение accepted main закрытыми; он не выдаёт права организации.
4. Native Bitbucket/terminal binding и политика классификации общих данных для точного принятого repository identity. По умолчанию классификация закрыта; одной строки repositoryUrl недостаточно. Нельзя заменить это `classifyRecord:()=>true`. Нативное получение Git, локальный validator и code update не доказывают защищённый корпоративный merge gate.
5. Открытие XLSX/PPTX/PDF в целевом Office/просмотрщике, шрифты и печать. Локальный рендер не гарантирует идентичную Office-вёрстку.
6. Установка подготовленного Linux x64 комплекта на фактической корпоративной ОС, системный Git и trusted Sber path; Windows launcher сохранён, но новый Windows-installation run здесь не выполнен.

## Данные и поддержанные пределы

- Выбранные материалы30 октября содержат58 команд/5 метрик и происхождение. Источник25 октября для команд отсутствует; его агрегаты остаются reported claims.30 целей/177 назначений по доступной истории не восстановлены и не выдуманы.
- Сырой CSV/TSV просматривается до100000 строк/1 млн ячеек/10 МиБ; XLSX и обычный импорт имеют отдельные защитные пределы. Измерения относятся к описанной пятиколоночной fixture и тестовому хосту.
- Shared setup ограничен900000 байтами, поддержанными типами и разрешёнными файлами. Универсальные плагины, любые Office-шаблоны/формулы/макросы и произвольные скрипты не исполняются.
- Несохранённый ввод не является гарантированно переживающим аварийное закрытие автосохранённым черновиком. Durable receipts и формы восстановления относятся к уже отправленным операциям.
- Чужой личный архив не становится общим пакетом. Восстановление на другом installationId требует той же подтверждённой личности; сеансы/сертификаты/допуск не переносятся.
- История бессрочная: длительные объёмы реальной работы, ёмкость диска и retention политики организации требуют отдельного наблюдения. Полный backup нельзя считать проверенным только по наличию ZIP.

## Продуктовый следующий шаг

Провести наблюдаемую приёмку с читателем, редактором и руководителем: первый сохранённый файл, найденная причина статуса, изменение правила с preview, готовый отчёт без ручной переделки, неделя→действия, установка коллеги и безопасное обновление. Измерить время/ошибки/необходимую помощь; исправить реальные препятствия. Оценка выручки или готовности платить без таких наблюдений не является доказанной.

Старые ограничения0.5, где отчёт/база знаний/weekly считались неподключёнными, больше не описывают0.6. Исторические акты сохраняются в Git и помечены в VALIDATION.
