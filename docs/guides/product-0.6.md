# РМ УОР 0.6 — установка и ежедневная работа

Руководство к выпуску от 2 ноября 2026 года. Точный состав исходников, результаты проверок и ограничения приведены в [акте выпуска](../validation/product-2026-11-02.md). Предыдущие руководства 0.4/0.5 описывают прежние состояния интерфейса; для новых модулей используйте этот документ.

## 1. Что теперь можно сделать

Рабочее место связывает четыре задачи: получить исходные данные, разобраться в показателях, подготовить управленческий отчёт и передать коллегам согласованную настройку. Оно работает на личном компьютере. Принятая общая версия объектов хранится в Git; постоянного общего сервера приложения нет.

Начать можно с одного файла. Для его сохранения не нужны цель, справочник, сопоставление столбцов или принятый каталог. Разбор, обогащение и принятие фактов выполняются отдельными явными действиями. Ошибка разбора не удаляет исходник.

В новой поставке есть выбранные владельцем материалы модели зрелости: оригинальные XLSX/PPTX, 58 команд, 5 метрик и проверенная привязка к 8 руководителям. Материалы доступны для изучения сразу. Они не создают автоматически принятые бизнес-факты, аттестации или права доступа.

Практический маршрут: **Данные → База знаний → Цели → Обзор/дашборд → Отчёты → Недельная сводка**. Для настройки и переноса используйте **Настройки** и **Обновления**. Панель УОР отвечает за пакет изменений и публикационный процесс.

## 2. Первый запуск подготовленного комплекта

Подготовленный архив `RM_UOR-0.6.0-linux-x64…tar.gz` предназначен для Linux x64. В нём находятся закреплённые Node.js22.16.0/npm 10.9.2, зависимости из lock-файла и чистый Git-checkout принятой версии. СберБраузер и системный Git устанавливает ИТ в разрешённом контуре. Этот комплект не является доказательством совместимости с любой корпоративной Linux-сборкой.

1. Получите проверенный комплект у сопровождающего и распакуйте в отдельную разрешённую папку на локальном диске, вне сетевых и автоматически синхронизируемых каталогов. Не распаковывайте поверх рабочего места с данными.
2. ИТ один раз выбирает установленный СберБраузер 152, проверяет права на папку и создаёт ярлык «РМ УОР».
3. Откройте ярлык. Альтернатива для подготовленной папки — `START_RM_UOR.sh`. В обычной работе вводить команды и устанавливать зависимости не требуется; служебное окно запуска может оставаться открытым.
4. Откроется локальный адрес рабочего места в СберБраузере. По умолчанию интерфейс использует `http://127.0.0.1:5173`, API — порт4174. Другие значения показывает сопровождающий, если стандартные порты заняты.
5. Откройте **Настройки → Рабочее место**: проверьте версии, доступность папки, браузер и первые шаги. Затем загрузите небольшой файл в «Данных».

Ежедневный запуск не выполняет `npm install`, не создаёт вторую legacy-базу и не стирает конфигурацию. Закрытие вкладки приложения не равно остановке локального процесса. Для обычной остановки закройте окно запуска штатным способом; не удаляйте `.runtime`.

## 3. Однократная подготовка ИТ

Этот раздел предназначен сопровождающему. Обычному пользователю JSON и терминал не нужны. Для подготовленного Linux-комплекта команда из его корня использует вложенный Node:

```text
runtime/node/bin/node scripts/install-local.mjs --browser-executable /absolute/path/to/sberbrowser --desktop-directory /absolute/path/to/Desktop
```

Путь браузера должен быть фактическим абсолютным путём к установленному СберБраузеру. Проверка вызывает `--version`, проверяет название и точную версию152.0.7977.120. Заявленная в исходном TXT целевая версия —152.0.7977.120; точный build и банковский вход проверяются на целевом ПК. Пример пути из чужого компьютера не следует копировать как настройку своего.

Для исходного ZIP сначала установите закреплённый Node/npm, затем выполните `node scripts/install-local.mjs --install-dependencies`. Установка зависимостей явно отделена от ежедневного запуска; существующая папка `node_modules` автоматически не заменяется. Прокси/CA настраиваются разрешённым порядком организации, проверка TLS не отключается. Выполните `npm run build` и проверьте первый запуск. Исходный ZIP не содержит Git-историю и сам по себе не поддерживает кодовое Git-обновление: для него нужен принятый clone или подготовленный комплект.

`config/site.local.json` создаётся только при отсутствии. Он содержит разрешённые физические папки, порты, режим доступа и локальный путь браузера. После переноса папки ИТ проверяет `allowedWorkspaceRoots`; символические ссылки в пути рабочего места не используются. В файле не следует хранить пароли, cookies или сертификаты.

Корпоративный Git и реестр допуска подключаются по утверждённым точным адресам. Одного URL недостаточно для полноценной банковской публикации: требуются проверенные Bitbucket/terminal binding, политика классификации общих записей и защищённый main. Эти сведения в комплекте не выдуманы. Раздел «Общие данные» остаётся закрытым для применения, если соответствующий допуск или binding не настроены.

## 4. Личное и общее: что является истиной

**Локально** находятся исходные выгрузки, личные черновики, операции, история отчётов, настройки вида и личный браузерный сеанс. **В принятом Git** находятся опубликованные общие объекты и их версии. **В общем пакете настройки** передаются выбранные справочники, проверенные определения и пресеты. **В личной резервной копии** переносится рабочая история конкретного подтверждённого владельца.

Читатель может получать собственные файлы, смотреть данные и использовать разрешённые личные действия. Редактор готовит изменения и пакет. Принятие общего результата определяется правами Git/Bitbucket; переключатель приложения сам по себе их не выдаёт. Скрытая кнопка не является защитой: сервер отдельно проверяет владельца, capability, версию и CSRF.

Первый запуск использует явно обозначенный **локальный режим**. Переключение «Читатель/Редактор» сохраняет ту же личность. Оно полезно для настройки и проверки путей, но не даёт банковский допуск, право отправки в ГигаЧат или применения принятого main. Для этих операций нужна подтверждённая политика организации.

Не передавайте коллегам свою `.runtime`, профиль браузера или файл личной конфигурации как способ настройки. Общий пакет создаёт одинаковые настройки при сохранении разных личностей. Личная копия предназначена тому же подтверждённому человеку; одинаковое отображаемое имя не доказывает владение.

## 5. Навигация и внешний вид

Основные разделы находятся в боковой панели. На широком экране панель сворачивается, на узком открывается как выдвижное меню. Предпочтение сохраняется для владельца. Быстрый переход доступен по Ctrl+K. Закрыть диалог можно Escape, фокус возвращается к вызвавшему элементу.

Добавляйте в избранное разделы, отдельные цели, команды и сохранённые версии отчётов кнопкой со звездой. В быстром переходе откройте нужный объект, измените порядок кнопками «Выше»/«Ниже» или Alt+↑/Alt+↓. Переключатель «Показывать избранное» временно скрывает список. Закладка отчёта открывает именно сохранённую версию. Если объект больше недоступен, его закладку можно убрать из избранного.

В раскрытии **Стандартный личный вид** команда сбрасывает избранное, недавние разделы, стартовый раздел, тему, плотность, боковую панель, сортировки и выбор столбцов. Выбранные область и период, получатель уведомлений, рабочие данные и права доступа сохраняются.

Откройте **Настройки → Внешний вид**, чтобы выбрать светлую, тёмную или системную тему и плотность. Изменения внешнего вида не меняют расчётные правила. Настройка темы не должна перезаписывать отдельно сохранённую свёрнутость панели; при конфликте или неопределённом сохранении интерфейс предлагает сверить состояние.

Область и дата в общей панели задают контекст целей и расчёта. «Данные», «База знаний», «Отчёты», «Настройки» и «Обновления» доступны и без общего каталога. Пустой экран предлагает следующее действие, а не заполняется фиктивными результатами.

Большая таблица прокручивается в своей области; вся страница не должна расширяться за границы окна. Не полагайтесь только на цвет статуса: рядом есть текст, объяснение или основание. Перед уходом с изменённой формы сначала сохраните её либо явно подтвердите отказ от ввода.

## 6. Сначала сохранить исходник

В **Данных** доступны файл с компьютера, ручная таблица и личное получение через браузер. Confluence можно использовать как источник скачанного вложения либо настроенного браузерного сценария. Приложение не подставляет неизвестный корпоративный адрес API.

Для локального файла нажмите **Добавить файл** и выберите исходник. Для ручного ввода используйте **Ввести таблицу**: задайте название, столбцы и строки, затем сохраните. Пустое значение, текст «Нет данных» и числовой ноль остаются разными исходными значениями.

В списке показываются имя, тип, источник, время получения, размер, состояние и доступные действия. Карточка показывает hash и происхождение. Время получения — время скачивания; дата самих данных отдельно и может быть неизвестна. Для Confluence версия вложения, страница и исходная дата отображаются только если они действительно получены.

Скачивание оригинала возвращает сохранённые байты. CSV/TSV/XLSX можно просматривать в поддержанных пределах. XLS/OLE и неизвестный формат могут быть сохранены без табличного просмотра. HTML страницы входа, повреждённый контейнер и прерванная загрузка не объявляются успешными фактами. Мягкое скрытие убирает файл из обычного списка, но сохраняет байты и историю.

## 7. Получение через СберБраузер

Откройте **Данные → Получение файлов**; кнопка **Получить файл** в списке исходников ведёт туда же. Настройте личный сценарий: установленный СберБраузер, точный URL источника и разрешённые origins. Пароли и сертификаты вводятся и выбираются в штатном браузерном/системном диалоге; они не переносятся в Git или общий пакет.

Нажмите **Открыть браузер для входа**, выполните ручной вход и нажмите **Завершить ручной вход**, затем **Выбрать элемент отчёта в браузере**: нужен однозначный видимый признак уже открытого отчёта. Можно начать сразу с выбора элемента и войти в открывшемся окне. После выбора оставьте это окно открытым и нажмите **Начать запись действий**, затем примените фильтры и выполните экспорт. Вход, выбор элемента и первая запись используют один личный сеанс; действия входа не записываются. Подготовленное окно ожидает начала записи до 15 минут.

Получение исходника отделено от последующего сопоставления. После события скачивания приложение сохраняет байты, владельца, hash и квитанцию до объявления о сохранении. Закрытие настройки или ошибка парсера не должны лишать полученного файла. При неопределённом результате используется восстановление прежней операции.

**«Файл получен» и «сценарий можно повторить» — разные состояния.** Если кнопку экспорта не удалось однозначно записать, выберите подходящее записанное действие или дозапишите его. Затем выполните проверку сценария: повтор должен действительно получить новый сохранённый артефакт. Индикатор готовности отчёта сам по себе не является кнопкой экспорта.

Если подготовленное окно закрыли до записи, истекли 15 минут ожидания или приложение перезапустили во время настройки, выполните новый ручной вход и явно продолжите текущую операцию. Окно для записи можно закрыть штатной командой освобождения своего профиля. Не копируйте чужой профиль и не удаляйте lock-файлы вручную. Живое либо неоднозначно принадлежащее окно не завершается принудительно. При неопределённом результате проверьте прежнюю операцию вместо запуска многих одинаковых экспортов.

Для очередной выгрузки нажмите **Получить файл ещё раз**. Приложение проверит личный профиль и при необходимости запросит ручной вход. Запись и повтор используют одну выбранную вкладку отчёта. Перед повтором приложение завершает фоновые задачи этого контекста и запрещает новые service workers, Web Workers и Shared Workers. Выгрузка, которой нужны такие задачи, новое окно или дополнительная вкладка, требует отдельной адаптации. Страница отчёта проверяется в памяти с пределом 16 МиБ. При невозможности установить ограничения повтор останавливается; защита браузера не отключается.

Этап ручного входа допускает фоновые сервисы, необходимые SSO. Ограничения адресов приложения на этом этапе не являются доказанной сетевой изоляцией каждого запроса таких сервисов. Разрешённость корпоративного входа и сетевую политику подтверждает ИТ в целевом контуре.

## 8. Просмотр и обработка таблицы

Карточка файла показывает первые50 строк. Поиск и сортировка выполняются по всему разобранному набору. Для сырого CSV/TSV предусмотрены пределы100000 строк,100 столбцов,1000000 ячеек и10 МиБ. XLSX сохраняет отдельный проверенный предел20000 строк и защитные ограничения OOXML. Обычное принятие фактов не расширено автоматически до100000 строк.

В **Настройках просмотра таблицы** можно выбрать лист Excel, кодировку и разделитель. Изменение этих параметров не меняет оригинал. Столбцы можно переставить/скрыть в личном представлении; настройка связана с hash файла и схемой, поэтому чужой порядок не переносится случайно на другой набор.

Чтобы использовать строки в цели, выберите обработку и нужную опубликованную цель. Сопоставление столбцов, даты, единицы и команд задаётся явно. Предпросмотр показывает принятые, отклонённые и неизвестные строки, а также происхождение. Применение выбранных корректных строк создаёт факты через существующий импортный процесс. Просмотр, пробный расчёт и сохранение исходника фактов не создают.

Если команда не сопоставлена, исправьте справочник или явное соответствие. Похожее название не является достаточным доказательством. Повтор сохранения той же команды восстанавливает её квитанцию; отдельное получение файла сохраняет новый факт получения, даже если байты совпали.

## 9. База знаний

В **Базе знаний** находятся команды, кластеры, трайбы, блок, метрики, отображаемые руководители и связи. Таблица и дерево используют стабильные IDs и внешние коды. Карточка показывает происхождение и историю; переименование не должно разрушать старые расчёты.

Редактор может открыть форму или импорт CSV/XLSX, посмотреть предпросмотр и diff, затем применить изменения в собственный черновик. Неоднозначные совпадения и дубликаты остаются явными. Архивирование сохраняет ранее использовавшийся объект для истории. Читателю не предлагаются действия редактирования чужого пакета.

Для исходных материалов зрелости используйте подготовку из материалов. Повторная подготовка не дублирует справочник и не стирает уже отредактированные подписи/псевдонимы. Имена руководителей из презентации — бизнес-справочник, а не автоматически созданные учётные записи.

Если нужен полный набор определений цели зрелости, явно выберите ответственного бизнес-участника при подготовке. Это создаёт обычный пакет определений, источника, сопоставления и назначений команд. Факты, применимость исключений и аттестации не появляются из такого выбора автоматически. Общие правки проходят штатную проверку пакета и публикационный процесс.

## 10. Цели, статусы и подтверждения

Конструктор цели начинает с понятной заготовки, затем позволяет настроить методику, метрики, участников, пороги, период и источник. Изменение порога сначала показывается в пробном расчёте. Например, повышение90→95 должно изменить предварительный результат и объяснение, сохраняя опубликованную версию до явного принятия изменений.

Расчётный статус, качество данных и подтверждение УОР отображаются отдельно. Нет данных не равно нулю, неприменимо не равно успешно, выполненная работа не подтверждает цель. Ожидаемый состав команд и метрик задаётся заранее; исчезнувшая строка ухудшает полноту, а не уменьшает знаменатель ради красивого процента.

Принятая корректировка участвует в каноническом расчёте. Отчёт показывает эффективное значение, исходное значение и причину, когда это нужно для объяснения. Исторический снимок сохраняет точные версии методики, состава, фактов и корректировок.

После изменения фактов/правил прежнее подтверждение может стать неактуальным. Проверяйте fingerprint и основание подтверждения. При конфликте двух окон сначала сравните основу, текущую версию и свой ввод, затем явно разрешите конфликт. Не отправляйте прежнюю форму заново с новой версией, не понимая различий.

## 11. Дашборды и конструктор экрана

Откройте **Обзор → Мои дашборды**. Начните с управленческого или качественного пресета, выберите область/период и настройте блоки. Поддержанные блоки включают сводку, сравнение, таблицу, тренд, матрицу команда×метрика, работы и проблемы данных. Подписи, порядок и видимость настраиваются через формы; изменение порядка доступно с клавиатуры.

Матрица строится по ожидаемым участникам и метрикам. Отсутствующая ячейка остаётся видимой. Переход из результата открывает основание, а не неподтверждённую текстовую подсказку. Фильтры должны иметь понятную область действия; перед сравнением проверяйте, что сопоставляете одинаковые показатели и периоды.

Личный дашборд не меняет общую методику. Общий пакет может передать готовую заготовку блока, которую получатель затем редактирует под свой рабочий вопрос. Не требуется писать JSON для обычной настройки.

Для устойчивого управленческого документа создайте отчёт. Текущий дашборд может измениться после новых данных; сохранённый отчёт намеренно остаётся на своей зафиксированной основе. Это позволяет объяснить, что именно видел руководитель на момент подготовки.

## 12. Модель зрелости: чтение реальных материалов

Выбранный источник от30 октября содержит724 строки после заголовка:290 листовых позиций команда–метрика и434 исходных агрегата. Состав —58 команд×5 метрик. Из290 позиций273 числовые,271 достигает порога,2 не достигают; ещё15 помечены исключениями,1«Нет PR»,1«Нет данных». Пороги пяти метрик:70/80/80/95/70.

Исходная презентация сообщает271/273 и56/58 команд. Приложение сохраняет это как **утверждение источника**. Консервативный расчёт по полному ожидаемому составу не превращает15 исключений в согласованную неприменимость. N311 остаётся отсутствующими данными, N308 — отсутствием события. В карточке доступны ссылки на исходные строки/слайды.

Презентация за25 октября сообщает54/58 и270/274; исходного Excel этого периода нет. Из этих агрегатов не восстанавливается вымышленная история отдельных команд. Тренд не строится по несопоставимым знаменателям как будто это одинаковая выборка.

Специализированный экспорт зрелости использует общий замороженный снимок и реальные имена/команды. Оригинальная презентация сохранена как источник. Поддержка этого пресета не означает универсальную реконструкцию произвольных PowerPoint-шаблонов, макросов, внешних ссылок или Excel-формул.

## 13. Отчёты и выгрузки

В **Отчётах** выберите тип: управленческий отчёт по целям или специализированная зрелость. Настройте заголовок, период/область, разделы, порядок и комментарий; проверьте предварительный результат. Сохранение создаёт новую версию с неизменяемым снимком значений, единиц, имён, оснований и версии шаблона.

Экран сохранённого отчёта и XLSX/PPTX/PDF используют одну основу. После изменения справочника или порога старый отчёт не пересчитывается незаметно. Для нового состояния создайте новую редакцию. При конфликте версий интерфейс сохраняет ввод и предлагает сравнить разделы/поля с последней редакцией.

XLSX содержит таблицы и источник чисел. PPTX использует поддержанные редактируемые объекты, а не скриншот всей страницы. PDF создаётся через отдельный проверенный браузерный процесс без личного сеанса и сетевой загрузки. Если установленный PDF-браузер недоступен, приложение сообщает ошибку; HTML не выдаётся за готовый PDF.

На целевом ПК откройте результаты в разрешённом Office/просмотрщике: проверьте перенос строк, шрифты, числа, единицы, таблицы и печать. Рендер в тестовой Linux-среде подтверждает содержимое и базовую вёрстку, но не подменяет такую проверку.

## 14. Недельная сводка и ГигаЧат

Откройте **Отчёты → Недельная сводка**. Выберите область, неделю и категории доказательств. Сначала формируется детерминированный набор: подтверждённые данные, качество, работы, решения, относящиеся комментарии и ссылки на основания. Сравнение с предыдущим периодом разрешено только при сопоставимых бизнес-окнах, единицах и смысле показателя.

Предпросмотр показывает, что будет передано. Проверьте состав, затем явно разрешите отправку конкретной версии в настроенный корпоративный ГигаЧат. Согласие привязано к отчёту, revision, hash доказательств и текущему адресу/привязке чата. Новый набор или изменённый адрес требует нового просмотра и согласия.

В настройках браузерного подключения задаются фактический разрешённый URL, origins и проверенные элементы страницы: редактор, отправка, ответ и признак завершения. Вход выполняется вручную в отдельном личном окне СберБраузера. Приложение не угадывает банковский адрес и не переносит браузерную сессию в общий пакет.

Шаблоны промптов разделяют анализ, проверку оснований и редактуру. Результат AI — черновик: проверьте «Топ-3 инсайта», достижения, зоны внимания и план следующей недели, исправьте текст и сохраните проверенную версию. AI-текст не создаёт факт или аттестацию. При потере ответа используйте проверку прежней операции, а не повторную отправку.

## 15. Действия следующей недели

Из проверенной сводки осознанно создайте действие: ожидаемый результат, ответственный, срок и связь с основанием. Приложение хранит собственный статус действия; при необходимости можно явно создать связанную работу в обычном рабочем пакете.

На следующей неделе отметьте выполнение или перенесите незавершённое действие. Повтор команды не должен создавать второй экземпляр. Перенос сохраняет связь с исходной неделей, а не скрывает, что обещание осталось невыполненным.

Текст сводки, список действий и бизнес-цели — связанные, но разные объекты. Завершение действия не повышает автоматически расчётный статус цели. Создание работы не публикует её и не подтверждает результат за человека.

Сохраняйте проверенный текст перед выходом. Редактирование действия не должно стирать ещё не сохранённую редактуру сводки; при переходе к другому отчёту интерфейс запрашивает решение о несохранённом вводе. Если сохранение получило неопределённый ответ, сначала сверяйте ту же операцию.

## 16. Общая настройка для коллег

Откройте **Обновления → Общий пакет рабочего места**. Выберите материалы, справочники, заготовки дашбордов, отчётов, недельных промптов и, при необходимости, конкретные принятые общие объекты. Экспорт автоматически включает проверенную зависимость выбранных объектов. Неизвестные или личные артефакты не превращаются в общие.

Получатель открывает JSON-пакет, нажимает **Проверить и сравнить** и изучает изменения. На непустом месте перед изменением создаётся независимая защитная копия; после успеха доступна её ссылка. Повтор установки того же пакета не размножает объекты и не создаёт ещё одну копию без изменения.

Локально изменённый пресет сохраняется при входящем конфликте. Общие записи с несовместимой неизменяемой версией блокируют применение целиком. Старые версии и личные черновики не удаляются ради импорта. Поддержанный JSON-пакет ограничен900000 байтами; слишком большой набор нужно разделить на согласованные части.

Готовый пакет выпуска содержит 6 общих записей настройки и 4 файла разрешённых материалов: справочник и определение зрелости, недельный промпт, шаблон дашборда и два рецепта отчёта. Нормализованный JSON передаётся как типизированная запись справочника. В пакете нет cookies, сертификатов, приватных путей, учётных записей или выдуманных принятых фактов. Каждый получатель отдельно выполняет свой вход и локальную привязку источников.

## 17. Обновления и уведомления

Центр обновлений различает **код приложения**, **общие принятые данные** и **общий пакет настройки**. Обновление одной части не является автоматическим разрешением менять остальные.

Проверка кода использует точный доверенный origin и принятый main. Уведомление связано с конкретной версией и владельцем; прочтение, отложенное напоминание и применённый результат сохраняются. Отсутствие сети показывает последнее известное состояние и время проверки, а не выдумывает актуальность. Повторы используют ограниченную задержку с разбросом; параметры задаются сопровождающим.

Проверка работает, пока запущен локальный процесс приложения, и возобновляется после запуска. Публикация в Git не устанавливает версию одновременно на выключенные компьютеры: каждый экземпляр обнаруживает её при своей проверке и проходит собственное безопасное обновление.

Перед применением сохраните работу и завершите активные браузерные операции. Приложение проверяет точный commit, чистоту отслеживаемых файлов, возможности launcher и совместимость. Действующий захват или открытое управляемое окно не закрывается принудительно ради обновления. Перемещение main во время подготовки требует новой проверки.

Обновление делает защитную копию, согласует остановку, проверяет здоровье новой версии и фиксирует результат. При сбое действует журнал восстановления; после точки принятия нельзя откатывать новые пользовательские данные как будто операции не было. В локальном preview применение внешнего main закрыто. Сопровождающий должен проверить реальный корпоративный Git/допуск отдельно.

## 18. Личная копия, перенос и восстановление

Используйте **Обслуживание рабочего места** для полной личной копии. Выберите включение оригиналов, если нужно перенести сохранённые файлы. В копию входят поддержанные данные модулей, скрытые и видимые исходники, отчёты, недельные версии, настройки и необходимые квитанции. Состав проверяется по inventory/hash; неизвестная схема не игнорируется.

Для переноса подготовьте чистую установку, подтвердите того же владельца штатным допуском и откройте копию для предварительной проверки. Другой installationId допустим; другая личность — нет. Сама копия не переносит право доступа, браузерный сеанс или сертификаты. Если оригиналы исключены при экспорте, интерфейс сообщает их отсутствие; фиктивная ссылка на файл не создаётся.

На непустом месте сначала формируется rescue. Восстановление проходит через staging и проверку владельцев модулей, затем атомарное переключение. Ошибка не должна создавать пустую замену старой базе. Не подменяйте активный pointer и не удаляйте DB/WAL/SHM вручную. Для переноса используйте созданную приложением проверенную копию: фоновая синхронизация отдельных файлов работающей базы может смешать базу и журнал от разных состояний.

Периодически проверяйте не только создание ZIP, но и восстановление собственной копии на отдельном подготовленном месте с повторным скачиванием нескольких оригиналов и открытием старого отчёта. Удалять основную установку после получения непроверенного ZIP нельзя.

## 19. Если что-то пошло не так

| Ситуация | Что сделать |
| --- | --- |
| Не открывается интерфейс | Проверьте окно запуска, разрешённую папку и занятые порты; передайте сопровождающему точный текст ошибки. Не запускайте много копий процесса. |
| Не найден СберБраузер | Настройки → Рабочее место → проверка установленного браузера; ИТ задаёт фактический путь и проверяет152. |
| Требуется вход | Продолжите ручной вход в собственном управляемом окне; не копируйте cookies и чужой профиль. |
| Файл есть, таблица не читается | Скачайте оригинал, проверьте формат/лист/кодировку/разделитель и пределы. Сохранённые байты не зависят от успеха просмотра. |
| Статус операции неизвестен | Нажмите проверку состояния. Повтор допустим только явно для прежней команды после `not_found`; новая команда не заменяет reconciliation. |
| Изменения конфликтуют | Сравните основу, последнюю версию и свой ввод; подтвердите выбор полей. |
| Обновление недоступно | Проверьте роль/допуск, origin/main, Git/launcher, активные задачи и локальные изменения; не используйте force/reset. |
| Отказ владельца при restore | Нужна та же подтверждённая личность. Имя в архиве и режим «Редактор» этого не доказывают. |

В **Настройках** можно скачать диагностический JSON. Он содержит разрешённые сведения о среде и, по желанию, статус собственной команды по ID; не включает её payload/result, содержимое таблиц, пароли или browser cookies. Доступ к чужой команде отклоняется. Локальные журналы ограничены20 МБ на файл и последними20 файлами; `npm run logs -- --follow` предназначен сопровождающему. Диагностику никто автоматически не отправляет наружу.

## 20. Целевая приёмка и дальнейшее сопровождение

Локальная проверка выполнялась на Linux x64 с Node 22.16.0/npm 10.9.2, настоящими HTTP/SQLite/Git и отдельным синтетическим браузером. Точный SHA и команды приведены в акте выпуска. Она не подтверждает вход в банк, работу smartcard/ГОСТ/CA/proxy, установленный СберБраузер 152.0.7977.120, корпоративный ГигаЧат или отображение в банковском Office.

На целевом месте выполните четыре маршрута: установка→сохранение/повтор ОКО; исходник→справочник→цель→экспорт; недельные основания→ГигаЧат→проверка→действия; пакет коллеги→уведомление→обновление→открытие прежней работы. Для каждого запишите фактические версии, дату, входной hash, результат, обнаруженные ограничения и ответственное решение.

Проверьте закрытие окна во время экспорта, истёкший вход, потерю сети, неопределённый ответ, изменение main, занятое окно, повторный импорт пакета и восстановление копии. Не используйте реальную конфиденциальную информацию как диагностический публичный пример.

Следующий продуктовый шаг — наблюдение за реальными пользователями: сколько времени занимает первый полезный результат, где требуется помощь, понятны ли причины статуса, готовы ли руководители использовать выгрузку без ручной переделки. Коммерческую ценность подтверждают эти результаты и обратная связь; выручка не выводится из внешнего вида интерфейса.
