# Работа редактора в рабочем месте УОР 0.5.0

Это руководство описывает текущий локальный интерфейс. В нём пять основных экранов: «Обзор», «Цели», «Работы и решения», «Данные», «Панель УОР». Сохранённый личный черновик, проверенный файл, отправленный коммит, открытый PR и принятые общие данные — разные результаты работы.

## С чего начать

Откройте приложение, запущенное обычной командой `npm run dev`, по адресу, который сообщил запуск. Личный инструмент находится в «Данные» → «Личные выгрузки ОКО»; он доступен и без общего каталога. Старая закладка `oko.html` в объединённом приложении переводит в этот же раздел. Отдельный `dev:oko` предназначен для изолированной проверки прежнего размещения до управляемого указателя; на управляемом рабочем месте этот запуск отклоняется.

Если вверху есть «Режим работы» и пояснение «Временные локальные роли», для подготовки выберите «Редактор». Это разрешённое временное переключение локального предпросмотра между «Читатель» и «Редактор»; оно сохраняет того же владельца личных данных. Оно не создаёт запись в банковском реестре и не выдаёт права Git или Bitbucket. При неизвестном результате используйте «Повторить смену режима» для сохранённой операции.

В рабочем подключении допуск определяется принятой политикой по имени компьютера. Доступные действия проверяет сервер; само название роли не разрешает отправку. При отсутствии связи собственные черновики могут оставаться доступны, а внешней отправке нужна свежая проверка допуска. Архив рабочего места не переносит допуск на другой компьютер.

Если каталог пуст, не создавайте вымышленные ДИТ, продукты или сотрудников ради открытия экранов. Используйте личную выгрузку, восстановите свою копию или получите проверенный main при настроенном доверенном подключении. Перенос описан в [руководстве по восстановлению](workbench-recovery.md).

## Личная выгрузка ОКО: получить файл с именами из справочника

Личный сценарий сохраняет настройки и результат на этом рабочем месте. Он не создаёт факт цели, подтверждение УОР или публикацию.

1. В «Данные» → «Личные выгрузки ОКО» нажмите «Создать первый сценарий». Для следующего отчёта используйте «Новый сценарий» рядом с «Мои отчёты», заполните «Название отчёта» и нажмите «Создать сценарий».
2. В разделе «Браузер и ручной вход» укажите известный вам «Адрес отчёта». В «Настроить личный профиль браузера» выберите «Установленный браузер», задайте «Имя личного профиля» и, если необходимо, точные «Дополнительные сайты входа». Для СберБраузера требуется путь к установленной программе. Нажмите «Сохранить личный профиль». Адреса отчёта и сайтов входа предоставляет ваша среда; приложение их не угадывает.
3. Нажмите «Открыть браузер для входа». Войдите обычным способом в открывшемся окне, затем вернитесь и нажмите «Завершить ручной вход». Пароли и коды вводятся на странице входа; запись действий в этот момент выключена.
4. Нажмите «Выбрать элемент отчёта в браузере» и выберите однозначный заголовок или другой признак уже открытого отчёта. Для замены есть «Выбрать другой элемент отчёта».
5. В «Запись действий» раскройте «Как читать файл CSV / XLSX». Явно выберите разделитель и кодировку CSV либо лист XLSX; проверьте формат дат, десятичный знак и разделитель тысяч. Затем нажмите «Начать запись действий». В браузере примените фильтры и скачайте CSV или XLSX. Полностью полученный файл завершает запись; на экране появляются шаги и «Образец скачанного отчёта». При необходимости нажмите «Получить записанные шаги».
6. В «Сопоставление столбцов» отметьте «Уникальный ключ строки», выберите «Ключ продукта для справочника», дату, единицу измерения и числовые значения. Если записаны параметры, явно заполните «Подтвердите безопасные значения фильтров»: их значения не копируются из браузера. Нажмите «Сохранить сопоставление и фильтры».
7. В «Обогащение из справочника» выберите «Файл справочника». Настройте «Формат файла справочника», затем нажмите «Прочитать столбцы справочника». Сопоставьте ключ продукта в ОКО, UUID и названия продукта, кластера, ДИТ, UUID и имена руководителей кластера и продукта. Поля команды необязательны. Нажмите «Применить справочник к предпросмотру».
8. Нажмите «Проверить сценарий и получить данные». Приложение повторит действия и скачает новый файл. В «Последний результат» проверьте число строк, строки, требующие сопоставления, дату источника, замечания и таблицу. Затем используйте «Скачать исходный файл» или «Скачать обогащённый CSV».

Названия и руководители могут отсутствовать в исходном отчёте: они добавляются из явно сопоставленного справочника. UUID должны находиться в справочнике; название не заменяет идентификатор. Ключ продукта сопоставляется точно в контексте источника. Похожее написание, пробелы или регистр не разрешают угадать продукт. Неизвестный ключ остаётся проблемой, например `UNMAPPED_PRODUCT`.

При ошибке исправьте выбор столбцов или сам файл справочника, снова загрузите его, нажмите «Прочитать столбцы справочника», проверьте сопоставление, примените справочник и повторите проверку сценария. Таблица предпросмотра доступна для чтения; редактирования её ячеек и выбора похожего имени в ней нет. Если в справочнике отсутствует обязательный руководитель или UUID, устраните это в файле, а не подставляйте человека по догадке.

Исходный файл сохраняется без добавления имён и без изменения его байтов. Обогащённый CSV — отдельный результат: сохраняет исходные столбцы, добавляет поля справочника и обезвреживает значения, которые табличная программа могла бы выполнить как формулу. При совпадении имён добавляемых и исходных столбцов производное имя получает префикс `derived.`. Проверяйте фактические заголовки файла.

Ошибка или отмена повторного получения сохраняет предыдущий успешный результат. Экран показывает только «Последний результат»; полного списка старых результатов и версий настроек в интерфейсе нет. Ранее сохранённые ссылки на файлы результата остаются связаны с прежними файлами. Сохраняйте нужные выгрузки самостоятельно и включайте исходники в полную резервную копию.

Если собственное окно автоматизации потеряно или профиль занят, раскройте «Окно осталось открытым или профиль занят» и используйте «Закрыть окна браузера и освободить профиль». Не копируйте работающий профиль обычного браузера. При ошибке слишком длинного пути Windows сначала выберите короткую разрешённую папку рабочего места и короткое имя профиля, затем повторите настройку. Путь профиля длиной 260 символов и более отклоняется до запуска; прежняя настройка остаётся сохранённой.

## Создать или продолжить цель

При наличии общего каталога откройте «Панель УОР» → «Создать цель». Для существующей цели используйте «Цели» → «Открыть цель: …» → «Настроить цель». Если незавершённая цель уже в пакете, нажмите «Продолжить настройку: …».

Настройка состоит из пяти шагов:

| Шаг | Что проверить |
| --- | --- |
| «Название и источник» | Название, способ оценки, режим «На дату» или «За период», штатный источник, основной куратор из справочника. |
| «Область и состав» | Реальная область назначения, официальный срок, явно заданный ожидаемый состав для числовой цели. |
| «Шаблон или своя методика» | Опубликованный шаблон или самостоятельная методика. |
| «Показатели и условия» | Значения условий, веса, обязательность, допустимая давность и применимость. |
| «Пример и влияние» | «Рассчитать пример», «Настроить источник», «Проверить готовность» и замечания к пакету. |

Используйте «Сохранить черновик», «Далее» и «Назад». Сохранение допускает незавершённую настройку; сообщение «Черновик сохранён» не означает готовность к публикации. Незаполненные объекты в пакете отмечены «Требует заполнения». При конфликте редакций откройте актуальный собственный черновик и продолжите с него.

«Рассчитать пример» показывает расчёт по сохранённым входам и основанию. Он не создаёт нового измерения и не подтверждает выполнение. «Проверить готовность» проверяет сохранённый пакет, но также не создаёт подтверждение. Положительное условие и подтверждение УОР остаются отдельными состояниями; для подтверждения нужны отдельное действие и точное актуальное основание. Это руководство не предлагает отсутствующую универсальную кнопку подтверждения.

Для ручной цели в «Ручной результат» выбираются «Не начато», «В работе», «Завершено». Завершение требует «Описание результата», возврат — «Причина возврата». Доступное действие называется «Сохранить ручной результат». Сохранённый переход ещё должен пройти обычный путь общего пакета.

## Принять данные цели

В «Данные» выберите «Данные целей» и нужную цель. Для штатного источника «Файл» выберите «Файл данных» и нажмите «Проверить файл». В «Предпросмотр импорта» проверьте даты, значения и проблемы. Можно нажать «Выбрать корректные строки» или отметить допустимые строки отдельно. Изменения прежних фактов выбираются отдельно в «Изменения прежних фактов». Затем нажмите «Принять выбранные строки».

Например, если из четырёх строк корректны три, можно явно принять эти три; четвёртая останется в «Непринятые строки» с причиной. Набор остаётся неполным. Исправьте непринятую строку во внешнем файле и загрузите исправленный файл: уже принятые факты сохраняются. Повтор той же операции принятия не создаёт вторую копию набора; отдельная новая загрузка является новой попыткой получения. Принятые ручные корректировки не отменяются очередным импортом молча.

В «Принятые наборы» сравните «Исходные строки» и «Обогащённые строки», включите «Только строки с проблемами» и откройте «Происхождение» у обогащённого факта. Исходные строки сохраняются отдельно от нормализации, обогащения и расчёта. В этом экране частичного импорта нет ссылки на скачивание итогового файла; чтение строк не следует путать со скачиванием личного результата ОКО.

Для источника «ОКО» используется «Получить данные ОКО» и доступные действия текущего задания. Сбой сохраняет последний успешный набор. Настройка источника и личная выгрузка ОКО — разные пути: личный предпросмотр не становится общим фактом автоматически.

## Накопить пакет и проверить публикацию

Работы и запросы решений создаются на экране «Работы и решения» кнопками «Создать работу» и «Создать запрос решения». Они описывают исполнение; выполненная работа, ответ или комментарий сами по себе не подтверждают цель. Изменения накапливаются в собственном пакете, а не создают PR при каждом сохранении.

1. На «Панель УОР» выберите «Собственные пакеты». «Зона просмотра» фильтрует только список: проверяется и отправляется весь пакет.
2. Проверьте состав, незавершённые объекты и нажмите «Проверить пакет». Изучите «Предварительный просмотр», изменения и конфликты. Просмотр относится к точной редакции и основанию main и имеет срок действия. После изменения пакета или устаревания проверьте его заново.
3. «Отправить пакет в Bitbucket» доступно только при действующем разрешении и пригодном предпросмотре. Во временном локальном режиме внешняя отправка и применение публикации запрещены. В поставляемой конфигурации рабочее подключение Bitbucket по умолчанию недоступно: без проверенного провайдера публикация не объявляется выполненной.
4. При настроенном проверенном подключении следите за «Ход публикации». Сохранённый локальный коммит, подтверждённая отправка коммитов и созданный PR показаны отдельно. При запросе входа используйте предложенное штатное внешнее окно. Git и Bitbucket могут потребовать независимого входа. Возврат из окна сам по себе не означает успешный PR.
5. Для сверки используйте «Обновить состояние пакета» и, когда доступно, «Проверить состояние PR». При неизвестном результате есть «Проверить результат запроса» с тем же идентификатором операции. «Повторить операцию» и «Отменить операцию» применяйте только к показанному заданию. После отмены, отказа или отзыва допуска сохранённый коммит не доказывает разрешение продолжать передачу.
6. Откройте «Открыть PR в Bitbucket». Окончательное принятие выполняется во внешнем Bitbucket; кнопки merge в приложении нет. Полученные замечания отображаются в «Замечания к PR».

После внешнего принятия обновление общих данных выполняется через «Обслуживание рабочего места» → «Проверить обновление main» → «Применить проверенный main», если это разрешено текущим допуском и подключением. Локальное время применения не является датой принятия PR. Если Bitbucket не подтвердил дату, приложение честно показывает «Дата принятия в Bitbucket неизвестна». Новое применение не переписывает прежнее согласованное основание.

После восстановления пакета может появиться сообщение «В копии сохранена подготовка отправки…». Это сохранённая подготовка, требующая новой проверки пакета и сверки с сервером, а не подтверждение уже выполненной отправки.

## Граница локальной проверки

Локально проверены пути с Node.js 22.16.0, npm 10.9.2 и установленным Chrome; Chrome и Edge обозначены в настройке как браузеры для локальной проверки. Сквозная проверка внешнего PR использовала синтетические провайдеры Git, Bitbucket и входа; реальное банковское подключение не настроено. Это не подтверждает банковские SSO, smartcard, ГОСТ, прокси, СберБраузер и целевую ОС. Реальные банковские проверки T41/T48 и BP-01–BP-06 остаются `BLOCKED_BANK_INPUT`. Рабочие адреса, доступы и профили подключений здесь не заданы.

Для чтения состояния используйте [руководство читателя](workbench-reader.md); для копий, ошибок обслуживания и обновления программы — [руководство по восстановлению](workbench-recovery.md).
