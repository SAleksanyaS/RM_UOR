# Обновление кода из приложения

Штатный запуск — `npm run dev` из разрешённой рабочей папки. Launcher ведёт приватный маркер `.runtime/code-update/launcher.json` (PID, heartbeat, случайный токен текущего запуска). Маркер не является общим каталогом и не публикуется. Другой launcher в той же папке не стартует при живом маркере.

В разделе обслуживания любой вошедший пользователь (включая читателя) сначала получает текущую и опубликованную версии через GET `/api/system/code-update`. Адрес origin должен точно совпасть с repositoryUrl в приватном config/site.local.json; ветка кода — publishedBranch (обычно main). Отслеживаемые файлы должны быть без локальных изменений. Конфликтующая/разошедшаяся ветка требует ручного согласования: обновление не выполняет reset, checkout с потерей работы, force или push.

Для обновления своей программы нужны только права чтения опубликованного Git. Обновление не отправляет изменения в репозиторий и не даёт прав публикации. POST `/api/system/code-update` принимает ровно expectedCommit и targetCommit из проверки. Сервер повторно получает выбранную ветку и сравнивает обе ревизии, проверяет отсутствие других операций, устанавливает maintenance и записывает приватную заявку с токеном launcher. Конфигурация/секреты, cookies и корпоративные факты в заявку не входят. Повторная заявка/изменившаяся версия отклоняется.

Launcher забирает свою заявку, посылает серверу IPC `uor.shutdown` и дожидается штатного app.close/закрытия SQLite/браузеров. Клиентский Node/Vite также останавливается. Только после завершения дочерних процессов повторяются проверки origin, tracked dirty, текущего commit и точного fetched target. Затем выполняется Git merge --ff-only точного SHA, npm ci по package-lock.json и новый запуск API/клиента. Сам родительский терминал остаётся открыт; служебные окна скрыты. Команды запускаются с массивами аргументов, без конструирования shell-строк; Git credentialHelper берётся из приватной конфигурации.

npm CLI берётся из npm_execpath штатного `npm run dev`; для особого способа запуска можно задать абсолютный npmCliPath в site.local.json. npm ci использует настроенные .npmrc/окружение и корпоративный registry. Проверяется strict-ssl=true; registry должен использовать HTTPS (HTTP только localhost для стенда). Корпоративный CA/proxy настраиваются штатно, проверка TLS не отключается. npm-скрипты и зависимости должны происходить из доверенного согласованного репозитория/registry.

`.runtime` сохраняется при обновлении. Последняя фаза/причина записана в `.runtime/code-update/status.json` и доступна GET после загрузки. Нет сообщения об успехе до реального старта нового API и клиента. При ошибке до замены кода launcher запускает прежние службы и показывает причину. Если код уже получен, а npm ci/новый старт не удался, код не откатывается разрушительными командами: причина остаётся в приватном status и консоли; исправьте registry/доступ/зависимости и снова выполните npm ci, npm run dev. Запущенные из другой папки или не этим launcher чужие процессы не завершаются.

Адресные проверки используют только созданные тестом временные локальные Git-репозитории: успешный ff и порядок установки, сохранность .runtime, отказ dirty/origin mismatch, CAS смены локальной/удалённой ревизии, отказ divergent history и приватная заявка с привязкой к launcher. Обновление реального рабочего checkout и npm ci во время тестов не выполнялись.
