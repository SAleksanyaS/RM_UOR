Меню, страницы и сервер используют общую политику. Скрытые операции недоступны прямым HTTP-вызовом. Читатель получает происхождение/актуальность фактов без сценария, профиля доступа и сопоставления импорта; видит свои операции и общий опубликованный журнал. При выходе закрываются редакторы, прежний ответ сервера не возвращает права.

## Войти

Нажмите профиль → «Войти как куратор», выберите имя и введите индивидуальный пароль. Обычный пользователь продолжает просмотр без кураторского входа. Код/пароль локальной роли не выдаёт прав на Git или корпоративный дашборд; они определяются доступом пользователя к этим системам.

## Локальный реестр

Учётные записи находятся в `.runtime/local-config/curators.json`. Реестр содержит стабильныйID, имя, случайную соль и scrypt-хеш. Пароли не хранятся в открытом виде, не возвращаются через API, не включаются в публичный Git/клиентские исходники.

На этой станции добавлены шесть запрошенных персональных профилей и сохранён прежний. На другой станции они не возникают от одного `git pull`: примените тот же защищённый локальный реестр (с теми жеID) средствами сопровождения либо настройте банковскую идентификацию. Не отправляйте реестр в публичный RM_UOR. Копирование файла с хешами не заменяет правила защиты файла и учётных записей банка.

Для отдельного куратора есть `npm run setup:curators`: ввод скрыт. Пакетное сопровождение — `npm run setup:curators:batch`; команда читает JSON-массив объектов `{name,code}` только через стандартный ввод и выводит лишь публичныеID/имена. Пароли не передаются аргументами командной строки и не сохраняются командой. Используйте утверждённый способ подачи секретов, не версионируемый файл с паролями. Повторное применение имени сохраняетID; некорректные/повторные данные не заменяют прежний реестр. После изменения реестра перезапустите службу.

## Перенос в банк

Локальная модель разделяет работу внутри приложения; это не корпоративный IdM/SSO. Внутренний агент должен связать проверенную корпоративную личность с role/curatorId, настроить защищённое provision/revoke и Git-права/защиту веток. Интерфейсы общей политики и сессии отделены от способа проверки пароля, расчёты от идентификации не зависят.
