# Версии среды и обновление приложения

Целевая связка выпуска 0.4.1:

| Компонент | Версия | Для чего нужен |
| --- | --- | --- |
| Node.js | **22.16.0** | Локальная служба, SQLite, сборка и запуск интерфейса |
| npm | **10.9.2** | Установка зафиксированных зависимостей и команды запуска |
| Python | **3.13.5 допустим** | Приложение его не вызывает; менять установленный Python не нужно |
| Git | Установленная корпоративная версия | Получение программы и выпуск общих данных |

Проверить первые две версии: `node --version` и `npm --version`. Для выбора Node в менеджерах версий предусмотрены `.nvmrc` и `.node-version`. Проверенная базовая версия npm указана в `packageManager`; рабочие зависимости фиксируются в `package-lock.json`.

## Если приложение уже установлено

1. Остановите его командой **Ctrl+C** в окне запуска.
2. В разрешённой папке проекта выполните:

```text
git pull
npm ci
npm run dev
```

`npm ci` пересоздаёт папку зависимостей `node_modules`. Рабочая база, настройки и учётные записи в `.runtime` сохраняются. Для существующего рабочего места повторно выполнять `setup:workspace` не требуется.

Если `git pull` сообщает о локальных изменениях, сохраните и согласуйте их обычным порядком. Не используйте `git reset --hard` для обхода ошибки.

## Новая установка

```text
npm ci
npm run setup:workspace -- --mode empty
npm run dev
```

После запуска браузер откроет приложение. Python и установка pip-пакетов для этого не нужны. Прежний порядок настройки источников, кураторов и корпоративных доступов описан в [руководстве пользователя](../USER_GUIDE.md).

## Ограничения для разработчика

Node.js 22.16.0 и npm 10.9.2 должны проходить `npm ci --engine-strict`, `npm test` и `npm run build`. Проверка `tests/runtime-compatibility.test.ts` контролирует требования **всех** записей lock-файла, включая необязательные платформенные пакеты Linux и macOS, которые могут не устанавливаться на Windows.

Типы Node закреплены на 22.16.0. Rollup закреплён через `overrides` на 4.62.2: проверенные версии 4.63.0, 4.64.0 и 4.65.0 подтягивали Linux-пакет `@napi-rs/lzma-linux-x64-gnu@1.5.1` с требованием Node.js 22.20+. Убирать ограничение или обновлять lock-файл следует только после повторной проверки целевой связки и всех платформенных требований.

В Node.js 22.16.0 `node:sqlite` выводит предупреждение `ExperimentalWarning`. Само по себе оно не означает ошибку запуска. База, резервирование и восстановление проверяются тестами на этой версии. Результат проверки Windows не заменяет приёмку реального СберОС/macOS, браузера, корпоративного registry и сертификатов.
