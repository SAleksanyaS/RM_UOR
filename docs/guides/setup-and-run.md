# Подготовка среды и запуск

Инструкция относится к версии0.2.0. Приложение запускается из консоли в разрешённой папке и открывает веб-интерфейс; отдельная иконка и установка в системные каталоги не нужны.

## 1. Среда

Нужны Node.js 22.20+ совместимой ветки 22.x либо Node.js 24+, npm, Git и браузер. Устанавливайте их через корпоративный каталог ПО. Python не требуется. Для браузерного сбора нужен установленный совместимый Chromium/Сбербраузер/Edge, указанный в личном профиле. Необходимость сертификата определяется вашим источником. Настройка описана в docs/BANK_CONNECTORS_RUNBOOK.md.

Испытанный локальный контур — Windows, Node.js 24.19. Пути и запуск процессов рассчитаны на macOS и СберОС, но проверки на этих ОС пока не проведены.

```text
node --version
npm --version
git --version
```

## 2. Получить проект

Выберите разрешённую папку. Примеры ниже замените утверждёнными путями и, внутри банка, корпоративным Git URL.

Windows PowerShell:

```powershell
Set-Location -LiteralPath 'C:\ApprovedApps'
git clone https://github.com/SAleksanyaS/RM_UOR.git
Set-Location -LiteralPath 'C:\ApprovedApps\RM_UOR'
```

macOS / СберОС:

```sh
cd /approved/apps
git clone https://github.com/SAleksanyaS/RM_UOR.git
cd /approved/apps/RM_UOR
```

## 3. Настроить разрешённый корень и репозиторий

Скопируйте `config/site.example.json` в `config/site.local.json`. Локальный файл исключён из Git. Заполните `allowedWorkspaceRoots` существующими абсолютными путями: корнем проекта или утверждённой родительской папкой.

```json
{
  "allowedWorkspaceRoots": ["C:/ApprovedApps/RM_UOR"],
  "repositoryUrl": "https://github.com/SAleksanyaS/RM_UOR.git",
  "publishedBranch": "main",
  "releaseBranch": "release/current",
  "publicationMode": "demo-only",
  "port": 4174,
  "clientPort": 5173,
  "autoOpen": true
}
```

На macOS/СберОС задайте соответствующий путь, например `/approved/apps/RM_UOR`. Пустой список корней блокирует запуск. Без локальной конфигурации демонстрационный запуск разрешает текущий корень проекта и не подключает удалённый репозиторий. Для корпоративного развёртывания явная конфигурация разрешённых папок обязательна; сопровождение задаёт и защищает её.

В публичном RM_UOR оставляйте `publicationMode: "demo-only"`. Режим `internal` предназначен для разрешённого корпоративного репозитория. Git-пароли в конфигурацию не записываются: используется штатная авторизация пользователя.

Штатные порты: 4174 для службы и 5173 для интерфейса. При занятости завершите прежний экземпляр; смену портов согласуйте с сопровождающим, поскольку настройки службы и прокси интерфейса должны совпадать.

## 4. Установить зависимости и профили кураторов

Из корня проекта:

```text
npm ci
```

Команда использует закреплённый `package-lock.json`. Корпоративные registry, CA и прокси настраиваются по инструкции сопровождения без отключения TLS.

Для каждого куратора выполните в интерактивной консоли:

```text
npm run setup:curators
```

Введите имя и индивидуальный код. Ввод кода скрыт; в `.runtime/local-config/curators.json` сохраняются соль и хеш. Не помещайте код в командную строку, исходники и общие документы. Повторный запуск с тем же именем меняет локальный код, сохраняя идентификатор. После настройки перезапустите службу.

Без реестра доступен просмотр. Код включает роль внутри приложения; Git-права выдаются отдельно. При переносе между компьютерами сопровождение должно согласовать устойчивые идентификаторы кураторов: текущий setup-скрипт создаёт локальные профили, централизованного управления ими пока нет.

## 5. Запустить

```text
npm run dev
```

Команда проверяет разрешённую папку, запускает службу и интерфейс, затем открывает `http://127.0.0.1:5173`. Если браузер не открылся, откройте напечатанный адрес самостоятельно. Служба слушает только `127.0.0.1`. Консоль оставьте открытой; остановка — Ctrl+C.

«Не куратор» открывает просмотр. Для редактирования выберите кураторский вход и введите настроенный код. Этапы действий, время и итог доступны в «Обновления и история».

Начните с компактного обзора. Подробности доступны через матрицу, направления и карточки; пошаговый маршрут приведён в [сценарии демонстрации](../demo/first-stage-walkthrough.md). Проверка свежей версии после установки описана отдельно в [журнале доказательств](../verification/first-stage-evidence.md).

## 6. Импортировать карту

Чистая копия содержит вымышленные демонстрационные данные. В режиме куратора откройте «Каталог целей» → «Импорт карты HTML» и выберите файл с JSON-блоком `portal-data`. HTML не исполняется; прежний каталог сохраняется локально как резервная запись.

Альтернатива из консоли:

```text
npm run import:map -- "путь/к/карте.html"
```

Команда сохраняет `.runtime/imports/catalog.json`; затем нужен перезапуск. Существующие снимки и подтверждения не удаляются. Смена карты не создаёт факты для новых целей автоматически. Перед заменой рабочего набора сделайте резервную копию `.runtime` при остановленной службе.

Факты можно внести через «Источники данных» → «Внести факт вручную». Специальный импорт предоставленного Excel подготовлен локально для демонстрации; универсального пользовательского мастера Excel пока нет. Подготовленные `catalog.json` и `snapshots.json` в `.runtime/imports` не отправляются в Git автоматически.

## 7. Обновление и сохранность

Диалог «Обновить» позволяет выбрать общие данные УОР, источники и пересчёт. Обновление содержания не заменяет исходники работающей программы. Для обновления кода остановите приложение, получите опубликованную версию штатным Git; если зависимости изменились, повторите `npm ci`. Затем запустите `npm run dev`.

Локальная SQLite-база `.runtime/app.db` хранит факты, черновики, подтверждения и историю. Перезапуск их сохраняет. Не удаляйте `.runtime` ради исправления ошибки: там могут быть неотправленные изменения. Резервную копию папки делайте при остановленной службе и храните в разрешённом месте.

## 8. Диагностика

- Команда не найдена: проверьте установку Node/npm/Git и откройте консоль заново.
- Запрещена папка: проверьте реальный путь и `allowedWorkspaceRoots`; ссылка не должна выводить за разрешённый корень.
- Репозиторий не настроен: заполните `repositoryUrl`. Локальные данные доступны и без удалённой синхронизации.
- Источник — заглушка: это ожидаемо на первом этапе; браузер не запускался и новые факты не получены.
- Устаревший срез: проверьте период и дату источника. Время запуска не делает старые факты свежими.
- Публикация отклонена: проверьте итог операции, Git-права и режим публикации. Черновик сохраняется локально.

Реальный сертификатный вход и запись браузерных сценариев потребуют отдельного гайда и испытания на каждой ОС.


## Получение данных и обслуживание

В разделе «Получение данных» создайте личный профиль: разрешённые origins, установленный браузер, имена переменных окружения для API, при необходимости пути CA/клиентского сертификата. Значения токенов в приложение/репозиторий не вставляются. Настройте адаптер и формат у источника; для CSV/XLSX предварительно сохраните сопоставление. Выполните обычный ручной вход, затем проверку получения или запись сценария на авторизованной странице.

В «Обслуживании» видны версии, доступность Git/папки и резервные копии. Восстановление возвращает локальную БД с предварительным откатом; внешние исходные файлы и браузерный профиль в SQLite-копию не входят. Храните резервную копию всей .runtime при переносе компьютера. Автоматические копии включаются отдельно и работают пока запущено приложение. Обновление программы кнопкой описано в code-update.md.
