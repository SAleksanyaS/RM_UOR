# Запуск и окружение

Действующая пошаговая инструкция Workbench0.5 — [README](../../README.md), затем [личный сценарий ОКО](../OKO_WORKFLOW.md) и [руководство читателя](workbench-reader.md). Прежние corporate-transfer/USER_GUIDE описывают legacy0.4; их шаги подготовки аккаунтов не заменяют нынешний запуск.

Штатная новая установка Workbench0.5: Node.js22.16.0, npm10.9.2, Git и установленный браузер; новая разрешённая папка; `npm ci`; собственный `config/site.local.json` по [README](../../README.md); `npm run dev`. Для проверки сборки — `npm run build`. Первый запуск local-preview создаёт стабильную личность без legacy реестра аккаунтов и не заполняет каталог демоданными. Повторный запуск сохраняет данные.

`setup:workspace`, legacy аккаунты и старое руководство0.4 сохраняются для прежнего формата. Не запускайте подготовку пустого места поверх живой `.runtime`. Обновление существующей установки выполняется по [руководству восстановления](workbench-recovery.md), отдельно от данных.

Настройки места находятся в config/site.local.json, личные файлы — .runtime. ВнутренниеGit/registry/CA/прокси,Сбербраузер/ССО/сертификаты задаются в банке по [runbook](../BANK_CONNECTORS_RUNBOOK.md). Сбор с источников реализован адаптерами; неподдержанная либо отсутствующая настройка возвращает диагноз и не объявляет успешную выгрузку.
