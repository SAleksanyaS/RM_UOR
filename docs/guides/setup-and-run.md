# Подготовка среды и запуск

**Состояние:** инструкция задаёт целевой запуск будущей реализации. Сейчас в репозитории только проектные документы; package.json и приложение ещё не созданы. Команда `npm run dev` станет доступна после выполнения задачи 1 плана.

## 1. Что нужно заранее

Разрешённая компанией папка, Node.js 22.20+ совместимой ветки 22.x с npm, Git 2.43+ и браузер. Python 3.11+ понадобится при подключении Python-сборщика; для первого этапа с готовыми данными он не обязателен. Рабочий Сбербраузер и сертификат понадобятся для отдельного этапа реального корпоративного сбора.

Устанавливайте компоненты из корпоративного каталога. Внешние официальные источники для тестового окружения: [Node.js](https://nodejs.org/en/download), [Python](https://www.python.org/downloads/), [Git](https://git-scm.com/downloads). Конкретные разрешённые версии и способ установки в банке задаёт сопровождение.

Проверка в консоли:

```text
node --version
npm --version
git --version
```

При необходимости Python:

```text
python --version
```

На части Linux/macOS команда Python называется `python3`; это определяется инструкцией разрешённой среды, а не предположением программы.

## 2. Рабочая папка

Выберите утверждённый путь. Примеры ниже служат только иллюстрацией: использовать их можно, если эти директории разрешены политикой компьютера.

Windows PowerShell:

```powershell
Set-Location -LiteralPath 'C:\ApprovedApps'
git clone https://github.com/SAleksanyaS/RM_UOR.git
Set-Location -LiteralPath 'C:\ApprovedApps\RM_UOR'
```

macOS/СберОС:

```sh
cd /approved/apps
git clone https://github.com/SAleksanyaS/RM_UOR.git
cd /approved/apps/RM_UOR
```

Для корпоративной установки заменить Git URL и путь на утверждённые. Не переносить в приложение личный путь автора примера.

## 3. Подготовка приложения после реализации

1. Создать локальную конфигурацию из `config/site.example.json` и указать разрешённый рабочий корень, URL/провайдер Git, main/release/current и режим публикации.
2. Выполнить `npm ci` из корня проекта. Эта команда использует закреплённый lockfile.
3. Куратору подготовить штатный Git-доступ с правом записи. Читателю достаточно чтения.
4. Инициализировать локальный реестр кураторов через предусмотренный setup-скрипт; коды вводятся скрыто и сохраняются хешами.
5. Импортировать рабочую карту/данные в разрешённую локальную область либо использовать обезличенный демо-набор.

При недоступном внешнем npm используется утверждённый корпоративный registry и CA. Не отключайте проверку TLS ради установки; укажите штатный сертификат и прокси по инструкции сопровождения.

## 4. Штатный запуск

```text
npm run dev
```

Команда выполняется из корня проекта. Служба проверяет путь, среду и порт, затем открывает страницу. Консоль остаётся открытой. Остановка — Ctrl+C, с корректным завершением дочерних процессов.

Последующие входы не требуют переустановки зависимостей, пока они не изменились в новой версии. Локальные черновики и данные переживают закрытие страницы и обычный перезапуск.

## 5. После обновления программы

Приложение отдельно сообщает об обновлении каталога и программы. При новых исходниках/зависимостях выполните показанную инструкцию перезапуска из той же разрешённой папки. При изменении lockfile повторно выполняется `npm ci`. Программа не устанавливает себя в другую директорию.

## 6. Будущий Python-сборщик

Виртуальное окружение размещается внутри разрешённого корня, например `.venv`. Предусматриваются отдельные инструкции активации для PowerShell и POSIX-оболочки. Python-путь, путь Сбербраузера и профиль задаются локально; Linux-путь из старого проекта не является универсальным.

Порядок установки зависимостей сборщика добавляется только после получения и проверки его исходников. Первый этап не требует загружать браузер Playwright или настраивать сертификатный вход.

## 7. Частые ситуации

- **Не найдены Node/Git:** проверить версию и установку из корпоративного каталога.
- **Запуск из запрещённой папки:** перейти в разрешённый корень, а не отключать проверку.
- **Нет доступа к репозиторию:** проверить корпоративную учётку и права чтения/записи.
- **Видны старые данные:** посмотреть даты источника, проверки куратора и синхронизации.
- **Личные права отсутствуют:** проверить, доступен ли опубликованный проверенный снимок; он помечается автором и датой.
- **Неотправленные изменения:** не удалять локальную область; открыть историю операции и повторить отправку.

Подтверждённые версии ОС/CPU/браузера и результаты чистого запуска будут добавлены после реальной проверки, а не заранее.
