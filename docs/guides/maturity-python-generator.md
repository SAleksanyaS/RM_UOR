# Python-генератор презентации модели зрелости

`scripts/generate-maturity-presentation.py` строит редактируемую PowerPoint-презентацию из XLSX-выгрузки модели зрелости. Это самостоятельная локальная утилита; она не меняет базу рабочего места и не заменяет подтверждение цели УОР.

## Быстрый запуск

Нужен Python 3.10 или новее. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r scripts/requirements-maturity.txt

python scripts/generate-maturity-presentation.py \
  --current materials/maturity/2026-10-30/source.xlsx \
  --date 2026-10-30 \
  --output ./maturity-2026-10-30.pptx
```

На Windows вместо `source .venv/bin/activate` выполните `.venv\Scripts\activate`.

При запуске внутри этого репозитория используются уже опубликованные шаблон `materials/maturity/2026-10-30/source.pptx` и карта лидеров `data/reference/maturity-2026-10-30.json`. Это справочник на указанную дату: перед следующим отчётом проверьте назначения новых команд. Скрипт не угадывает лидера по похожему названию.

## Следующий отчёт и сравнение периодов

```bash
python scripts/generate-maturity-presentation.py \
  --current /path/to/current.xlsx --date 2026-11-20 \
  --previous /path/to/previous.xlsx --previous-date 2026-11-13 \
  --leaders /path/to/leaders.json \
  --template /path/to/DIT_OPS_UOR_template.pptx \
  --output /path/to/maturity-2026-11-20.pptx \
  --audit-json /path/to/maturity-2026-11-20-audit.json
```

Пути в этом примере — заполнители. Текущая и базовая даты задаются явно, а базовая дата должна быть раньше текущей. Без предыдущего Excel изменения обозначаются прочерком. Исторические цифры не извлекаются из старых слайдов и не восстанавливаются по догадке.

`--previous-leaders old-leaders.json` задаёт отдельную историческую карту. Без неё оба периода группируются по выбранной карте `--leaders`, а утилита сообщает об этом. Переименование команды не создаёт новую команду: сопоставление идёт по коду.

`--sheet Sheet1` выбирает лист явно. `--goal-share 80` задаёт показываемый ориентир доли команд. Он не меняет пороги пяти показателей. Существующий файл результата заменяется только с `--force`. Входные файлы перезаписывать нельзя.

## Что получается

1. Первый слайд: текущие итоги ДИТ и таблица лидеров с изменением числа команд и метрик. Если лидеров больше восьми, добавляется продолжение.
2. Слайд пяти показателей: пороги, выполнено / измерено, предыдущий результат, невыполнения и пропуски.
3. Детализация каждого лидера: команды, результат двух периодов и конкретные показатели ниже цели с фактом и порогом. Длинные таблицы продолжаются на следующем слайде.

Используются тема и мастер выбранного шаблона, его размер 16:9 и логотип в верхнем левом углу. Данные рисуются редактируемыми текстовыми блоками и фигурами в оформлении ДИТ / OPS / УОР. Старые слайды и их заметки удаляются. Шрифт — Arial. Произвольный другой макет может потребовать адаптации отрисовки.

## Формат данных

Поддерживается иерархическая выгрузка с заголовками «Блок»/«ДИТ», «Трайб», «Кластер», «Команда», «Этап APP», «Группа практик», «Метрика», «Метрик достигли», «Всего метрик», «Значение метрики», «Цель метрики». Заголовок ищется в первых 20 строках. Код команды берётся из финальных скобок, например `Команда А (TEAM001)`.

Учитываются пять метрик:

- связь историй и багов с кодом;
- связь PR с задачами;
- автоматизированные развёртывания на ПРОД;
- достаточность описания задач перед ПСИ;
- архитектурные требования перед ПСИ.

Порог читается из строки Excel. Например, `79,6%` при пороге `80%` остаётся невыполнением. Итоговые строки блока, трайба, кластера, этапа и группы не суммируются повторно. Командные итоги сверяются с измеренными значениями; противоречия приводят к ошибке вместо создания недостоверного отчёта. Неизвестная метрика или конфликтующая повторная строка также требует исправления входного файла.

Допустимая простая карта лидеров:

```json
{
  "leaders": {
    "Лидер А.": ["TEAM001", "TEAM002"],
    "Лидер Б.": ["TEAM003"]
  }
}
```

Поддерживается и опубликованный нормализованный JSON с `teams[].id/code` и `leaders[].name/teamIds`. Неизвестные коды остаются в группе «Лидер не назначен», а не исчезают из итогов.

## Как читать цифры

Счётчик команд воспроизводит правило исходной выгрузки: **все доступные числовые показатели команды достигли своих порогов**. Это не означает, что известны все ожидаемые показатели, и не является подтверждением УОР. Поэтому пропуски показываются отдельно.

`В исключениях`, `Нет PR`/`Нет релизов` и `Нет данных` — разные состояния. Они не превращаются в числовой ноль или выполненную метрику. Команда вообще без измеренных показателей не попадает в числитель. Показатели вне числового расчёта перечислены отдельно; применимость исключений должна быть проверена куратором.

Дельты первого слайда показывают разницу фактических срезов. Изменение состава команд, доступности показателей или порогов отмечается рядом. Переходы через порог рассчитываются только для одинаковых кодов команд и метрик при неизменном пороге. Само исключение метрики не считается её улучшением.

## Проверка и ограничения

```bash
python -m unittest discover -s scripts/tests -p 'test_generate_maturity_presentation.py' -v
```

Перед сохранением утилита проверяет ZIP/XML, повторное открытие PPTX, отсутствие пустых слайдов, заметок и объектов за границами страницы. Дополнительно проверялась сборка на опубликованной книге 30.10.2026 и визуальный рендер LibreOffice в Linux. Это не прямая проверка в Microsoft PowerPoint на macOS или в корпоративном Office.

Оригиналы выгрузок, результаты, JSON аудита и локальные карты с актуальными рабочими данными остаются локально. Для новых метрик и отдельного отчёта GigaCode требуется самостоятельное расширение входного контракта; текущие пять показателей не смешиваются с другими целями.
