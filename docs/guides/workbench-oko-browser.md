# ОКО: личный браузер, запись и проверка сценария

Основной путь ОКО — установленный СберБраузер с личным сохраняемым профилем, запись действий и повторная загрузка CSV/XLSX. Файл, скачанный сценарием, остаётся выгрузкой ОКО. Адрес отчёта, разрешённые сайты, браузер, сертификаты, условия SSO и ожидаемый полный состав предоставляет банковская среда.

## Личный отчёт в общем интерфейсе

В «Данные → Личные выгрузки ОКО» собственный сценарий доступен читателю и редактору. «Получить данные» запускает уже настроенный отчёт, «Настроить» открывает профиль, запись и справочник. Результат и два скачивания остаются доступны отдельно от настройки. Личная выгрузка не меняет общие факты, источники и пакеты.

Ожидание ручного входа требует входа в собственном открытом браузере и явного продолжения. Ошибка или отмена повторного получения не стирает последний успешный результат. Если ответ неизвестен, проверяется сохранённая операция; новая операция не заменяет её вслепую.

Браузер запускается с включённой Chromium sandbox. При отказе ОС исправьте разрешённую среду запуска; приложение не повторяет запуск с отключённой защитой. Локальная проверка Chrome на Linux не подтверждает СберБраузер, сертификаты и вход в банке.

Локальная проверка Edge/Chrome доказывает работу механизма. Она не подтверждает СберБраузер, банковский вход, ГОСТ, smartcard, прокси или полноту настоящего банковского источника. BP-03/T48 и банковская часть BP-05 остаются **blocked**, пока нет фактического подтверждения в разрешённой среде.

## Подготовка и запись

1. Откройте «Данные» и нужный источник. Для подготовки общего сценария нужен текущий доступ к панели УОР. Для нового источника сначала сохраните собственный черновик настройки; чужие черновики недоступны.
2. В разделе «Установленный браузер» выберите «СберБраузер», укажите «Путь к СберБраузеру», личное имя профиля и предоставленный адрес отчёта. Нажмите «Сохранить личный профиль». Chrome и Edge в списке явно предназначены для локальной проверки. Не копируйте чужой профиль или cookies.
3. Нажмите «Открыть браузер для входа». Выполните ручной вход в открытом браузере, включая штатные сертификатные и SSO-действия. Нажмите «Проверить вход» в общем мастере. В личном мастере кнопка называется «Завершить ручной вход». Закрытие окна и наличие cookie не подтверждают вход: нужен живой признак открытого отчёта.
4. Выберите однозначный признак готового отчёта. Проверьте формат CSV/XLSX, разделители, кодировку, лист, даты и числа. Примените точные фильтры; оставшиеся от прошлого запуска значения сами по себе не считаются начальным состоянием.
5. Нажмите «Открыть СберБраузер и записать действия». В браузере выполните разрешённые действия отчёта, выберите период и полный состав, скачайте выгрузку. Запись ждёт завершения download event. Затем нажмите «Завершить запись и проверить шаги». «Отменить запись» сохраняет прежний сценарий и последний принятый набор.
6. Просмотрите шаги и значения фильтров. Пароли, одноразовые коды, токены, cookies и сертификатные значения не входят в сценарий. Проверьте ключи строк, даты измерений, единицы, числовые поля и соответствие справочнику.
7. Нажмите «Проверить сценарий». Проверка читает реальный скачанный файл, применяет сопоставление и показывает принятые/отклонённые строки. Число строк файла без независимого подтверждения выбора и всех страниц не доказывает полноту. Ошибки даты, числа, повтор ключа и отсутствующий ожидаемый участник требуют исправления.
8. Нажмите «Сохранить сценарий в черновик». Проверьте пакет УОР и его предпросмотр обычным путём подготовки. Публикация общего сценария и ссылки источника идёт через согласованный пакет/PR и внешний merge в Bitbucket. Проба не создаёт PR, не меняет допуск и не подтверждает цель.

## Получение читателем

После применения проверенного main читатель настраивает собственный личный профиль, выполняет собственный вход и повторяет опубликованный сценарий. Профиль, cookies и сертификаты автора сценария не передаются с пакетом. Полученные данные остаются на рабочем месте читателя. «Скачать исходную выгрузку» и «Скачать обогащённый CSV» показывают разные уровни данных.

При истёкшем входе повторите ручной вход и «Повторить получение». При отказе остаётся последний успешный набор с исходной датой; отсутствие данных не становится нулём. Ошибка ОКО не включает скрытый ручной файловый резерв. Изменение страницы требует безопасной перезаписи и новой проверки собственного черновика, затем обычной публикации точной новой версии сценария.

## Исполняемая локальная проба

Из корня установленного проекта, с согласованными Node 22.16.0 и npm 10.9.2:

```text
npx --no-install tsx scripts/probe-oko-browser.ts
```

Без конфигурации команда возвращает JSON `status: "blocked"`, `acceptedSourceBinding: false`, `INPUT_REQUIRED`, код завершения **2** и не запускает браузер. Это проверка отказа, а не банковская проба.

Явную приватную конфигурацию разместите внутри `.runtime/probes/oko/`, например `.runtime/probes/oko/local.json`. Поля строго ограничены:

```json
{
  "profileId": "own-oko",
  "sourceRef": { "entityType": "source_definition", "id": "00000000-0000-4000-8000-000000000001", "revision": 1 },
  "scenarioRef": { "entityType": "browser_scenario", "id": "00000000-0000-4000-8000-000000000002", "revision": 1 },
  "mode": "check"
}
```

Замените синтетические ссылки точными текущими опубликованными версиями и укажите собственный настроенный профиль. JSON не содержит адреса, executable, данные доступа, bankVerified, исторического actor или модуль провайдера: профиль читается из собственной локальной настройки, доступ — из текущего доверенного runtime. Дополнительные поля отклоняются. Ссылки должны вести на подтверждённую публикацию источника, сценария, сопоставления и цели.

```text
npx --no-install tsx scripts/probe-oko-browser.ts --config .runtime/probes/oko/local.json
```

`check` проверяет собственную привязку и текущие версии без запуска браузера. `record-replay` требует интерактивной консоли: ручной вход → Enter в консоли → запись действий и скачивание → Enter → завершение download event → повтор точного опубликованного сценария → разбор выгрузки. Enter не заменяет проверку живого признака входа или фактического завершения скачивания. Отмена доступна через Ctrl+C. Проба не сохраняет новый сценарий, факты, подтверждения, PR или изменения ACL.

Standalone-проба использует штатную блокировку рабочего места. Перед запуском нормально закройте работающий локальный сервер; `WORKSPACE_BUSY` означает живого владельца, а не разрешение удалять lock или завершать чужой процесс. Не запускайте пробу для пустого/неизвестного рабочего места: требуются существующие локальные настройки, identity и active pointer.

Публичный CLI намеренно не устанавливает банковские `inspectExport` и `targetEvidence` адаптеры. Поэтому даже успешно выполненная локальная последовательность вернёт `EXPORT_COVERAGE_REQUIRED`/`BLOCKED_BANK_INPUT`, `acceptedSourceBinding: false`, exit **2**. Присвоение `bankVerified: true`, имя браузера, архивный JSON и число скачанных строк этого не изменят. В настоящем банке нужен отдельный reviewed server-only состав адаптеров по наблюдённому источнику, а не дополнительный флаг конфигурации.

## Контракт банковского доказательства

`probeOkoBrowser` использует существующий `BrowserRuntimePort` и точные текущие опубликованные ссылки. Доверенные порты серверной сборки разрешают текущий доступ и собственный профиль, ждут явных операторских этапов, наблюдают native-метаданные и проверяют экспорт. Ни один такой порт не выбирается из HTTP, env, JSON-архива или произвольного JS-модуля.

Полнота требует свежего доказательства выбора/всех страниц, точного числа строк, owner/source/mapping/scenario/payload hash и опубликованного назначения. Проба заново разбирает скачанные байты, проверяет уникальные ключи, даты, Decimal и единицы, выполняет обогащение и сравнивает полный ожидаемый состав. Профиль 2 000 строк — нагрузочный пример, а не допустимое обрезание.

`OkoTargetEvidenceVerifier` дополнительно должен независимо проверить фактические действия оператора и банковскую среду для одного свежего runId, тех же ссылок/хешей/профиля/назначения/обогащения. Обязательны все проверки: `BANK_BROWSER`, `BANK_MANUAL_AUTH`, `BANK_CANCEL_REOPEN`, `BANK_EXPIRED_REENTRY_RETRY`, `BANK_REVOKED_ACCESS`, `BANK_OFFLINE_CACHE`, `BANK_SELECTOR_CHANGE`, `BANK_FULL_EXPORT`. Неисполненная или неподдержанная проверка остаётся blocked. Эта локальная поставка такого банковского адаптера не содержит и не свидетельствует о миграции реальных данных.

Отчёт содержит дату проверки, фактически наблюдённые безопасные версии, стабильные коды и постоянные диагностические сообщения. Приватный JSON сохраняется под `.runtime/workbench/probes/oko/`; путь доступен только в серверном результате, публичная проекция его исключает. Отсутствующие входы не создают отчёт, похожий на успешную банковскую проверку. Не включайте `.runtime`, исходные выгрузки, профили, сертификаты или диагностические приватные файлы в кодовый пакет/Git.

## Диагностика и следующее действие

| Код | Действие |
| --- | --- |
| `INPUT_REQUIRED` | Исправить строгую приватную конфигурацию, ссылки и расположение файла. |
| `CURRENT_ACCESS_REQUIRED`, `PROFILE_CHANGED` | Обновить текущий допуск/профиль и начать новую пробу. Исторический actor не выдаёт прав. |
| `PROFILE_REQUIRED` | Настроить собственный профиль именно для выбранного источника и точных разрешённых сайтов. |
| `PUBLISHED_BINDING_REQUIRED` | Применить проверенный main и выбрать точные подтверждённые версии. |
| `OPERATOR_REQUIRED`, `AUTH_REQUIRED` | Использовать интерактивную консоль, выполнить ручной вход и проверить живой маркер. |
| `WORKSPACE_BUSY` | Нормально завершить работающий локальный runtime, затем повторить. |
| `RECORDING_REQUIRED`, `EXPORT_INVALID` | Повторить запись/скачивание, проверить формат, колонки, ключи, даты, числа и единицы. |
| `EXPORT_COVERAGE_REQUIRED` | Предоставить проверенный адаптер полноты данного отчёта; не подменять доказательство числом строк файла. |
| `BLOCKED_BANK_INPUT`, `TARGET_EVIDENCE_INVALID` | Предоставить разрешённую банковскую среду и reviewed verifier всей матрицы BP-03/T48. Не угадывать Qlik Engine endpoint. |
| `CANCELLED` | Закрыть собственное окно пробы при необходимости и начать заново; прежние факты сохраняются. |
| `RUNTIME_FAILED`, `CLEANUP_FAILED` | Проверить установленный браузер, сеть/сертификаты и только собственное окно пробы. Не публиковать сырой текст исключения. |
