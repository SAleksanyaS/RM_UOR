# Действующая спецификация · Рабочее место УОР ДИТ Operations

Версия приложения0.4.1. УОР — управление обеспечения развития. Этот документ описывает действующее решение; прошлые планы и обсуждения находятся в [отдельном архиве](ARCHIVE.md).

## Для кого и зачем

Директор ДИТ видит общую технологическую повестку, результаты по фамилиям ИТ-лидеров, отклонения, сроки, решения и недельную сводку. ИТ-лидер видит назначенные цели и необходимые действия. Куратор УОР самостоятельно настраивает каталог, показатели, источники, подтверждения и отчётность.

Каждый компьютер запускает собственное локальное веб-приложение командой `npm run dev` из разрешённой папки. Клиент React и локальный сервер Fastify работают только на127.0.0.1. SQLite и личные файлы хранятся в `.runtime`. Общий центральный сервер не требуется. Промышленное многопользовательское серверное развёртывание является отдельной архитектурой, а не настройкой этой поставки.

Целевая среда выпуска 0.4.1 — Node.js 22.16.0 и npm 10.9.2. Python 3.13.5 допустим, но приложение его не использует. Требования всех платформенных зависимостей проверяются по lock-файлу; [правила обновления среды](guides/runtime-versions.md).

## Чистый старт

- `main` и `release/current` начинаются одной чистой исходной версией. Прежняя история сохранена отдельно; рабочие журналы из неё не импортируются.
- Новая установка по умолчанию пуста: без прежних целей, фактов, учётных сессий, недельных записей и событий разработки. Демоданные включаются только явно через `setup:workspace -- --mode demo`.
- Повторный обычный запуск сохраняет свои данные. Подготовка нового места отказывается перезаписывать существующую базу, импорт или локальные настройки.
- Пароли находятся в локальном хеш-реестре. Для ввода/обновления есть отдельный приватный JSON, публичный пример не является рабочим паролем. Перенос существующих аккаунтов — отдельным приватным архивом, без включения в кодовую поставку.

## Роли

| Возможность | Читатель / директор / ИТ-лидер | Куратор УОР |
|---|---|---|
| Общий обзор, лидеры, матрица, направления, планы, отчёты | Просмотр | Просмотр |
| Еженедельная сводка | Общая опубликованная версия | Общая версия и собственные черновики |
| Обновление общих данных и доступных источников | Под личными правами | Под личными правами |
| Цели, источники, импорт, знания, подтверждения | Без изменения | Изменение |
| Подготовка общего выпуска, обслуживание базы | Нет | Да |
| Обновление локальной программы | Да | Да |

Роль приложения не даёт Git-прав или доступа к источнику. Защита применяется сервером; скрытие кнопок — дополнительное удобство.

## Каталог и расчёт

Цель имеет стабильный ID, полное русское название, направление/категорию, описание результата, владельца, куратора, ссылки, единицу измерения, официальный и внутренний пороги, направление улучшения, срок, приоритет и необязательный вес. Назначения задают ИТ-лидеров, применимость, команды/продукты и явный ожидаемый состав.

Самостоятельная настройка проходит паспорт → показатели → ответственные → источник → пробный расчёт → сохранение. Поддержаны шесть объявленных методик: отдельное значение, доля участников, бинарный результат, вехи, диапазон и изменение. Произвольный код/формулы пользователя не исполняются.

Пробный пример не становится фактом. Пустота, неполнота и неизвестная применимость не превращаются в нулевой результат или успех. Разные показатели не усредняются в фиктивный общий процент. Весовой итог означает долю подтверждённых целей по явно заданным весам, с отдельным охватом.

Статусы: нет данных; не выполнено; выполнено по расчёту, ожидает УОР; подтверждено УОР. Положительный результат подтверждается комментарием или доказательством и привязан к точному fingerprint фактов/правил/состава. Регресс и смена основы лишают старое подтверждение силы. Завершение работы и текст сводки сами по себе не подтверждают цель.

## Получение фактов

Получение отделено от разбора и принятия. Поддержаны ручной ввод, специализированный Excel зрелости, настраиваемый XLSX/CSV, HTTP, точное вложение Confluence, Qlik Engine и декларативный браузерный сценарий. Общая конфигурация содержит безопасные объявления и ссылки на личные профили, не секреты.

Пользователь входит в корпоративную систему сам. Ошибка прав, сессии, сертификата, сети, формата или состава показывается явно; предыдущий принятый срез сохраняется. Снимок содержит источник, период факта, актуальность источника, время получения, автора/проверку. Расписание работает только при запущенном приложении.

Новые факты сохраняют историческую методику и организационный состав. Для старого снимка отсутствующие исторические сведения не придумываются. Сравнение и экстраполяция требуют действительно сопоставимых периодов.

## Работы, сроки и сводка

План хранит объявленные этапы, владельцев, обязательства, ручной прогноз, препятствия и следующий шаг. Пакеты работ содержат вехи, зависимости без циклов, базовый план и фактические события. Диаграмма сгорания строится из событий, а не из придуманных дат. Длинная история ротируется в связанные неизменяемые сегменты.

«Еженедельный отчёт» хранит по одной записи куратора за неделю: главная сводка, выполненные задачи УОР, внимание, планы следующей недели. Неделя начинается в понедельник. Это объявленный текст. Куратор редактирует собственную запись с проверкой версии; директор видит опубликованную общую версию после обновления. Локальный черновик явно помечен и не выдаётся за публикацию.

## Визуализация и отчётность

Главная показывает статус всех целей ДИТ, остаток, полноту данных и распределение назначений по ИТ-лидерам. Любую цель можно выбрать отдельно. Детали доступны в карточке, матрице, планах и направлениях. Меню сворачивается до иконок; настройки вида личные. На мобильном экране меню выдвигается отдельно.

Отчёт создаёт неизменяемый снимок выбранных целей, лидеров, периода и сопоставимого базового периода. HTML/печать и PPTX используют этот снимок. Общий OOXML-движок проверяет исходный шаблон, связывает поддержанные тексты/таблицы и повторяет слайды. Индивидуальный профиль хранится отдельно от движка. Специализированный `dit-maturity-v1` заполняет весь предоставленный шаблон зрелости; он не является универсальным шаблоном любых целей. Отсутствующие факты и сравнение показаны явно. Байты выбранного шаблона и подробные показатели замораживаются вместе с отчётом.

## Знания и публикация

Знания включают команды, продукты, ИТ-услуги, лидеров продуктов, статьи и связи. Они редактируются через UI, архивирование учитывает действующие ссылки. Переименование не уничтожает используемые алиасы.

Общий обмен: собственный черновик → preview выпуска → `release/current` → выпуск руководителем в `main` → «Обновить данные» на другой станции. Независимые изменения объединяются, конфликтующие поля выбираются явно. Версии локальной и удалённой основ проверяются повторно перед записью; ошибка сохраняет черновик. Работа под старой версией не перетирает новую. Доказательства, факты и шаблоны включаются в выпуск только при явном выборе.

## Обслуживание и перенос

Чистый кодовый ZIP не содержит `.git`, `.runtime`, зависимостей, секретов, локальных фактов или прежней истории. Он отличается от переносимой копии рабочего набора, которая намеренно включает выбранные записи/проверенные файлы. Личные браузерные профили, сессии, ключи и сертификаты в такой перенос не входят.

Очистка сначала показывает состав и защищённые ссылки, затем использует обратимый карантин. Окончательное удаление выполняется явно после срока хранения. Восстановление проверяет хеши/структуру/данные, сохраняет предыдущее состояние и согласует прерванную операцию при запуске. Если безопасный откат невозможен, запись остаётся заблокированной.

Обновление программы отделено от обновления данных: подготовка кода/зависимостей при живой прежней версии → согласованная остановка → проверка точных ревизий → замена → закрытый запуск → устойчивая точка подтверждения → открытие записи. До подтверждения возможен возврат к прежней версии; после него новые данные не откатываются. Человеческие изменения не стираются.

## Расширение и границы

Приоритетная поставка ОКО доступна отдельным запуском `npm run dev:oko` / `npm run start:oko`: личный профиль браузера → ручной вход → выбор признака отчёта кликом → запись до полного скачивания CSV/XLSX → сопоставление столбцов → личный справочник → повторная выгрузка и исходный/обогащённый файл. По указанию владельца временно используется переключатель «Читатель / Редактор» без реестра, с явным состоянием `local_preview` и без общей публикации. Предметные факты и подтверждения из предпросмотра не создаются. [Инструкция и границы](OKO_WORKFLOW.md).

Карта модулей и точные контракты — [архитектура](architecture/module-map.md). Порядок работы агента — [START_HERE](agents/START_HERE.md). При новом источнике меняется адаптер/профиль; при новом разборе — parser; при новой методике — предметный контракт и вычислитель; при новом оформлении — профиль/пресет отчёта. Адреса и секреты не встраиваются в предметные функции.

Реальные банковские SSO/ГОСТ/smartcard/прокси, конкретныйСбербраузер, СберОС/macOS, Office и производственные объёмы принимаются внутри банка. Нет обещания понимания любого Excel, выполнения макросов, динамического редактирования любых объектов PowerPoint, работы расписания при закрытом приложении или вымышленной банковской модели ущерба. [Точные ограничения](remaining-work.md), [результаты проверки](VALIDATION.md).
