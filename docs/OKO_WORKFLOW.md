# ОКО: запись, выгрузка и дообогащение

Нужны Node22.16.0/npm10.9.2, зависимости проекта и установленный СберБраузер либо Edge для локальной проверки.

```text
npm run dev:oko
```

Интерфейс: http://127.0.0.1:5175/oko.html. Для запуска собранной версии:

```text
npm run build
npm run start:oko
```

Собранная версия открывается на http://127.0.0.1:4176/oko.html. Остановка — Ctrl+C. Основной запуск приложения остаётся прежним.

## Временные роли

По указанию владельца сейчас включён локальный переключатель **Читатель / Редактор** в правом верхнем углу. Начальный режим — редактор; выбор сохраняется на этом рабочем месте. Это временная роль приложения, без реестра допуска и без публикации общих данных. Режим с настоящим hostname-реестром сохранён отдельно для будущего подключения.

## Рабочий путь

1. Создайте личный сценарий отчёта. Введите адрес отчёта, выберите установленный браузер или путь к СберБраузеру. Добавьте точные origins сайтов SSO, если вход переходит на другие сайты. Пароли, токены и коды в приложение не вводятся.
2. Сохраните профиль, откройте браузер для ручного входа и завершите обычный вход. Затем закройте этот этап кнопкой приложения.
3. Выберите признак открытого отчёта: в открывшемся браузере нажмите устойчивый заголовок/панель отчёта. CSS и JSON не требуются. Элемент должен быть уникальным и находиться на основной странице, вне формы входа.
4. Укажите формат чтения CSV/XLSX, начните запись, выставьте фильтры и скачайте файл. Запись закончится автоматически после полного получения непустого файла. Значения фильтров не записываются; подтвердите их отдельно для повторения.
5. Выберите столбцы ключа строки, продукта, чисел, даты и единицы. Для CSV явно задаются разделитель, кодировка и формат чисел/дат; для XLSX при необходимости — лист. Отсутствующая дата остаётся неизвестной.
6. При необходимости загрузите CSV справочника и сопоставьте его столбцы с ключом продукта, явными UUID и названиями ДИТ/кластера/продукта/руководителей. Команды необязательны. Идентификаторы берутся из файла, из имён они не придумываются. Один продукт может иметь несколько команд; строки исходной выгрузки не размножаются.
7. Повторите выгрузку. В результате доступны строки/диагностика, исходный файл и обогащённый CSV. Ошибка повторного запуска сохраняет предыдущий успешный результат. Неоднозначные или отсутствующие связи остаются явными проблемами.

Сценарии, личные настройки, исходные и полученные файлы хранятся в `.runtime/workbench`. Они не входят в Git. При обновлении страницы восстанавливается ожидание фоновой операции. Если окно потерялось, раскройте «Окно осталось открытым или профиль занят» и закройте собственные окна автоматизации кнопкой приложения.

Это законченный личный путь получения и дообогащения файлов. Он не публикует сценарий в общий каталог, не создаёт принятые факты/подтверждения цели и не объявляет полноту банковского отчёта по одному наличию файла. Реальный банковский SSO/сертификаты проверяются в рабочей среде отдельно; локальные тесты используют синтетический отчёт.

## Настройки запуска и будущий реестр

Необязательный `config/oko.local.json` не публикуется:

```json
{"port":4176,"clientPort":5175,"autoOpen":true,"roleMode":"local-preview"}
```

Для будущего реального допуска `roleMode` меняется на `registry`; задаются `mainRepositoryId` и `registry` с `checkout` (абсолютный путь к отдельному приватному Git checkout), `expectedRemote` (точный origin), `acceptedBranch`, `registryPath` и `repositoryId`. Приложение читает JSON из полученного принятого Git-коммита, а не из изменённого рабочего файла. Нативный Git-вход выполняется штатным способом заранее. При отсутствии реестра в этом режиме автоматических прав редактора нет.

В этой поставке СберБраузер подключается собственным persistent-профилем приложения. Повседневный пользовательский профиль не копируется и произвольный CDP-адрес не подключается.
