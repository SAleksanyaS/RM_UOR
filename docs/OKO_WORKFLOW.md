# ОКО: запись, выгрузка и дообогащение

Основной путь в версии0.5.0: `npm run dev` → **«Данные» → «Личные выгрузки ОКО»**. Он доступен и на новом пустом рабочем месте. Старая закладка `/oko.html` в объединённом приложении переводит в тот же раздел.

Нужны Node22.16.0/npm10.9.2, зависимости и установленный браузер. СберБраузер задаётся локальным путём к исполняемому файлу; Google Chrome/Microsoft Edge подходят для локальной проверки. Программа создаёт отдельный личный профиль, не копирует повседневную сессию и не подключается к произвольному CDP-адресу.

## Пройти сценарий

1. Вверху выберите временный режим «Редактор», затем «Создать первый сценарий» или «Новый сценарий». Введите понятное название отчёта.
2. В «Адрес отчёта» укажите известный адрес, выберите «Установленный браузер». При необходимости добавьте точные адреса сайтов входа без пути/учётных данных и сохраните личный профиль.
3. Нажмите «Открыть браузер для входа». Пароли, коды и сертификатные действия выполняются только в открытом браузере. После обычного входа вернитесь и нажмите «Завершить ручной вход».
4. Нажмите «Выбрать элемент отчёта в браузере» и выберите устойчивый уникальный заголовок или панель уже открытого отчёта. Вход и его iframe не подходят для признака отчёта.
5. Откройте «Как читать файл CSV / XLSX»: явно задайте нужный лист, разделитель/кодировку и формат даты/чисел. Например, CSV с точкой с запятой требует выбора этого разделителя до записи.
6. Нажмите «Начать запись действий». В браузере примените фильтры и скачайте CSV/XLSX. После полного получения непустого файла запись закончится, появятся шаги и образец.
7. Подтвердите безопасные значения записанных фильтров. Выберите уникальный ключ строки, столбец внешнего ключа продукта, числовые столбцы, дату и единицу измерения. Нажмите «Сохранить сопоставление и фильтры».
8. В «Обогащение из справочника» загрузите отдельный CSV/XLSX, нажмите «Прочитать столбцы справочника», сопоставьте ключ продукта, UUID/названия продукта, кластера, ДИТ и руководителей. UUID должны быть в файле; названия не являются заменой идентификаторов.
9. Нажмите «Применить справочник к предпросмотру». Связи строятся по точным ключам. Неизвестный продукт, отсутствующий руководитель и неоднозначность показываются явно. Исправьте файл справочника и загрузите его повторно либо выберите правильные столбцы; встроенного редактора ячеек здесь нет.
10. Нажмите «Проверить сценарий и получить данные». Выполняются сохранённые действия, скачивается новый файл и применяется справочник. В «Последний результат» проверьте число строк, несопоставленные строки, дату и человеческие имена.
11. Нажмите «Скачать исходный файл» или «Скачать обогащённый CSV». Исходный файл сохранён побайтно. Служебные столбцы не затирают исходные имена: при совпадении добавляется `derived.`. Формулы нейтрализуются только в отдельном CSV.
12. После исправления справочника повторите проверку. Новый результат имеет новый ID; старые собственные файлы по сохранённым ссылкам остаются прежними. Интерфейс показывает последний результат, без полного списка исторических рецептов.

Результат личного сценария не публикуется, не становится официальным фактом и не подтверждает цель. Наличие файла не доказывает полноту страниц банковского отчёта.

## Временные роли и неизвестный ответ

По указанию владельца используется общий переключатель «Режим работы»: читатель/редактор со стабильной личностью. Это локальная заглушка, без выдачи банковских/Git-прав. Внешняя публикация и применение main в local-preview запрещены.

После потерянного ответа сначала используйте проверку прежней операции/обновление состояния. Не запускайте новую запись или замену данных, пока прежний исход неизвестен. При истёкшей сессии появится ручной вход и продолжение того же задания; перед продолжением снова проверяются личность, роль и конфигурация.

Если окно осталось открытым, используйте «Окно осталось открытым или профиль занят» → «Закрыть окна браузера и освободить профиль». Это закрывает собственные окна автоматизации, сохраняя сценарий и прежний результат. После изменения страницы отчёта выберите новый признак и запишите действия заново.

На Windows путь личного профиля длиной260 символов и больше отклоняется до запуска/сохранения. Выберите короткое имя профиля или короткую разрешённую папку приложения. Не переносите работающий профиль вручную.

## Общий источник цели и проверка целевой среды

Общий браузерный сценарий настраивается в мастере источника цели: собственный профиль → признак → запись → значения параметров → проверка → сохранение черновика → проверка пакета. Читатель после принятой публикации использует свой профиль и свой ручной вход. Личный файл из раздела выше не подменяет этот общий источник.

Инструкция сопровождающему и executable probe — [проверка браузерного ОКО](guides/workbench-oko-browser.md). Копии, rescue и восстановление — [обслуживание](guides/workbench-recovery.md). Локальный Chrome/Edge и синтетические2000 строк не подтверждают фактический СберБраузер/SSO/ГОСТ/smartcard/прокси. T48 и BP требуют настоящих входов и проверяемых свидетельств.

## Совместимость прежнего отдельного запуска

`dev:oko` / `start:oko` остаются для отдельной прежней установки без managed pointer. Они используют `config/oko.local.json` и собственные порты. В папке нового управляемого рабочего места такой запуск запрещён до открытия второй базы. Обычному пользователю0.5.0 нужен `npm run dev` и раздел «Данные».

Исторические проверки отдельного launcher/compiled UI сохранены в `tests/oko-runtime-loader.test.ts` и `tests/oko-launcher-end-to-end.test.ts`; новая объединённая цепочка — в `tests/workbench/` и actual native-entry tests. Эти группы имеют разные границы доказательств.
