# Проверка целевой поставки0.4.0

Среда здесь: Windows x64, Node24.19.0, локальная разрешённая папка, временные синтетические Git/SQLite/HTTP-стенды. Банковские источники/ССО/сертификаты,СберОС/macOS и PowerPoint этой проверкой не считаются принятыми.

## Новые законченные сценарии

- Недельная сводка: собственный текст/неделя, роли/CSRF, owner isolation, CAS, частичный in-flight draft, читатель без утечки неопубликованного, ограничения ввода, реальные Git release/current→main и UI.11 целевых тестов.
- Чистая установка: empty/demo, отказ перезаписывать существующую базу/настройки, отсутствие старых фактов, защита приватной папки.4 целевых теста.
- Кодовая поставка: чистый сохранённый Git HEAD, фильтрация приватного/старой истории, SHA256manifest, безопасный пустой catalog, пример аккаунтов, реальный export→setup, отдельный PRIVATE архив, dirty tree/ссылки/WindowsADS/занятыйвыход.9 целевых тестов.
- Учётный JSON: действующий вход по хешу, сохранение ID, placeholders, пустойпарольбезизменения, отказ на публичный путь/junction.4 целевых теста.
- Архивирование журнала: независимаяпроверенная SQLite-копия+durablemanifest, точныеданные, retention, остановленный launcher/API-port, CLI иотказ на копии.10 целевых тестов. Это защита поддержанных способовзапуска, не формальная сертификация произвольного внешнего процесса или физического сбоя питания.

## Настоящее рабочее место

Выполнена history:archive при остановленном приложении. Перед очисткой создана и проверена отдельная полная копия в приватной .runtime/history-archive. Цели, факты, черновики, подтверждения, отчёты, шаблоны и хеш-реестр сохранены. В браузере0.4.0 проверены новая недельная страница / четыре поля / пустая общая сводка и нулевые счётчики операций/изменений. Примерный недельный текст не сохранялся как рабочий отчёт.

Старые планы, акты и конкретные рабочие цифры находятся в отдельном архиве; в чистую поставку они не включаются. Общий прогон объединённой версии: 97 файлов, 472 теста — все прошли. npm run build завершился успешно (TypeScript и production Vite). Одно-коммитная основа и финальный кодовый экспорт проверяются по refs, manifest и пустой установке перед передачей. Приватные логи и снимки — .runtime/implementation/completion, не публичный Git.

## Дополнительная проверка приватных файлов и установки

После общего прогона закрыт статический HTTP-доступ к приватным путям через Vite. Отдельный regression на настоящем временном сервере проверил68 запросов: прямые пути, `?raw`, `/@fs` и их сочетания для базы, конфигурации, реестра/ввода паролей, ключей, архивов и Git-файлов получают403/404. Обычная страница получает200. Тест сначала воспроизвёл нарушение на синтетических файлах, затем прошёл после исправления; реальные пароли не запрашивались. Финальная сборка после этой правки также прошла. Весь общий набор повторно не запускался.

Готовый кодовый ZIP распакован отдельно, каждый manifest hash проверен. В новом контексте после empty setup —0 целей,0 фактов,0 операций,0 изменений; аккаунты не встроены в публичный ZIP. Отдельный приватный архив сохраняет действующий хеш-реестр без изменения ID/паролей. Обычный `npm ci` на чистой распакованной копии установил410 пакетов из официального registry. Предварительная offline-попытка показала неполный локальный кэш; работа без registry требует заранее подготовленного кэша. Корпоративный registry и целеваяОС проверяются отдельно.

Очистка старого местного журнала не скрывает последующие действия пользователя: новые сохранения и обновления снова появляются в истории. При переносе существующих данных можно отдельно получить набор без прежнего журнала; чистая кодовая установка остаётся пустой.
