# Фактический объём и проверка операционного этапа

Актуальный этап v0.7 · 25.10.2026. Имя этого файла сохранено для прежних ссылок. Описания первого этапа «только подготовленные данные», «реальный сбор — заглушка», «PPTX только встроенный» и прежние счётчики тестов относятся к прошлым состояниям. Текущие ограничения перечислены в [remaining-work](remaining-work.md), инструкция внутреннему агенту — в [AI-PDLC](AI_PDLC_HANDOFF.md).

## Реализованный сквозной сценарий

Локальный разрешённый workspace → self-service цель/методика/состав → настройка источника либо явный импорт → preview/полное получение → проверка и принятие личных фактов → расчёт с полнотой/давностью/происхождением → отдельное подтверждение УОР → работы/зависимости/удержание → сравнение реальных периодов и фиксированный отчёт → выбор общих артефактов/разрешение конфликтов → кураторский выпуск и получение другими клиентами.

Реальная загрузка выполняется HTTP, Confluence attachment, Qlik Engine export или Chromium/Edge browser scenario. Источник без конфигурации возвращает причину; ручной файл остаётся файлом, а прежний срез не объявляется новой выгрузкой. Встроенный PPTX и загруженный OOXML-шаблон доступны независимо; неизвестный объект/тип привязки не выдаётся за универсальную поддержку PowerPoint.

Новая историческая основа сохраняет методику, ожидаемый состав, организационные имена/владельцев/направления/источники. Отчёт и история не подменяют её текущим каталогом. Legacy остаётся явно неполным. Факт, работы и подтверждение разделены во всех проекциях.

Эксплуатационный слой включает manifest совместимости, миграцию с согласованной SQLite-копией, проверяемое восстановление и полный rollback после post-install ошибки, очистку старых сессий/расписаний и восстановленных running-задач, retention проверенных копий, диагностику и обновление кода через штатный launcher. Личная раскладка и ограничение отображаемых списков реализованы; это не доказательство неограниченной производительности.

## Что действительно проверялось локально

| Проверка | Свидетельство и точная граница |
|---|---|
| Предметная логика, роли, CSRF, CAS | Unit/service/API/integration тесты в `src/features` и `tests`; синтетические данные и изолированные Git-репозитории. Действующие банковские права этим не проверяются. |
| Получение данных | HTTP-стенд с JSON/CSV/XLSX, отказами/лимитами/отменой; точный download URL Confluence на стенде; Qlik JSON-RPC WebSocket стенд с OpenDoc/GetObject/ExportData и последующим HTTP-файлом. Это реальные вызовы протоколов, а не обращение к банковским серверам. |
| Браузер | Установленный Microsoft Edge на Windows: persistent profile, реальные действия/скачивание, recorder, очередь и отмена. Наличие этого результата не подтверждает Сбербраузер/СберОС/macOS/корпоративный SSO. Тесты — `src/features/connectors/connectors.test.ts`. |
| Исполнение | Зависимости/циклы, реальные события базы/сгорания, пригодность прогноза, удержание, веса/неизвестные, CAS и сохранение ввода. Руководство — [execution-and-retention](guides/execution-and-retention.md). |
| Отчёты и OOXML | Реальное чтение ZIP/XML, изменение текстов через runs, повтор слайдов/таблиц, продолжение длинных имён, вредоносные пути/связи/макросы/лимиты, private/shared и CAS. Предоставленный локальный корпоративный PPTX прочитан и преобразован приватно: 11 слайдов, master/layout/theme сохранены побайтно. Это технический проход одного объекта, а не полная настройка всех банковских полей и не просмотр в PowerPoint. |
| История | Изменение/удаление live лидера/источника не меняет подписи сохранённого периода; неизвестная legacy организация не дополняется догадкой. Несопоставимые периоды не соединяются фиктивным трендом. |
| Доказательства | Проверка байтов/размера/hash/classification, legacy path игнорируется, stage без overwrite, разграничение личных/общих файлов, HTML выдаётся attachment с nosniff/CSP. Имя HTML в UI остаётся текстом, без inline preview. |
| Восстановление | Повреждённый/неподходящий schema/version до замены; post-restore failure возвращает прежние namespaces; старые sessions/jobs не воскресают; running становится interrupted; повреждённые новые копии не вытесняют последние исправные при retention. Тесты — `src/features/system/{backup,restore-safety}.test.ts`. |
| Программа и Git | Проверки manifest/версии, локальные CAS/merge/conflict и code-update тесты. Корпоративный Git/registry, аварийный отказ конкретного банка и целевые ОС принимаются отдельно. |

Адресные результаты текущего прохода записаны в приватных `.runtime/implementation/completion/*-report.md`; они не включают корпоративные оригиналы в публичную поставку. Сводный прогон и финальная сборка конкретного commit — в [журнале доказательств](verification/first-stage-evidence.md). Числа 118/130/161/187/213/296 из прежних этапов не являются результатом нынешней ревизии; складывать отдельные адресные прогоны в «общее число тестов» нельзя.

## Как проверять изменённую ревизию

```text
npm ci
npm test
npm run build
npm run dev
```

При разработке сначала запускать относящиеся к изменению проверки; общий прогон проводить на объединённом результате, затем адресно повторять проверки новых исправлений. Статус «реализовано» не заменяет status «проверено этим запуском». Браузерная визуальная проверка отдельных страниц не доказывает все размеры, устройства и новые ветви UI.

Приёмочный пользовательский маршрут: обзор ДИТ → выбранная цель/ИТ-лидер → неизвестное/отрицательное/положительное на проверке → self-service preview → факт и подтверждение с доказательством → план/веха/удержание → источник/запись/реальный download/отказ/отмена → история и недельный отчёт с шаблоном → конфликт двух кураторов → выбор состава и выпуск → резервирование/restore → обновление программы. Проверить стандартный ноутбук и большой экран, клавиатуру и читаемость длинных русских названий.

## Что эта проверка не доказывает

- Банковские SSO/права/сертификаты/ГОСТ/smartcard/прокси/PAC, конкретные Confluence/Qlik deployments и работа целевых СберОС/macOS станций ещё требуют предоставленной среды и приёмки по [runbook](BANK_CONNECTORS_RUNBOOK.md).
- Автоматическое понимание любых Excel, выполнение произвольных формул/макросов, SmartArt/chart bindings и будущая автоматическая активация dated правил не поддержаны.
- Прогноз не гарантирует срок, вехи не подтверждают измеренный результат, явная ресурсная ёмкость не равна фактической загрузке, банковский ущерб не вычисляется без утверждённой методики.
- SQLite-копия не резервирует весь workspace. Рост фактов/оригиналов/Git, хранение больших файлов и длительная промышленная нагрузка требуют измерений и согласованной политики банка.
- В чистом клоне только синтетические примеры. Локальные рабочие импорты/снимки/оригиналы находятся вне публикации; исторические локальные данные не выдаются за текущую неделю.
