## Как читать результат

`КОНТРАКТ` означает: тест и соответствующий исходник сверены по назначению; полный набор fba0ce6 прошёл(E12), но это не утверждение отдельного полного пользовательского сценария для каждой строки. `ЛОКАЛЬНЫЙ ПРОГОН E…` означает наблюдённый ниже запуск указанного сценария, только в его границах. Ни одна из этих отметок не означает банковский PASS. `PENDING_LOCAL` — ещё нет фактического filtered-artifact build или финальной release-docs записи; `BLOCKED_BANK_INPUT` — нет необходимых реальных банковских входов/доказательств. Текущие corrections/review имеют отдельное evidence E14–E17; общий PASS fba0ce6 не переносится на текущую revision.

Реально использованы Windows, Node **22.16.0**, npm **10.9.2**, Google Chrome **156.0.8078.74**; в локальных T47/T48 — Edge **156.0.4314.58**. Синтетические внешние Git/Bitbucket/registry/Qlik-провайдеры в T40 соединены с настоящими HTTP, SQLite и сервисами production composition. Это не проверка реального банка, физического СберБраузера, NSS/SSO, сертификатов, smartcard, прокси или согласование реального сотрудника. Python 3.13.5, другие ОС и банковский ноутбук этим не сертифицируются.

## Ограничения для решения о выпуске

Production startup использует новый composition и не открывает прежние парольные/публикационные HTTP обходы. Unrelated legacy `.runtime/app.db` не переинтерпретируется и не мигрируется молча. Узнаваемый старый typed layout допускается только при точном доверенном identity/owner/schema inventory: копия и rescue проверяются до activation, source DB/WAL/SHM сохраняются; foreign/unknown layout отказывает. **Реальные legacy данные пользователей ещё не перенесены.**

При применении verified main у originating curator разрешено строго ограниченное attachment `publicationAnchorId: null → confirmed exact anchor` при том же id/revision/body/actor/recordedAt и актуальном trusted owner. Это одна transaction применения, без новой бизнес-редакции; generic immutable import остаётся строгим, agreed basis не переписывается. Негативные случаи/rollback/reopen проверяются в [repository tests](../../src/server/storage/workbench-repository.test.ts), [apply tests](../../src/features/publishing/workbench/publication-apply.test.ts) и [archive roundtrip](../../src/server/workbench/production-archive-roundtrip.test.ts); E12 прошёл, whole-branch review E13 принял это узкое исключение без отдельного finding.

Личная история сохраняет artifact IDs и файлы, но интерфейс показывает последний результат: inline cells/history recipe browser не предъявлены. Частичный импорт показывает raw/enriched layers и все четыре raw строки с retained exact BLOB; protected accepted-capture endpoint возвращает 404 для partial capture, UI не предлагает для него file links. Нативный личный workflow отдельно доказывает предлагаемые пользователю original/enriched downloads.

Только dense JSX T33(M2) остаётся deferred cosmetic; M1DOWNLOAD_REQUIRED и M3transfer guidance/public-doc links исправлены. В логах остаются Node SQLite experimental, Zod/Rollup annotation, крупный fixture React/Babel chunk и CRLF notices; ожидаемые private HTTP403/allow-list сообщения относятся к отрицательным проверкам. Заявления о полностью бесшумном запуске нет.

До локального закрытия: фактически проверить сборку чистого распакованного экспорта и записать итоговый release-docs результат. Все I1/I2/I3+M1/M3 ADDRESSED по сохранённому scoped report и I1closure addendum; текущие checks/build E16 готовы, полный E12 относится к прежнему fba0ce6. Банковская часть T48 остаётся заблокированной. До корпоративного выпуска нужны все шесть real BP reports, фактический перенос с counts/кураторским решением и целевая эксплуатационная проверка. Подключение примерно100 сотрудников, merge в main, tag и rollout не одобрены.
