# Сохранение и восстановление форм — F12/F13

Дата: 2026-11-01. Проверки выполнялись в отдельной Linux-копии, Node 22.16.0, с реальным локальным API/SQLite на синтетических данных. Пользовательская Windows-папка и её `.runtime` не затрагивались.

## Поведение

- Подтверждённый `preferences.set` сразу означает «Личный вид сохранён». Если следующий GET недоступен, остаётся отдельная ошибка чтения с действием «Обновить отображение». Это действие не отправляет mutation.
- Потеря именно mutation response сохраняет прежний `commandId`, блокирует повторное редактирование до проверки и получает прежнюю квитанцию через существующую идемпотентность. Повтор не создаёт вторую редакцию.
- Составное сохранение цели запоминает подтверждённые определения и их точные `versionRef`/CAS token. После сбоя на N-м шаге уже подтверждённые шаги не повторяются; форма показывает количество завершённых шагов.
- Неизвестный шаг сначала проверяется через `reconcileCommand`. Для `completed` повтор того же неизменного запроса возвращает сохранённую серверную квитанцию с CAS token; для `not_found` отправляется тот же исходный запрос. `pending`/`interrupted` не разрешают последующие шаги и не получают новый ID автоматически.
- После успешного `draft.open` его квитанция удерживается до удачного чтения пакета. Ошибка GET предлагает «Повторить чтение»; новая запись не создаётся.
- Общий guard защищает локальное закрытие, навигацию Workbench, смену области/даты, browser back и `beforeunload`. Отказ сохраняет ввод и URL. Фоновое чтение не объявляет несохранённый ввод сохранённым.
- Кнопка настройки цели сохраняет один DOM-узел при переходе от загрузки к полученным данным: возврат фокуса больше не теряет прежний opener.
- Preview мастера использует общее предметное сравнение «исходная редакция / текущий main / предлагается». Основные состояния расчёта и ручного результата показаны по-русски.

## Границы

Сохранение нескольких сущностей остаётся последовательностью подтверждённых операций, а не общей транзакцией. При перезапуске UI читаются реальные серверные черновики. Неотправленный ввод не записывается в localStorage; его потеря при подтверждённом пользователем уходе или аварии браузера не скрывается обещанием автосохранения.

При отменённом переходе browser history восстанавливается полный принятый URL; отвергнутый контекст не сохраняется в настройках. Это не механизм синхронизации вкладок или центральных прав.
