НАХОДКИ

R1. P2 / высокая уверенность — личная вкладка ОКО не переживает reload, refreshSession и Back/Forward.
Новый код: src/app/workbench/WorkbenchApp.tsx:39–41 хранит выбор в #personal-oko. Связь с неизменённым provider: src/app/workbench/context.tsx:12 собирает locationUrl только из pathname+search; :74–75 и :91–92 затем replaceState через canonicalPageTarget. Сам canonicalPageTarget умеет сохранять hash (route-state.ts:91), но сюда он уже не доходит.
Сценарий: при существующем общем context открыть «Личные выгрузки ОКО», затем перезагрузить страницу, обновить сеанс/роль либо уйти и вернуться Back. Фрагмент исчезает, active снова становится goals. Вместе с ним неверно возвращаются глобальные фильтры. При пустом каталоге ошибка замаскирована fallback на personal.
Минимальное исправление: обеспечить сохранение page selector во всех канонизациях/возвратах, не помещая его в глобальные персональные preferences. Регрессия: выбранный personal tab и прежний scope/time сохраняются при startup, refreshSession и Back/Forward; переход на goals явно удаляет selector. Проверка должна использовать production provider, не только routeUrl отдельно.

MaintenancePanel сам возврат фокуса не делает.
Минимальное исправление: назначать доступную точку возврата после снятия hidden/inert и завершения соответствующего overlay-перехода. Не менять существующий корректный переход на заголовок другого раздела. Регрессия настоящего браузера: 360px, текущий пункт меню; затем открытие/закрытие обслуживания кнопкой и Escape. R3. P2 / высокая уверенность — исходное поле CSV может быть показано как поле обогащения без такого происхождения.
src/features/connectors/workbench/PersonalOkoWorkspace.tsx:50–57,65 определяет derivedName лишь по наличию ключа и отсутствию любых derived.*. Это не доказательство происхождения. Server enrichment сохраняет исходные заголовки буквально и добавляет derived.* только при фактической коллизии с созданным полем (src/features/connectors/workbench-workflow-enrichment.ts:57–61,68–72).
Воспроизводимый случай: исходный CSV содержит directory.productLeaderName, а справочник не смог дать руководителя. В сохранённом preview остаётся исходное значение под этим именем, но нет derived.directory.productLeaderName. Новый сокращённый вид подписывает его «Руководитель продукта», хотя это лишь неподтверждённое поле источника. При проблеме справочника строка также получает предупреждение — это не доказанная «зелёная» строка и не утечка данных, а подмена происхождения столбца.
Чистый probe на штатных parseWorkbenchTable/previewOkoTable подтвердил: collision=false, исходное значение сохранено, product leader link отсутствует, unresolvedRows=1, issue LEADER_REQUIRED. Текущая эвристика всё равно выбирает данный ключ как leader.
Минимальное исправление: без сохранённого доказательства происхождения столбцов показывать их точные заголовки через существующий PreviewTable; не угадывать по зарезервированному имени и не читать текущий recipe для переинтерпретации прошлого result. Регрессия: такой CSV+неразрешённый справочник, а также обычная действительная коллизия и старый result после изменения recipe. Исходное значение не должно получать неподтверждённую семантическую подпись.

R4. P2 / высокая уверенность — обзор приписывает ручной цели продолжающуюся работу без этого состояния.
src/features/overview/workbench/OverviewPage.tsx:19 использует manualStatus?.to !== 'completed' и во всех случаях возвращает «Работа продолжается». Это включает manualStatus=null и сохранённое not_started. Ранее ResultSummary показывал «Ручной статус не задан» / «Не начата»; теперь эта точная информация в Overview отсутствует.
Сценарий: опубликованная ручная цель без события статуса либо с событием not_started появляется в очереди с заявлением, что работа продолжается. Это новый выведенный UI-статус, а не данные API.
Минимальное исправление: различать отсутствующий статус, not_started и in_progress; отсутствие события нельзя превращать в ход исполнения. Регрессия: три этих состояния плюс completed с/без attestation отображаются раздельно и не смешивают факт исполнения с ожиданием подтверждения.
