# Приёмка больших исходных таблиц — план измерения

Условия и бюджеты зафиксированы до оптимизации 2 ноября 2026. Измеряем одну локальную установку Workbench через настоящий HTTP/SQLite, Node 22.16.0; характеристики машины и hashes двух затронутых модулей автоматически входят в каждый JSON. Эта машина не является целевым банковским ПК.

Fixture: 10 000 и 100 000 строк, пять столбцов Row/Team/Value/Date/Status, 58 повторяющихся команд, текст UTF-8 CSV, точные bytes/hash в результате. Операции: сохранение исходника, первый разбор после restart, страница50 строк, поиск по всем строкам и числовая сортировка Value. По20 последовательных warm samples; p95 — ближайший верхний ранг. RSS всего процесса содержит сервер, harness и ещё не освобождённую память V8; это не изолированный размер одной таблицы.

Проектные бюджеты для этой fixture: cold сохранение/разбор до5 с; p95 страницы до500 мс, поиска до1000 мс, сортировки до1500 мс. Это бюджеты завершения операции, отдельно от мгновенного состояния «обрабатываем» в интерфейсе. Отрисовываются только50 строк. Тест фиксирует честный отказ, если формат/объём не поддержан; отказ не считается поддержкой100000 строк.

До изменения обычный parser ограничен20000 строками. Для большого исходника планируется отдельный ограниченный режим просмотра: максимум100000 строк,100 столбцов,1000000 ячеек и10 МиБ; правила принятия фактов остаются прежними. Лимит числа ячеек удерживает даже очень широкие файлы от чрезмерного выделения памяти. Байты исходника сохраняются и при отказе просмотра.

Команда из подготовленного checkout:

```text
node --import tsx scripts/benchmarks/raw-preview.ts /absolute/path/raw-preview-result.json
```



## Измеренный результат

Данные: [до](product-2026-11-02-evidence/raw-before.json), [после](product-2026-11-02-evidence/raw-after.json), [проверка реального UI](product-2026-11-02-evidence/raw-browser.json). В JSON сохранены время UTC, hashes модулей и фикстур. CSV-путь измерен после финального сохранения отдельного ограничения XLSX; защитный OOXML-парсер не расширен.

До изменения 100 000 строк сохранялись как raw, но просмотр завершался TABLE_LIMIT_EXCEEDED. Это не baseline успешной обработки. После изменения все объявленные бюджеты достигнуты на этой fixture. Оптимизация: один Intl.Collator на сортировку, создание DTO только для возвращаемой страницы, ограниченный cache с оценкой стоимости ячеек; полный исходник не отрисовывается в DOM.

Реальный Workbench/HTTP/SQLite/Vite/синтетический Chromium156 после restart показал ровно50 строк, нашёл строку99999, отсортировал полный набор, перешёл на следующую страницу, сохранил byte-identical скачивание и не создал observed_fact. Ширины1440/1024/320 не дали overflow страницы; pageerror отсутствует. Проверка `tests/workbench/raw-large-browser.test.ts` вместе с двумя parser-файлами:3 файла/20 тестов PASS, exit0.

### Граница применимости

Эти числа относятся к пятиколоночному CSV, тестовому Linux x64 и Node 22.16.0. CPU/RSS включают harness и V8; на машине могли работать другие инженерные задачи. Это не замер банковского ПК, не обещание100 мс для любой операции и не поддержка100000 строк XLSX. XLSX сохраняет проверенный предел20000 строк; обычный импорт фактов также не расширен. Объём сырого CSV/TSV ограничен100000 строк/100 столбцов/1000000 ячеек/10 МиБ. Нативный regression `raw-preview-limits.test.ts` отвергает100001 строку и слишком широкий набор, сохраняя прежний предел обычного импорта.
